# 权限层:她能动什么,谁说了算

状态:设计稿第二版(2026-10-11),取代 09-14 的第一版。第一版已落地的部分(放置记录、三张规则表、模式、征询协议、
"允许并记住"、命令入口)在本版里保留或改写,改动处见 §十一。

与 `pathing.md` 的分工:那份讲寻路怎么走,本文讲身体的任何动作在动手前怎么过权限。寻路只是调用方之一,攻击、开容器、
丢物品、执行指令是另外几个。

## 一、问题

第一版用"玩家放没放过"区分能挖与要问:放置记录里有的要问,没有的当自然方块放行。两个缺口:

- **记录只从装上模组那一刻开始。** 装模组之前盖的房子、村庄等生成结构的墙板与玻璃,在她眼里都是"没人放过",放行挖。
  第 7 步之后寻路默认可挖可搭(`adr/pathing/0016-model-says-where-only.md`),抄近道就可能穿墙而过。
- **"玩家放的"一律问主人。** 单机没事;多人服里那是邻居的房子,主人没资格替邻居答应。走服务端插件方向之后这是硬伤。

两个缺口是同一个根:规则判的是"有没有记录",该判的是"这东西是谁的"。

## 二、模型:防火墙

规则照防火墙的五个要素写:

| 要素 | 这里是 | 说明 |
|---|---|---|
| 主体 | 同伴 | 缺省是主人名下的每一只;可点名某一只 |
| 动作 | `break`、`place`、`attack`、`use_block`、`use_entity`、`take`、`drop`、`command` | 第一版的八个动词不变 |
| 对象 | 方块、实体、物品、指令根名,用对象组与属性组合 | 本版的重点,见 §三 |
| 判决 | `allow`、`ask`、`deny` | 不变 |
| 默认策略 | 哪条都不中:`ask` | 不变 |

再加防火墙的两样:

- **对象组。** 一个名字代表一类对象:`nature`、`owner`、`structure(#minecraft:village)`……规则只写组名,组怎么判归对象组的提供者。
- **命中计数。** 每条规则记命中次数与最近一次命中的时间,规则列表与面板上显示,主人一眼看出哪条在起作用、哪条从没用过。改了规则计数清零。

**不照搬防火墙的一处:顺序。** 防火墙按书写顺序首条命中,一条宽的放行写在前面就让后面的禁止全失效。这里照 IAM:
**明确的禁止永远赢**,判定顺序与书写顺序无关(§五)。

一行规则:

```
<判决> <动作>(<对象条件>) [@<同伴名>]

deny  break(other)
ask   break(structure(#minecraft:village))
allow break(owner & minecraft:cobblestone)
deny  attack(owner | self) @小蓝
allow command(msg)
```

对象条件是对象组、属性、方块或物品 id、标签(`#minecraft:beds`)、某一只实体(`entity:<uuid>`)、`*` 的组合,
`&`、`|`、`!`、括号。全仓只在规则核心的解析器里解析(§九),写错了回教学式的错误,列出认得的动词、组与属性。

## 三、对象:先判是谁的

### 1. 归属:六类,互斥且完备

每一格方块恰好属于下面一类,判出来就停,不看后面:

| 次序 | 组 | 是谁的 | 怎么判 |
|---|---|---|---|
| 1 | `self` | 她自己的 | 放置记录:她放的 |
| 2 | `owner` | 主人的 | 放置记录:主人放的,或主人名下别的同伴放的 |
| 3 | `other` | 别的玩家的 | 放置记录:别的玩家放的,或别人名下同伴放的 |
| 4 | `structure` | 生成结构的 | 世界生成时记下的结构件范围(`StructureManager`);带参数按结构类型分,`structure(#minecraft:village)` |
| 5 | `nature` | 没人的 | 种类在自然方块表里(§三.2) |
| 6 | `unknown` | 说不清的 | 以上都不是:不在记录里、不在结构里、也不是地形会长出来的方块——装模组前盖的木屋多半落在这里 |

次序有讲究:

- 记录最准,所以最先看。主人在村庄里放的方块是主人的,不是村庄的。
- 结构先于自然:村庄件范围里的泥土、石头算村庄的。宁可在村子里多问一句,也不把沙漠村的砂岩房当成沙漠。
- `unknown` 不当 `nature`。不知道是谁的就问,这是第一版"不替主人做决定"的原则在归属上的落点。
- **专用服务器上 `unknown` 按 `other` 算**(进硬规则),服主可在配置里改;单机与局域网照旧问主人。多人服上说不清的多半是别人装模组前盖的,
  让主人答应就等于让想搞破坏的主人一键拆别人的房子。

实体用同一套名字的前四类与一类"没主":`self`(她驯服、结契的)、`owner`(主人的宠物)、`other`(别人的宠物)、`nature`(野生的、没主人的)。
没有 `structure` 与 `unknown`:原版的驯服记录说得清每一只有没有主人、主人是谁。

### 2. 自然方块表

一个数据标签 `numen:natural`,随模组发布,整合包与主人都能用数据包改。由这几部分组成:

- 原版标签:主世界与下界的基岩类石头、泥土类、沙子类、雪与冰、珊瑚、洞穴里的(滴水石、紫水晶、苔藓、幽匿)、花草与可替换植物、蘑菇块、黑曜石……
- 各模组通用的 `c:` 标签:`c:ores`、`c:stones`、`c:sands`、`c:gravels`……模组矿石与模组石头不用逐个适配。
- **原木与树叶看状态,不只看种类。** 原版里玩家放下的树叶带持久标记(`persistent = true`),自然长出的不带。树叶不持久才算 `nature`;
  原木连着不持久的树叶(在原版树叶腐烂的距离内)才是野树,木屋的原木连着的是持久树叶或根本没有树叶,落到 `unknown`。

表不全的后果是"多问",不是"误挖":漏掉的种类落到 `unknown` 去问,主人答"以后都允许"就记住这一种。这正是白名单比黑名单安全的地方。

**判不了的,照实说。** 装模组之前、用自然方块盖的东西(老存档里的石头墙、圆木堆以外的砂岩房),在任何一处都留不下记录,
种类也分不出来,会落到 `nature`。主人用规则补(例如 `deny break(nature & minecraft:sandstone)`),或等有了区域组(§三.4)圈起来。
不靠"看形状像不像建筑"去猜——那条路 Baritone 七年没走通。

### 3. 属性

归属之外的事实,与第一版的信号同一回事,改叫属性:

| 属性 | 问题 |
|---|---|
| `block_entity` | 这格有没有方块实体 |
| `contents` | 容器里有没有东西(撤不回) |
| `named` | 实体有没有自定义名字 |
| `villager` | 是不是村民 |
| `hostile` | 是不是敌对生物 |
| `hazard_item` | 放的是不是岩浆、火、TNT、水 |
| `near(<组>)` | 放置点附近有没有属于那一组的方块,`near(owner)`、`near(other)` |

撤不回由属性标:`contents`、实体的 `owner`/`self`/`other` 命中 `attack` 时,征询卡把那一项标成"撤不回"。

### 4. 对象组是扩展点

组由提供者给出,原版也是提供者之一。登记一个组 = 一个名字 + 一个"这个对象属不属于它"的判断(可带参数)。

| 提供者 | 组 |
|---|---|
| 原版(Numen API 自带) | `self`、`owner`、`other`、`structure`、`nature`、`unknown` |
| 领地模组的插件 | 例 `claim(other)`:别人圈的地 |
| 区域(以后) | 主人圈的一片地,`area(家)`。等有真实需求再做,做时是主人定义的保护范围,不是给模型用的工作区 |

插件只加名词,不加动词,不改判定顺序。

## 四、谁能改规则

| 谁 | 能做什么 |
|---|---|
| 服主 | 硬规则的开关(§六),服务端配置 |
| 主人 | 自己那一层随便改:加、删、放宽、收紧;选模式 |
| 她(模型) | **只能收紧**:往主人层加 `deny`、`ask` 行,加完照实告诉主人。**放宽一律经主人**:她要加 `allow` 行、删任何一行,发一张征询卡,主人答应才写进去 |

收紧不会出事:禁止永远赢、`ask` 行排在同层 `allow` 之后(§五),她加的行只可能让更多动作被拦、被问。放宽要过主人,
否则就是她自己给自己发许可。

她加的行记着来源("她加的,因为主人说别动箱子"),规则列表里一眼看得出,主人删起来和删自己的一样。

主人说"别动我的箱子",她就加 `deny break(owner & #c:chests)`;主人说"农场随便收",她不能自己加 `allow`,要发卡。

## 五、判定顺序

一个动作进来,依次:

1. **模式**:`observe` 拒一切改世界的动作;`bypass` 放行一切——硬规则除外。
2. **硬规则**:命中即拒,模式、主人层都解不开。
3. **任何一层的 `deny`**:命中即拒。
4. **主人层 `allow`**,再 **主人层 `ask`**。
5. **出厂层 `allow`**,再 **出厂层 `ask`**。
6. 都不中:`ask`。

同层 `allow` 先于 `ask`,是为了"允许并记住"抠出来的细 `allow` 能盖过它出自的那条宽 `ask`。书写顺序不影响结果。

任务期授权(主人在卡上点了"允许")只把这一次任务里同一行规则问出来的同一种东西变成放行,解不开任何拒绝。

## 六、出厂规则

**硬规则**:主人答应不了的事。服主可在服务端配置里关(单机就是你自己)。

```
deny break(other)
deny place(other)
deny take(other)
deny attack(other)
deny use_entity(other)
deny place(hazard_item & near(other))
```

**出厂层:**

| 判决 | 规则 |
|---|---|
| allow | `break(nature & !block_entity)`、`break(self & !contents)`、`break(structure & !structure(#minecraft:village) & !block_entity)`、`place(!hazard_item)`、`place(hazard_item & !near(owner) & !near(other))`、`attack(hostile)`、`attack(nature & !named & !villager)`、`use_block(*)`、`use_entity(nature)`、`use_entity(self)`、`take(owner)`、`take(self)`、`take(structure & !structure(#minecraft:village))`、`command(help)`、`command(list)`、`command(me)`、`command(msg)`、`command(teammsg)`、`command(seed)`、`command(random)` |
| ask | `break(owner)`、`break(unknown)`、`break(structure(#minecraft:village))`、`break(block_entity)`、`break(self & contents)`、`attack(owner)`、`attack(self)`、`attack(named)`、`attack(villager)`、`use_entity(owner)`、`drop(*)`、`place(hazard_item & near(owner))` |
| deny | 空 |

读法:

- 没人的随便挖、随便打;她自己的随便拆(装着东西的除外);主人的、说不清的、村子里的要问;别人的碰不得。
- 同层 `allow` 先于 `ask`,所以 `allow` 行写得比 `ask` 行窄:带方块实体的(地牢的刷怪笼与战利品箱、蜂巢、可疑的沙子)不进任何 `allow` 行,落到 `break(block_entity)` 去问。
- 床、门、活板门、栅栏门不再单列:主人放的已经是 `owner`,村子里的已经是 `structure(#minecraft:village)`,自然生成的门只在结构里。
- 从主人的容器拿东西放行:她的设计就是用主人的工作台熔炉箱子;主人想管就加 `ask take(owner)`。废弃结构里的战利品箱随便拿,村民的箱子要问。
- 右键方块全放行:开门、开容器、按按钮不改世界的归属;拿东西另由 `take` 管。

## 七、动作分类

| 档 | 动作 |
|---|---|
| 从不问 | 看(`scan`、`status`、`inv` 的查询、`build.diff`)、合成烧炼、吃、装备、换手——不改世界,不是权限层的动作 |
| 出厂放行 | 挖没人的、拆自己的、挖废弃结构、放普通方块、打怪与野生动物、右键方块、从主人与自己的容器拿东西、只读只说话的指令 |
| 问 | 挖主人的、挖说不清的、挖村子里的、挖带方块实体的、打有主或有名字的、打村民、丢东西、在主人的东西旁放危险物,以及没有任何一行规则说到的 |
| 拒 | 别人的一切(硬规则)、任何一层的 `deny`、`observe` 模式 |

挖不动(基岩)、岩浆与危险格、摔落上限回答的是"做不做得到、会不会伤到自己",是物理,不经裁决、不弹卡,留在寻路与身体。

## 八、检查时机与征询

**三个时机。**

| 时机 | 做什么 |
|---|---|
| 规划 | 寻路的代价只读裁决快照(端口 `TerrainPolicy`,Numen 以 `Gate` 实现):放行按原价,要问的格加价(倍数照旧,默认 10),拒绝是墙 |
| 执行开始 | 一件成批的活(建造施工前、攻击开打前)把动作整批裁决,要问的合成一张卡 |
| 每次动手 | 她的鼠标 `Mouse` 在每一下之前问;走路时走到要问的那一格跟前停下发卡。答应了接着走;拒了那一格在这一趟里当墙、重新规划绕开,绕不开才以 `denied` 收场 |

**各内容的接入点。** 内容只提出动作,判与问都归权限层。

| 内容 | 什么时候送动作 |
|---|---|
| `move.to`、`move.away`、`move.follow` | 规划时只读裁决定价;走到要改的格子那一刻由鼠标问 |
| `work.dig` | 挖给它的每一格,动手前问;够不着先走过去,路上要改的格同上 |
| `build.place` | 施工前把要清的与要放的整批裁决,一张卡;拒绝的格按"主人不让动"跳过并写进回执。她放下的每一格记在她名下(`self`) |
| `fight` | 开打前送目标,一张卡,等答复期间不打它;自卫换目标时新冒出来的再送 |
| `use.block`、`use.entity`、`use.hit`、`use.item` | 按下去之前送准星落到的动作 |
| `gui` 的取物 | 把东西从容器拿进背包的那一步动手前送 `take`;她自己背包的合成格与没有方块实体的工作台类界面不算 |
| `inv.drop` | 每次送 `drop` |
| `numen.mc.run` | 解析通了才送 `command(根名)`;服务器不让她用的当场失败,不送 |
| 她改规则 | 加 `deny`、`ask` 直接写入并回执;加 `allow` 或删行发卡 |

**征询协议**(第一版已落地,保留):

1. 服务端登记处 `ConsentDesk` 挂在同伴身上,一只同伴同时挂一条请求:id、清单(动词、坐标或实体、命中的规则与归属、名字)、到期游戏刻。
   清单真的变了才由新的顶掉旧的,旧的按拒绝收尾。
2. 清单按"动作 + 对象 + 理由"归堆发主人客户端。理由用归属说:"主人放的""说不清是谁的""村子里的";撤不回的整行警示。
   世界里给涉及的方块和实体描轮廓,请求结束就撤。
3. 答复框取代这只同伴的输入行:**允许**(本任务)、**以后都允许**(另写一行 `allow` 进主人层)、**拒绝**、拒绝并附一句话。
   有撤不回的项时不给默认选中。右上角 toast 提醒按键答复。
4. 卡片与 `/numen consent` 命令落到同一个入口 `ConsentDesk.reply`,只认主人。拒绝的附言原话交给模型。
5. 两分钟没答、主人离线,按拒绝,理由"主人不在场,无法征得同意"。
6. 悬着期间不占模型,没有 LLM 开销;同步动作这次调用悬着,后台任务停在原地,期限不走表。

**允许的作用范围。** 本任务内,同一行规则问出来的同一种方块(或同一只实体)都算已授权,不再重复问——穿过一座木屋只弹一张卡。
任务收尾即清。

## 九、模块

拆成两层,按组合接起来:

| 层 | 放什么 | 在哪 |
|---|---|---|
| **规则核心**,纯 JVM,不碰游戏类 | 规则语法的解析与打印;对象条件的语法树(`&`、`|`、`!`、括号);判决与判定顺序(§五);层与硬规则;主体匹配;命中计数;谁能改什么(§四);"允许并记住"从一次命中推出一行 `allow`;对象组的登记口——核心只知道组名与"问提供者属不属于" | 新的顶层模块 `permission/`,与 `ai/`、`ui/` 同类,单测几毫秒跑完 |
| **游戏适配** | 把游戏里的一下动作翻成核心的"主体 + 动作 + 对象";原版的对象组提供者(放置记录、结构、自然方块表、树叶持久、驯服记录);属性;名字校验(id、标签是否存在);裁决快照 `Gate`;征询登记处与网络载荷;存档;命令 | `numen-api` 的 `com.dwinovo.numen.api.permission` |

- 寻路不依赖权限层,经 `TerrainPolicy` 端口问,拆分不影响它。
- 插件经 `numen-api` 登记对象组(§三.4),不碰核心。
- 将来走服务端插件(包括 Paper 一类没有加载器的平台),核心原样带走,只重写适配层。

## 十、存储与命令

**存储。** `PermissionStore`,每主人一份存档:主人层规则(每行原文、来源是主人还是她、命中计数、最近命中时间)与名下每只同伴的模式。
读档经规则核心解析,写错的行记错误日志、不进表。硬规则开关在服务端配置,不在存档。任务期授权不落盘。

**"允许并记住"推出的规则**:同一个动词;对象认那一只实体(`entity:<uuid>`)或那一种方块、物品、指令根名,
并留着问出它的那一行的条件;撤不回的属性这一次不成立的,取反钉上——卡上没标撤不回,记下的规则就盖不到撤不回的情形。

| 命中 | 存成 |
|---|---|
| `break(owner)` 挖了圆石 | `allow break(owner & minecraft:cobblestone)` |
| `break(unknown)` 挖了橡木木板 | `allow break(unknown & minecraft:oak_planks)` |
| `attack(named)` 某只狼 | `allow attack(entity:<uuid>)` |
| 没有规则说到的 `setblock` | `allow command(setblock)` |

**命令**(主人专用,只调公开接口,不复制判断):

```
/numen permission mode <同伴名> [ask|bypass|observe]
/numen permission rules list                    硬规则、主人层(带序号、来源、命中次数)、出厂层
/numen permission rules add <deny|ask|allow> <规则>
/numen permission rules remove <序号>
/numen permission rules reset                   清空主人层
/numen consent <allow|remember> <请求 id>
/numen consent deny <请求 id> [附言]
```

面板的规则页列出每条规则、来源与命中计数,照 Claude Code 的 `/permissions` 对话框做。

## 十一、相对第一版改了什么

| 第一版 | 本版 |
|---|---|
| 信号 `placed`、`self_placed`、`owned`、`self_owned` | 归属组 `self`、`owner`、`other`、`structure`、`nature`、`unknown`(方块)与 `self`、`owner`、`other`、`nature`(实体)。存档里主人层带 `placed` 的行读档时改写成 `(owner \| other)`,`owned` 改写成 `(self \| owner \| other)`,改写后记一条日志 |
| 没记录就当自然方块 | 自然方块表里的才是 `nature`,其余落 `unknown` 去问 |
| "玩家放的"一律问主人 | 主人的问主人,别人的硬规则拒绝 |
| 床、门、活板门、栅栏门单列 ask 行 | 由归属覆盖,删掉单列 |
| `near_placed` | `near(<组>)` |
| 对象条件只有 `&`、`!` | 加 `\|` 与括号 |
| 规则无主体 | 可选 `@同伴名` |
| 模型没有任何写入口 | 模型能收紧,不能放宽 |
| 规则代码与游戏类缠在一起 | 规则核心独立成纯 JVM 模块 |
| 无命中计数 | 每条规则记命中 |
| 寻路的 `costs.consent`、`route.plan` 的 `asks`、`move.go` 的计划承诺 | 随寻路第 7 步删掉(`adr/pathing/0016-model-says-where-only.md`);要问的格只加价,走到那一刻问 |

不变:八个动词、三种判决、三种模式、默认问、征询协议与答复框、"允许并记住"、撤不回提示、鼠标在每一下之前问、物理安全不归权限。

## 十二、分步落地

前提:寻路第 7 步已合入。

1. **拆核心。** 新建 `permission/` 纯 JVM 模块,把规则语法、判决、判定顺序、"允许并记住"的推法搬进去并改成对象组口;
   `numen-api` 只留适配。行为不变,第一版的 GameTest 全过。
2. **归属。** 放置记录认主人名下的同伴;原版对象组 `self`、`owner`、`other`、`structure`、`nature`、`unknown` 与自然方块表、树叶持久判断;
   出厂层与硬规则换成 §六;存档里旧行改写。
3. **主体与命中计数。** `@同伴名`、计数与最近命中、规则列表显示来源与计数。
4. **她改规则。** 加 `deny`/`ask` 的 API 与回执;加 `allow`、删行走征询卡。
5. **面板规则页。**(已落地,见末尾"落地时的出入(第 5 步)")
6. 领地插件、区域组:有真实需求时按 §三.4 接。

**GameTest**(每步随步补):

- 装模组前就有的木屋(场景里直接写方块、不经放置记录)挖之前问;同一片地形里的石头直接挖。
- 野树砍、木屋原木问;玩家放的树叶不算野树的叶。
- 村庄结构件里的木板问,废弃矿井的木板直接挖。
- 别的玩家放的方块:规则、`bypass` 都解不开;主人放的问,答应后挖。
- 主人名下另一只同伴放的算主人的。
- 她加 `deny` 立即生效并回执;她加 `allow` 弹卡,拒了不写入。
- 判定顺序:主人层的 `allow` 盖不过任何一层的 `deny`;书写顺序不影响结果。
- 寻路默认可挖时绕开 `unknown` 的墙(加价),必须穿过时走到跟前问,拒了绕开。

规则核心的单测:解析与打印往返、判定顺序、`|` 与括号、主体匹配、收紧与放宽的判别、"允许并记住"的推法。

## 落地时的出入(第 1 到 4 步)

- **命中账在主人的存档里。** 硬规则、出厂层、主人层三处的账都记在这位主人的 `PermissionStore`,按"层名 | 表 | 规则原文"认。
  规则本身随模组发、不进存档,账只能跟着主人走。只有真动手前的那一问(`Gate.judgeLive`)记账,规划时逐格定价的 `judge` 不记;
  模式、任务期授权、没有规则覆盖定下的答复不是哪一行规则定的,也不记。`Verdict` 因此带上定下答复的规则与它所在的层。
- **服主的两个开关在服务器设置 `config/numen/server/server.json`。** `hardRules`(默认开)与 `unknownAsOther`(专用服默认开,单机与局域网默认关)。
  专用服上文件不存在时写出一份默认的;读不懂的文件记错误日志、取默认。
- **她加 `allow`、删行的征询卡是命令项。** 卡上写成她没法自己跑的那条命令(`/numen permission rules add allow …`、
  `/numen permission rules remove <表> <序号>`),主人看得懂也能自己敲;不提供"允许并记住",她不能给自己发许可。
- **旧存档行改写。** `placed`、`self_placed`、`owned`、`self_owned`、`near_placed` 按 §十一 改写并记日志;
  改写后的行经规则核心规范打印,所以 `!placed` 成了 `!(owner | other)`。
- **放置记录里不知道是谁放的**(记下放的人之前的存档)直接算 `unknown`:有人放过,不能当地形。
## 落地时的出入(第 5 步)

- **面板的"权限"页读写走库协议的一种 `permission`**,不另开包。整表由 `RuleBook`(命令 `rules list` 与她读的 `numen.permission.rules()`
  读的同一份)编成 JSON:服主的硬规则开没开、主人名下每只同伴的模式、三层规则(每层 deny、ask、allow 次序,带来源、理由、命中账)。
  写有四种:加一行(`put`)、按规则原文删一行(`delete`,不按序号:她可能在两次读之间加过行)、清空主人层(`reset`)、设一只同伴的模式(`mode`),
  调的都是 `PermissionStore` 的公开方法,规则对不对仍只由规则核心的解析判,写错的答复带着错误码,界面用命令那一套 `numen.command.rule_mistake.<码>` 翻。
- **只有主人读写自己那一份**:协议入口只认发请求的玩家,不看是不是管理员;模式只能设在他名下的同伴身上。硬规则与"说不清按别人算"的开关是服主的服务器设置,
  页面只报告硬规则开没开,不提供开关。
- **规则有变就推**:存档任何一处变(她加了行、命令改了、命中账涨了)记下是谁的,每 10 个服务端刻合并成一包推给在线、装着客户端的主人
  (`PermissionFeed`)。比"每刻一包"粗一点:挖矿时每一格都命中一次,半秒的窗口既让计数看着是活的,也不把整张表(出厂层三十多行)每刻发一遍。
- **规则页上没有铅笔**:主人层的行只有删,没有改——改一条规则就是另一条规则(命中账从零数起),删了再加。删在右键菜单里,和别的库页面一致。
