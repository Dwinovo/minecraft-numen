# 权限层:她能动什么,谁说了算

本文讲身体的任何动作在动手前怎么过权限。与 `pathing.md` 的分工:那份讲寻路怎么走;寻路只是权限层的调用方之一,攻击、开容器、
丢物品、执行指令是另外几个。决定的来历在 `adr/control/`(0020 问题与登记的门、0025 权限层只判不认、0026 "这是谁的"去问、
0027 按动作问一圈)。

心智模型一句话:**她要动手之前,按"做的是哪种事"问一圈;有人说不许就不做,主人说过不用问就做,有人说要问就问;都没人说话,
看主人给这种事定的档。** 权限层自己什么都不懂:不认方块、不认实体,也不知道"这是谁的"——懂的是登记进来的回答者。

```
干活的人(工具、任务、插件) → 她身体上的入口 → 权限层(问一圈、合结果) → 回答的人(谁懂谁登记)
```

## 一、八个动作

| 动作 | 词 | 出厂的档 | 名单里记什么 |
|---|---|---|---|
| 挖方块 | `break` | 许 | 那种方块的 id |
| 放方块 | `place` | 许 | 放的那样东西(物品)的 id |
| 交互方块 | `use_block` | 许 | 那种方块的 id |
| 打实体 | `attack` | 许 | 玩家或有主人的:那一只(uuid);否则那一种(实体类型 id) |
| 交互实体 | `use_entity` | 许 | 同上 |
| 扔东西 | `drop` | 问 | 物品 id |
| 用手里的东西 | `use_item` | 许 | 物品 id |
| 执行命令 | `command` | 问 | 命令根名(别名同认) |

动作是她的身体动手的方式,不是模组的名词;模组的操作说成这八种里的一种。从容器里拿东西不是单独的一问,归右键打开它的那一下
`use_block`(实体是 `use_entity`):界面开了之后搬东西不再过权限层。`use_item` 是她的手真正去用手里那件物品的那一下:对着空气右键,
或右键方块、实体没被吃掉、落到物品自用的那一下。

## 二、回答者

谁懂谁登记,和别的问题同一个门(`adr/control/0020`):

```java
numen.answer(Questions.PERMIT, "my_claims", (action, facts) ->
        isInMyClaim(action, facts) ? Answer.deny("is inside a claim", Component.translatable("mymod.claim"))
                                   : Answer.ABSTAIN);
```

回答者(`Answerer`)被问"这个动作、这个对象,许不许",答四种之一:**不许、要问、许、不表态**。不许与要问带一句理由——给模型与日志的英文
一句(回执里拒绝与要问的理由,不带主语),和给主人卡片上看的同一句(`Component`,走翻译键)。只说自己懂的,互相不知道对方,不懂就不表态。

- **线程。** 裁决既在服务端主线程上做(真要动手前),也在寻路的搜索线程上做(给每一格定价,量很大,读不到活世界)。所以回答者可能在
  任何线程上被叫,只读传给它的那份事实(`Facts`:方块视图、归属查表、要动手的同伴;`facts.live()` 在搜索线程上是 null),要读活世界
  才知道的事在搜索线程上按保守的答(宁可估成要问,不估成免费)。每定价一格就可能被问一次,别做慢事;不改世界,不留状态。
- 回答者抛了异常,只丢它那一条,记进日志,别的回答照常。
- 动作的清单这次不对插件开放登记。

### 内置的回答者:归属

`Ownership`,名字 `ownership`,经同一个门登记。动作的对象是方块或实体时,问"这是谁的"(`Owners` 问一圈,`Whose` 把回答换算成对要动手的
同伴来说是谁):

| 这是谁的 | 回答 |
|---|---|
| 别人的(别的玩家、别人名下的同伴、别人的宠物) | 不许 |
| 主人这一边的(主人本人、主人名下别的同伴、主人的宠物) | 要问 |
| 她自己的、没主人的 | 不表态 |

**是谁的不由权限层认,也不由它记。** 两个问题,回答者经 `numen.answer` 登记:

```java
// 这只实体是谁的。服务端主线程上被叫。
numen.answer(Questions.ENTITY_OWNER, "my_golems", entity ->
        entity instanceof MyGolem golem ? golem.masterId() : null);

// 这一格方块是谁的。主线程上交回她身边一片的查表,之后任何线程逐格读这一份。
numen.answer(Questions.BLOCK_OWNER, "my_claims", (level, center, chunkRadius) -> {
    Map<ChunkPos, UUID> owners = MyClaims.copyAround(level, center, chunkRadius);
    return owners.isEmpty() ? null : pos -> owners.get(new ChunkPos(pos));
});
```

- 实体由 Numen 答原版的驯服记录(回答者 `tame`:狼、猫、鹦鹉,以及继承原版驯服的模组宠物;记着的主人是一只活着的非玩家时不算有主)。
  **方块在原版里没有主人,Numen 不答**;知道哪些格子有主人的一方(领地模组的插件)登记回答者。
- 没人回答,就是没主人的。几个回答者说的不是同一个人,取最严的:别人 > 主人 > 自己。
- 方块的回答分两步:取裁决快照的那一刻(`Permission.gateFor`)在主线程上把她身边一片的归属抄成一份不可变的查表,之后哪条线程来问都只读
  这一份。没有任何方块回答者时那份查表是空的,逐格定价不扫。
- 身体本身就是一个人的实体(玩家、同伴)而没人说它另有主人,按那个人算。

后果:纯原版、没装回答方块归属的插件时,每一格方块都是没主人的,归属不表态,只看档位;装了这样的插件,别人的圈地不许碰、主人的要问,
自己生效。Numen 只出一套办法,保护有多严看装了谁来回答。

**同一个道理也用在"这一下右键会做什么"上**(`Questions.CLICK`,回答者 `ClickActions`):鼠标右键按在一格方块上之前,两只手里的东西各问一圈
"拿着这一叠按在这一面上会对世界做哪几件事",回答者交回动作(今天都是一次 `place`),Numen API 把各人说的合起来、再加上它自己的那一问
`use_block`,逐件交给裁决。原版的四种由 Numen 登记:方块物品贴着命中面放进可替换的格、桶、打火石、火焰弹;模组的放置类物品由它的插件登记;
没人认得的物品,这一下只问 `use_block`。回答者在服务端主线程上被叫;寻路规划不问这一圈。

## 三、合起来的顺序

先碰到哪条算哪条(`Merge`,纯逻辑):

1. 有回答者说不许 → 不做;
2. 在主人"不用问"的名单里 → 做;
3. 有回答者说要问 → 问主人;
4. 有回答者说许 → 做;
5. 都不表态 → 看主人给这个动作定的档(许 / 问 / 不许)。

不许是解不开的;主人说过不用问的就不再问。任务期授权(主人在卡上点了"允许")只把这一次任务里同一个动作、同一个名字的"要问"变成放行,
解不开不许。代码里不写死"能"也不写死"不能":放行来自名单、回答者的"许"与主人定的档,拒绝来自回答者的"不许"与主人定的档。

## 四、主人的设置

每只同伴一份(`Settings`):

- **八个档位**(许、问、不许):第 5 步没人说话时照它办。`observe`(全不许)、`bypass`(全许)是预设——只动档位、不动名单;另有
  "恢复出厂"(档位回到出厂的档,名单清空)。注意预设只定档位:名单里的名字与回答者的"许"仍排在档位前面。
- **每个动作一张"不用问"的名单**(一组名字,记什么见 §一)。名单在征询卡上点"以后都允许"进去,也能用命令、面板加删。

服主在权限里不占位置:没有服务器级的档位或开关。

**她(模型)自己只能往严了调**(`Edit.loosens` 是唯一的判据):把一个档位调严、从名单里删一项,直接生效、回执说清、也告诉主人;把档位调松、
往名单里加一项,发一张征询卡经主人——卡上写成她没法自己跑的那条命令(`/numen permission set …`、`/numen permission list add …`),主人看得懂
也能自己敲,不提供"以后都允许"。

## 五、动作分类

| 档 | 动作 |
|---|---|
| 从不问 | 看(`scan`、`status`、`inv` 的查询、`build.diff`)、合成烧炼、吃、装备、换手——不改世界,不是权限层的动作 |
| 出厂放行 | 挖、放、右键方块、打实体、右键实体、用手里的东西;别人的东西由归属不许,主人的由归属要问 |
| 出厂问 | 扔东西、执行命令 |

挖不动(基岩)、岩浆与危险格、摔落上限回答的是"做不做得到、会不会伤到自己",是物理,不经裁决、不弹卡,留在寻路与身体。

## 六、检查时机与征询

**三个时机。**

| 时机 | 做什么 |
|---|---|
| 规划 | 寻路的代价只读裁决快照(端口 `TerrainPolicy`,Numen 以 `Gate` 实现):放行按原价,要问的格加价(默认 10 倍),拒绝是墙。只裁决挖与放,不裁决右键 |
| 执行开始 | 一件成批的活(建造施工前、攻击开打前)把动作整批裁决,要问的合成一张卡 |
| 每次动手 | 她身体改世界的入口在每一下之前问:鼠标 `Mouse`(左键挖、打,右键点方块、点实体、用手里的东西)、直接写一格(`BlockWriter`);走路时走到要问的那一格跟前停下发卡。答应了接着走;拒了那一格在这一趟里当墙、重新规划绕开,绕不开才以 `denied` 收场 |

干活的一方不问权限:卡长在她身体改世界的入口里,内容只调入口,入口去问。要主动问的只有两种:开工前打听一批动作里哪些要问(合成一张卡、
给寻路定价),和插件做了一件不经过她身体的事(`GatedAct`)。

**各内容的接入点。** 内容只提出动作,判与问都归权限层。

| 内容 | 什么时候送动作 |
|---|---|
| `move.walk`、`move.fly`、`move.glide`、`move.away`、`move.follow` | 规划时只读裁决定价;走到要改的格子那一刻由鼠标问 |
| `work.dig` | 挖给它的每一格,动手前问;够不着先走过去,路上要改的格同上 |
| `build.place` | 施工前把要清的与要放的整批裁决,一张卡;拒绝的格按"主人不让动"跳过并写进回执;每一格真写下去时由写格入口再问一次 |
| `fight` | 开打前送目标,一张卡,等答复期间不打它;自卫换目标时新冒出来的再送 |
| `use.block`、`use.entity`、`use.hit`、`use.item` | 按下去之前送指名的那一格、那只实体上的动作:右键一格方块,先是手里的东西会做的事(问一圈 `ClickActions`),再是 `use_block`;没被吃掉、落到手里的东西自用时再问 `use_item` |
| 往容器里放、从容器里取(`container.put`、`container.take`、`furnace.take`、`lectern.take` 等) | 右键打开它的那一下送 `use_block`(或 `use_entity`);界面开了之后搬东西不再送任何动作 |
| `inv.drop` | 每次送 `drop` |
| `numen.mc.run` | 解析通了才送 `command(根名)`;服务器不让她用的当场失败,不送 |
| 她改设置 | 调严直接写入并回执;调松、往名单里加发卡 |

**征询协议:**

1. 服务端登记处 `ConsentDesk` 挂在同伴身上,一只同伴同时挂一条请求:id、清单、到期游戏刻。清单每条是"哪个动作、哪个对象、谁要问、
   为什么、点了以后都允许会记下什么名字"。清单真的变了才由新的顶掉旧的,旧的按拒绝收尾。
2. 清单按"动作 + 对象 + 理由"归堆发主人客户端。理由是说"要问"的那个回答者(或主人定的档)给主人看的那一句:"你的""你定的是问"。
   世界里给涉及的方块和实体描轮廓,请求结束就撤。
3. 答复框取代这只同伴的输入行:**允许**、**允许并说一句**、**以后都允许**(按钮上写明记下的是什么,如"以后都允许:挖 橡木原木")、
   **拒绝**、**拒绝并说一句**。允许与拒绝都可以附一句话,原话交给模型。右上角 toast 提醒按键答复。
4. 卡片与 `/numen consent` 命令落到同一个入口 `ConsentDesk.reply`,只认主人。
5. 两分钟没答、主人离线,按拒绝,理由"主人不在场,无法征得同意"。
6. 悬着期间不占模型,没有 LLM 开销;同步动作这次调用悬着,后台任务停在原地,期限不走表。

**允许的作用范围。** 本任务内,同一个动作、同一个名字(同一种方块、同一种物品、同一只实体、同一个命令根名)都算已授权,不再重复问——
穿过主人的一堵墙只弹一张卡。任务收尾即清。"以后都允许"另外把那个名字记进这只同伴这个动作的名单。

## 七、模块

拆成两层,按组合接起来:

| 层 | 放什么 | 在哪 |
|---|---|---|
| **纯逻辑**,不碰游戏类 | 八个动作、四种回答、档位、一只同伴的设置、预设、那五步合并(`Merge`)、调松还是调严(`Edit`) | 顶层模块 `permission/`,与 `ai/`、`ui/` 同类,单测几毫秒跑完 |
| **游戏适配** | 把游戏里的一下动作翻成动作与名字(`Action`);回答者的口(`Answerer`、`Answer`、`Facts`);问归属的那一圈与换算(`Owners`、`Whose`)与内置的归属回答者(`Ownership`);裁决快照 `Gate`;征询登记处与网络载荷;存档;命令 | `numen-api` 的 `com.dwinovo.numen.api.permission` |
| **原版的回答** | 驯服记录的回答者(`VanillaOwners`)、右键会做什么(`VanillaClicks`) | `numen`,经 `numen.answer` 登记,和插件同一个写法 |

- 寻路不依赖权限层,经 `TerrainPolicy` 问。
- 插件经 `numen-api` 登记回答者(§二),不碰纯逻辑。
- 走服务端插件(Paper 一类没有加载器的平台)时,纯逻辑原样带走,只重写适配层。

## 八、存储、命令与面板

**存储。** `PermissionStore`,每主人一份存档:名下每只同伴的八个档位(只存与出厂不同的)与每个动作的名单。任务期授权不落盘。
更早的存档里的规则行与模式读不通:记一条错误日志(`the permission save holds the older rules and modes`),不生效、不迁移;
文件不因此重写,旧内容到这份存档下一次落盘时才没有。写着此刻不认得的动作或档位的项同样记日志、不进表,别的项照读。

**命令**(主人专用,只调公开接口,不复制判断):

```
/numen permission show <同伴名>                          八个档位与每个动作的名单
/numen permission set <同伴名> <动作> <allow|ask|deny>   设一个档位
/numen permission preset <同伴名> <observe|bypass|factory>  套预设
/numen permission list add <同伴名> <动作> <名字>          往名单里记一项
/numen permission list remove <同伴名> <动作> <名字>       从名单里删一项
/numen consent <allow|remember|deny> <请求 id> [附言]
```

她读自己的设置用 `numen.permission.settings()`;调严用 `numen.permission.set`(往严的一头)与 `numen.permission.remove`,调松用
`numen.permission.set`(往松的一头,发卡)与 `numen.permission.add`(发卡)。

**面板的"权限"页**(客户端,未经真机验)。

- 读写走库协议的一种 `permission`,不另开包。整表由 `PermissionStore` 编成 JSON:名下每只同伴每种动作一行档位(`tier`),和每个名单里的
  每一项一行(`listed`)。写有三种:设一个档位(`tier`)、套一个预设(`preset`)、从名单里删一项(`delete`),调的都是 `PermissionStore`
  的公开方法,认不出的动作、档位、预设办不成、不改任何东西。
- 只有主人读写自己那一份:协议入口只认发请求的玩家,不看是不是管理员;只能改他名下的同伴。
- 设置有变就推:存档任何一处变(她调严了、命令改了)记下是谁的,每 10 个服务端刻合并成一包推给在线、装着客户端的主人(`PermissionFeed`)。
- 页面上面是每只同伴一节:名字与三个预设钮,下面八行各是一个动作和它的档位分段钮;下面是名单列表,按动作分节,右键一项能删。

## 参考

- Claude Code 文档 `permissions`、`permission-modes`:每类工具一个基本档、模式调基本档、"以后别再问"按工具类型记不同的名字、按钮上写明记的是什么。
- Common Protection API:保护类模组登记成提供者,内容模组动手前问;问题是固定的几个,没有"从容器里拿"。每个动作一个函数,答放行、
  拒绝或不拍板。
- 原版加载器的破坏、放置、交互事件:谁都能来听,任何一个取消就算取消。
