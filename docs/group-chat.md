# 群聊:多只同伴同处一个场面

状态:设计稿(2026-09-21),未落地。与 `architecture-mind-model.md` 的收件箱(§四)、
唤醒经济学(§三)一脉相承,落地时按 §十 修宪。界面部分照 `ui-design-rules.md`。起因是 #34。

## 一、问题

今天两只 Numen 站在一起,彼此是哑的。仓里没有任何同伴↔同伴的通道。

但"多只同伴"本身已经成立:名册、每同伴一个家、每同伴一个收件箱、每同伴一条循环,
都是现成的。缺的只是"她们能不能听见彼此"。

直接让她们互相说话是最自然的想法,也是所有同类实现踩坑最深的地方——两个 LLM 互相
回复没有天然的停止条件,而每一轮都是两份账单。真正的代价不是钱,是**主人失去了对场面的
控制**:他插不进去,也不知道什么时候能插进去。

## 二、不变量

整篇设计只有一条,其余全是它的推论:

> **唤醒只能由人产生。同伴说的话永远只是上下文,不产生唤醒。**

这不是"加了限制所以不会失控",是**失控没有路径**:每一次模型调用都能追溯到一次主人的
敲击。于是下面这些别人必须做的东西,我们一个都不用做——

| 别人的补丁 | 我们为什么不需要 |
|---|---|
| 轮数上限(`max_round`/`max_turns`) | 没有"一轮讨论"这个东西要终止 |
| 选发言人的额外 LLM 调用 | 主人点名就是选人 |
| 互聊冷却计数器 | 同伴的话不唤醒任何人 |
| 失速/循环检测 | 循环需要两端都能自发,这里只有一端 |
| 忙/闲四象限 + 要不要插话的判断 | 没被点名就不醒,不存在插话 |

代价是主人要当路由器。这不是代价,是目的。

## 三、三个角色

一条主人的话进来,三种身份:

- **主人**——唯一的唤醒源。
- **醒的**——收到急件,照常开一轮:该干活干活,该回话回话。
- **旁听的**——同一句话进她的收件箱,**但不触发熟度**。她下次因为别的事醒来时,
  这句话跟着那一轮一起进上下文。

第三条是整套东西省钱的地方:旁听者免费知道发生了什么,**不额外唤醒 = 不额外花钱**。

同伴说出口的那句话,对其他人也按旁听处理。所以 A 答了什么 B 听得见,但 B 不会因此醒来。

## 四、落到现有骨架

宪法 §四 已经把这件事准备好了:**一种事件的一切写在类型表的一行里**——怎么拼给模型、
进不进聊天流、主人按停止清不清、是不是主人说的、投递方式、是否恒为急件。

群聊需要的两种投递,正好是类型表已有的两档:

```
醒的     → 急件,STEER,立刻开轮
旁听     → 进队列,不参与熟度,等下次开轮时一起取走
```

所以**这是一个新的事件类型,不是一套新系统**。服务端唯一发出口仍是 `NumenEvents.emit`,
主人在线直送、离线进出箱、重连整批补发——跨服务器的同伴(不同主人、不同客户端)因此
天然可达,不需要第二条链路。

一条硬事实要在界面上说清:**主人不在线,他那只同伴根本没在跑**,群里就是少一个人。

## 五、形状

### 5.1 `@` 是转话头,不是寻址

群里有一个**当前话头**。`@` 把话头转给谁,转过去就一直是她,直到下次转:

```
@A 去挖铁      → 话头给 A,A 醒
多挖点          → 还是 A 醒,不必再打 @
@B 你去砍树     → 话头转给 B
```

这样 `@` 从"每句都要打"变成"偶尔转向",快捷对话(Y)那条路才不会废掉一半。真群聊的
手感本来就是这样:大部分时间在跟一个人说,偶尔换个人。

**一句话里没有 `@`,而且话头还没落到任何人身上时,全体都醒。**

这不是兜底,是和说话意图对上的:没点名的话通常本来就是说给全体的("我回来了"、
"天黑了"、"小心背后"),而派活的时候人自己就会打 `@`,因为心里本来就有人选。
N 只醒仍是 N 次唤醒对**一次**敲击,线性,不变量不破。

代价老实写在这:**两只可能同时接同一件活**。你说"去挖铁"忘了打 `@`,两只都应一声、
都跑去同一个矿。浪费的不是 token,是你得再说一次。两个天然的缓冲——说话规则本来就压着
她们"活干完或失败、有危险、有真问题才开口",以及先醒的那只说的话会进后醒那只的上下文
(旁听是在她说出口那一刻投递的)——前者靠谱,后者几乎同时醒时不保证。

**不为此加调度**:最坏情况是重复一趟,而为它加一层协调机制,就等于把 §二 省掉的东西
又捡回来了。

### 5.2 解析

`@` 在**客户端注入时**解析成收件人 UUID,不是留给模型去读的字符串。

判据是群成员的名字,不做子串匹配——名字互为前缀会误判(`Ann` / `Anna`)。

一条话可以点多个:`@A @B 一起去挖铁`,两次唤醒对一次敲击。

### 5.3 旁听者看到的东西

每行必须带发言人前缀:

```xml
<talk>
[主人 → A] 去挖点铁
[A] 好,我去东边那个矿洞
</talk>
```

前缀不是为了好看。模型上下文里只有 user/assistant 两种角色,**所有"别人"会塌缩成同一条
无法区分的流**——三方以上的场面里,B 分不清那句是主人说的还是 A 说的。AG2 为此专门做了
一种带名字的视图类型,并在源码注释里点明了这个原因。

**共享的是说出口的那句话,不是整个回合。** A 的工具调用、思考、回执都不进 B 的上下文:
既贵又没用。这份"说出口的"我们已经有了,就是气泡上显示、念出来的那一份。

### 5.4 三种模式是同一机制的开关

| 模式 | 话头上的那只 | 其他成员 |
|---|---|---|
| 群聊 | 急件 | 旁听 |
| 私聊 | 急件 | 什么都不给 |
| 全员静默 | 旁听 | 旁听 |

不是三套代码,是同一个事件带不同的收件人集合。

## 六、入口与界面

### 6.1 一处扩展,三件套不改

快捷交互三件套(R 选人 → Y 发文字 → V 按住说话)都只认**当前交互对象**
(`SelectedCompanion`)。群聊要的全部改动是:

> **`SelectedCompanion` 从"一只同伴"扩成"一只同伴 <b>或一个群</b>"。**

R/Y/V 一行不改——它们不关心那个槽里是谁。选中的是群时,发出去的话走 §五 的投递规则。

### 6.2 G:名册里建群

群和同伴**同列**在名册里。群那一行右边是铅笔(改名 / 改成员)和红垃圾桶(解散,过确认卡)
——`ui-design-rules.md` 写死的:"改与删是并排的两个入口"。

新建走 `＋ 新建群`,位置和画法与人设库的 `＋ New` 一致。点进去是勾选成员 + 起名字,
**一页说完,不藏子页**。

一个群就是**一个名字 + 一串同伴 UUID**。没有成员管理页,没有权限角色,没有群公告。

### 6.3 R:群占一个扇区

和同伴并排在轮盘上。头像用**叠起来的两三张脸**,一眼看得出是一群人。

群的数量天然很少,不为"轮盘挤了"做设计。

### 6.4 聊天面板

- **抬头一行成员头像**,当前话头的那只高亮。话头是 §5.1 的核心语义,得看得见。
- **连发合并**:同一只同伴接连说两句,只画一次头像。她一次说两句是常态,不合并会刷屏。
- **被 `@` 的名字高亮**。这不只是好看——它正好对应"谁会醒",主人扫一眼就知道每句话
  是喊给谁的。

聊天框仍然是日志(`ui-design-rules.md`):主人说的、同伴说的、要留痕的失败。

## 七、明确不做

- **中心调度器 / orchestrator。** 它会成为第二个决策源,和"改世界或伤害实体只由权限层
  裁决、没有第二个入口"直接冲突——**同伴的许可是她主人给的,不是队长给的**。这也正是 #71
  那套设计不能要的原因。
- **同伴能唤醒同伴。** §二。
- **按距离决定谁在群里。** 按 Y 跟她说话本来就无视距离,群聊突然讲距离就是凭空多一条
  主人没见过的规矩。群是显式建的,成员是名单说了算。
- **额外调 LLM 选发言人。** 主流正在淘汰这个做法(AG2 v1.0 撤掉了、LangChain 把
  `langgraph-supervisor` 停维、OpenAI 两代都没有过)。我们连它的替代品(handoff 工具)
  都不需要。
- **轮数上限当终止机制。** 硬上限是安全网,不是终止逻辑;谁拿它当主机制,谁就稳定地
  砍在半成品上。
- **每人每轮必须发言 / 全量 transcript 每轮重拼。** 强制发言就是强制烧钱,全量重拼是
  O(轮数²)。
- **为了让大家到齐而暂停世界。** 学术实现靠这个拿到可复现性;**陪伴产品里主人就在旁边玩,
  世界不能停。**
- **为群聊单开一条"说话"链路。** 她说的话已经是气泡那一份,群聊只是多了个听众。

  Project Sid 的反例值得抄在这里:agent 有两个独立 LLM 模块,人说"给我一把镐",
  chat 模块回 "Sure thing!",function 模块却去 explore ——**人拿着想象中的镐走了。**

## 八、协作靠世界,不靠对话

"A 把铁给 B"是一个世界动作,不是一句话。她们共享同一个箱子、同一堵墙、同一片地,还各有
一份札记。**能靠世界传的信息就别用对话传。**

这条是调研里最一致的结论:效果最好的实现都把**事实**从对话里搬走了——ChatDev 的黑板只进
结论不进对话,MetaGPT 的黑板是磁盘上的 git 目录,Anthropic 的子 agent 只回传一两千 token
的摘要。而我们的黑板就是世界本身,比谁的都实。

所以"主人要当路由器"在实践中没想象的累:真正需要来回协商的场合很少,大部分协作用世界
就传完了。

## 九、账单与规模

- 一句话要复制进 N 只同伴的上下文,**线性于 N,不是 N²**(因为没有互聊)。
- 每只同伴有自己的 provider 绑定,是 N 份账单。`TokenLedger` 是现成的抓手。
- **天花板在服务端,不在模型。** Project Sid 号称 1000+ agent,论文自己交代跑崩了,
  瓶颈是 Minecraft 服务端算力;而我们的同伴是真 `ServerPlayer`,比他们重得多。
  MineCollab 那篇的建造任务,三个 agent 以上就"超出预算做不起"。

先按**两到三只**设计,不为更多做抽象。

## 十、宪法修订

落地时同步改 `architecture-mind-model.md`:

- §三 C1 增加 `<talk>`(旁听到的话),与 `<memory>` 并列
- §四 类型表增加群聊事件类型,写清两种投递方式
- §三 唤醒经济学里"同伴互聊"那一条,改成本文的不变量:同伴互聊**不产生唤醒**

## 十一、分步落地

1. 群这个对象 + 事件类型 + `@` 解析与话头(纯 JVM,可单测)
2. 注入 `<talk>` 块与名字前缀
3. `SelectedCompanion` 扩成"一只或一个群";G 建群、R 轮盘出群
4. 聊天面板:成员抬头、连发合并、`@` 高亮
5. 三种模式的开关
6. 跨主人(服务端转发)

前两步做完就能两只同伴同处一个场面了,第 3 步起是产品面。
