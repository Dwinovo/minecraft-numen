# numen 心智模型宪法

一个同伴 = 一具身体(服务端)+ 一个大脑(客户端 LLM)+ 两个消息口。
任何新功能必须能在本文档里找到自己的位置;找不到,先修宪再动工。

**仓界(2026-07-16 裁决):机器在 numen-api,内容在 numen-core。** 判定口诀:
"这是机器,还是塞进机器的内容?"——收件箱/大脑循环/任务队列与竞价调度/
工具运输/异步受理/闲时生命体征是机器;本能链/任务执行器/30 个工具/寻路是
内容,经四个登记口插入(BrainChains 链、CompanionTaskFactory 任务执行器、
ToolRegistry 工具、ReflexRegistry 本能名册),外加 TaskSessionHooks 会话
结束回调(core 在此释放意图钉)。第三方内容包与 core 地位平等。

## 一、身体层:每 tick 一次竞价

所有想控制身体的机制都是 `TaskChain`,每 tick 向 `CompanionBrain` 出价
(`getPriority`),最高价独占身体,被抢占者收到 `onInterrupt`。

```
MLG(10) > 换气(6) > 反击/逃跑(5) > 进食(4/3) > 脱困(2) > LLM 任务(0)
└──────────────── 本能(硬编码,不花 token)────────────┘   └ 认知 ┘
```

- LLM 是出价最低的竞价者:任何本能都可随时抢走身体,完事归还。
- LLM 链内部按模型 tool call 的先后顺序执行任务(FIFO 只存在于这条链内部)。
- 不需要独占身体的自动行为(挖矿换工具、食物过滤、索敌过滤)不是链,
  是任务执行中被咨询的纯函数策略——没有 tick,没有优先级,不参与竞价。

## 二、大脑层:事件驱动,平时不在场

LLM 不在 tick 循环里。它只在三种时刻运转:主人说话、外部消费者显式唤醒
(核心域不使用)、自己的工具结果回来。它对身体的全部控制 = 向 LLM 链投任务。

## 三、模型输入全景:四层,动态口只有两个

```
A. 静态框架(每 turn 组装) A1 系统提示词 = 基座指令 + persona(+反射总览/语言指令,规划中)
                            A2 工具表(schema + description)
B. 历史                     B1 对话历史(ConvoLog 回放)
                            B2 压缩摘要(上下文过长时替换旧历史)
C. 本 turn 新输入(user 侧)C1 主人消息(含忙时缓冲)
                            C2 事件:收件箱三态路由(§4)——回合中贴边界,
                               任务中立刻开轮,全闲躺着搭车
D. turn 内回填(tool 侧)   D1 任务工具结果
                            D2 查询工具结果(get_self_status 等,拉取语义)
```

**动态注入口仅 C2 与 D1。核心域 C2 无紧急档。**
`emitEvent(xml, urgent)` 的 urgent 参数保留为公开 API 能力,仅供外部
交互型消费者;核心自身永远传 false。

**唤醒经济学(urgent 的裁决口诀)**:"这次唤醒在替谁花钱?"
替任务花(存在悬置 turn)→ D1 本来就会送达,无需唤醒;
替身体花 → 本能链应对,与模型无关;
替陪伴感花(主动打招呼/日程/同伴互聊)→ 产品功能,走 urgent API、
配开关、主人决定——即使实现在核心仓库里,也按"外部型消费者"接入,
不进 BodyLog、不修本宪法。

## 四、收件箱:模型输入的三态路由

主人的话和世界的事进同一个收件箱(每同伴一个,push 即落盘、消费即清,
跨会话不失忆)。消费时机由**发生时大脑的状态**决定,不由输入类型决定:

```
push(输入) ──┬─ 回合进行中     → 进箱躺着,工具批结算的边界一次倒空
             ├─ 后台任务执行中 → 立刻开轮(任务期间的事是军情,模型有权当场改链)
             └─ 完全空闲       → 进箱躺着,等下一个轮子搭车
```

- **唯一的例外位 principal**:"活人在说话"(主人本人、桥接的弹幕/QQ)在
  完全空闲时也开轮。世界/身体事件恒 false——事实不配自定紧急度。
- **倒箱 = 拼一条 user 消息**,固定顺序:状态快照(current_task/known_blocks,
  消费瞬间现取)→ 事件(按到达序)→ 主人的话压轴。躺超过 10 分钟的条目
  标注年龄(跨会话恢复的旧闻尤其要紧)。
- **进行中的请求永不掐断**;主人的停止按钮是队列外的物理开关,不是输入。
- **身体叙事(BodyLog)降级为纯生产者**:本能动作、抢占经过一律 report 进
  BodyLog,它即报即发(打包成 body_log 事件 push 进收件箱),唯一滞留原因
  是主人离线(有界积压,回线重试)。旧的双轨路由(忙时扣押、贴工具结果
  尾巴)已废除——其前提"任务链有活=模型正阻塞等结果"被异步任务抽掉了。
  闲时杀个僵尸不吵人,挖矿时被袭立刻上报,同一件事按状态各得其所。
- 死亡叙事无特权:干活时死=发生在任务态,复活后立刻开轮;闲逛时死=躺着
  等主人问起。主人的知情由 vanilla 死亡广播保证,与模型无关。
- 判定口诀:"这段文字是身体替自己写的日记吗?"是 → BodyLog;
  不是 → 各回各家(工具结果本体、主人消息、状态快照、静态框架)。
- **核心代码永远不直接调 emitEvent,一律 report 进 BodyLog**;emitEvent
  作为公开 API 保留,principal=true 仅供桥接模组转达活人消息。
- 已知偏离:换维度叙事暂由引擎直发(loader 维度钩子 →
  `Companions.onDimensionChanged`)——观察点只存在于引擎 loader 层,
  待 BodyLog 下沉引擎层时统一收口。

## 五、显式意图:钉(pin)

反射提供默认,显式意图压过反射,认知层管理例外的生命周期。

- **落钉**:模型/主人显式 `equip_item` 即为意图声明,自动落钉,无需新指令。
- **归还**:`equip_item` 的 item 取值 `"auto"` = 解除该槽位的钉,反射恢复。
- **过期**:四个自然终点——显式更换或归还 / 物品损坏 / 物品离开槽位 /
  主人姿态开关关闭整条链。**刻意不设定时器**:钉对认知层可见
  (`get_self_status` 标记 + 让位日记),陈腐意图由模型自己清理。
- **可见性**:反射因钉让位时记一次日记(去抖);任何卫兵类机制拒绝显式请求时,
  失败消息必须附带解除方法(拒绝时教学)。
- 裁决记录(2026-07-15):资产保护类反射(工具耐久卫兵、自主穿甲)整体下架——
  真机暴露"保住石镐、空手挠铁矿"的静默任务降级,用户裁定此类"替玩家心疼资产"
  的自动干预弊大于利。装备与耐久决策归还认知层(模型自行判断/主人指示)。

## 六、Reflex(本能)登记处

Reflex 不是运行时概念,是自动机制的入职契约:

```java
interface Reflex {
    String id();        // "mlg"
    String describe();  // 一行自述,汇入系统提示词反射总览
    // report(人话) 经 BodyLog 路由;通道与紧急度永远不由反射决定
    // enabled() 姿态开关由 Registry 统一管理(持久化,主人可关单项)
}
```

- 执行形态各归各位:要身体的 implements TaskChain(照旧),
  纯策略只 implements Reflex。没有第二个调度器。
- 新机制的接入成本 = 机制本身的逻辑;自述进提示词、动作进 BodyLog、
  姿态开关、尊重钉,全部由登记处自动获得。

## 七、异步任务与事件登记处

长跑任务(move_to / auto_mine / hunt / collect_items / wait)受理即回执:
工具结果只承载 `{task_id, async:true}`,身体在后台跑,大脑当场自由——
干活期间照常聊天、感知、规划。

- **一具身体一件活**:LLM 车道上有任何工作时,新的异步派发与同步动作工具
  一律拒绝并报出当前任务号。排队不可取:串行的工具派发器会被长活整个卡死。
  拒绝话术把选择权丢回模型(task_stop 叫停,或等收尾再派)。
- **收尾走事件,不走工具结果**:task_finished 发生在任务态,按收件箱三态
  路由(§4)自动落进"立刻开轮"档——它顶替的是旧同步模式里最后那次工具
  结果往返,不是新增开销。timeout 事件携带进度,重派同一调用可续做;
  stopped 是叫停的回执,叫停通常发生在回合中,自然贴边界送达。
- **事件登记处**(numen-api `GameEvents`):所有 `<event>` 类型在此登记
  kind,XML 组装与转义在此收口——散装手搓 `<event>` 字符串违宪。登记处
  不管时机:何时被消费是收件箱按状态路由的事,事件类型没有贵贱之分。
- **模型侧感知**:每个用户回合注入 `<current_task>`(客户端自记账:受理
  回执置位,对上 id 的 task_finished 清零,死亡清零);task_status 拉取
  现场,task_stop 叫停。禁止轮询——完成必然主动送达。
- **目标重算在任务层,进度携带只在寻路层**:重派任务=从当前世界状态重新
  求解(背包里已有的收获天然就是进度),已算路径由寻路层自己缓存。任务层
  永不做挂起/恢复簿记——每次打断后的"恢复"就是一次带新信息的重算,免费
  且无陈旧状态(mindcraft/女仆/AltoClef/Baritone 四方调研的共同形状,
  2026-07-16 裁决)。
- **拒绝式受理,不做替换式**:撞车时拒绝并报任务号,由模型显式 task_stop
  再派,不学"新指令静默停掉旧任务"——替换省一次调用,代价是手滑重复派发
  会误杀干了一半的活。真嫌两步繁琐,未来给派发加 replace 参数,不改默认。

## 八、检验:新功能四问

1. 要不要独占身体?→ 是:新竞价链,定优先级;否:纯函数策略。
2. 是模型发起的吗?→ 是:LLM 链里的任务,消息走 D1。
3. 是身体自己发生的吗?→ 是:report 进 BodyLog,双轨自动路由。
4. 模型需要预先知道这机制吗?→ 是:实现 Reflex,自述自动进提示词。

四问答完仍无处安放的功能,先修宪再动工。
