# numen 心智模型宪法

一个同伴 = 一具身体(服务端)+ 一个大脑(客户端 LLM)+ 两个消息口。
任何新功能必须能在本文档里找到自己的位置;找不到,先修宪再动工。

**仓界(2026-07-16 裁决):机器在 numen-api,内容在 numen-core。** 判定口诀:
"这是机器,还是塞进机器的内容?"——收件箱/大脑循环/任务队列与竞价调度/
工具运输/异步受理/闲时生命体征是机器;本能链/任务执行器/30 个工具/寻路是
内容,经四个登记口插入(BrainChains 链、CompanionTaskFactory 任务执行器、
ToolRegistry 工具、ReflexRegistry 本能名册)。第三方内容包与 core 地位平等。

## 一、身体层:每 tick 一次竞价

所有想控制身体的机制都是 `TaskChain`,每 tick 向 `CompanionBrain` 出价
(`getPriority`),最高价独占身体,被抢占者收到 `onInterrupt`。

```
MLG(10) > 换气(6) > 反击/逃跑(5) > 进食(4/3) > 脱困(2) > LLM 任务(0)
└──────────────── 本能(硬编码,不花 token)────────────┘   └ 认知 ┘
```

- LLM 是出价最低的竞价者:任何本能都可随时抢走身体,完事归还。
- LLM 链内部按模型 tool call 的先后顺序执行任务(FIFO 只存在于这条链内部)。
- 不需要独占身体的自动行为(挖矿换工具、食物过滤、索敌过滤)不是链,
  是任务执行中被咨询的纯函数策略——没有 tick,没有优先级,不参与竞价。

## 二、大脑层:事件驱动,平时不在场

LLM 不在 tick 循环里。每只同伴在主人的客户端上有一个循环内核(`AgentLoop`,纯 Java 的 `agent`
模块),它对身体的全部控制 = 派工具。设计稿见 `docs/agent-loop.md`。

- **唯一的推进点 `pump()`**:只在四种时刻被调——有输入进队列、一次 run 结束、停牌解开、每个客户端 tick
  (只为"攒够时长"这一条熟度)。闲着、没停牌、队列熟了才开一次 run;只在真的开 run 或执行控制条目时
  打日志,停牌时每 tick 调一次也没有输出。
- **一次 run 是 ReAct 的两层循环**:(该自动整理就先整理)→ 注入排着的输入 → 调模型 → 串行跑完它派的
  工具 → 再调模型……直到模型给出最终回复、而且队里没有要接着处理的输入。
- **停牌**(`Hold`)说明为什么不开 run,谁解开写死在一张表里:
  `DEAD`(复活解开)、`EXTERNAL`(外接大脑驾驶,现算)、`OWNER_STOP`(主人再说话)、
  `BLOCKED`(模型端点不可用;主人再说话或改绑解开)、`FAILED`(调用失败不再重试;主人说话或来了急件)。
- **切断只有一个入口 `halt(reason)`**:主人停止、死亡、登出、外接接管、遣散的差别只在 `HaltReason` 那张表
  (叫不叫停身体、清不清队列、进哪种停牌、目标收不收工)。
- **内核不碰界面**:它只发 `LoopEvent`,打字机与语音与气泡(`TurnPresenter`)、token 台账、整理记忆
  (`Compactor`)、长期目标(`GoalSteward`)、工作站坐标、当前任务镜像各自订阅。"她忙不忙、为什么不动、
  排着什么"只从 `LoopStatus` 一处读。

## 三、模型输入全景

```
A. 静态框架(会话内字节稳定,是缓存前缀)
   A1 系统提示词 = 人设 + 操作核心 + 技能表 + 命令索引 + 本能名册 + 札记的规矩 + 说话规则
   A2 工具表 = 全部工具的完整定义(自家的、插件带的、接进来的 MCP 一并发出)
B. 历史
   B1 对话历史(ConvoLog 回放;切断点照实记录,发请求前由 ProtocolView 统一配平)
   B2 整理记忆的摘要(替换更早的历史,近段原文保留)
C. 注入的输入(每次一条 user 消息,进历史)
   C1 札记索引 <memory>(她一 remember 就变,所以不进系统提示;全份重贴,只在开一局 / 压缩后 / 变过时发)
   C2 世界的事 <events>(按发生时间排)
   C3 主人的话(垫底);目标续跑也是这里的一条
D. 请求期挂载(每轮现算,不进历史)
   D1 <runtime_state> = 当前任务 + 背包 + 状态效果 + 骑乘 + 插件的身体状态片段
E. turn 内回填(tool 侧)
   E1 工具结果
```

**急不急写在类型表里**:一种事件要么恒为急件(`alwaysUrgent`),要么由发的那一方按事情本身定
(任务按收尾状态、主人挨打按血线)。

**唤醒经济学(急件的裁决口诀)**:"这次唤醒在替谁花钱?"
替任务花 → 收尾事件本来就会送达,不必另外唤醒;
替身体花 → 本能链应对,与模型无关;
替陪伴感花(主动打招呼、日程、同伴互聊)→ 产品功能,登记自己的事件类型、配开关、主人决定。

## 四、收件箱:投递方式写进类型表

主人的话和世界的事进同一个收件箱(每同伴一个,入队即落盘、取走即清,跨会话不失忆)。
**每个条目有一个类型,类型表(`EventTypes`)的一行说清它的一切**:拼给模型的样子、进不进聊天流、
主人按停止时清不清、是不是主人说的、投递方式、是否恒为急件。

```
投递方式  run 进行中                          闲着
STEER     下一个边界注入(这批工具结算后、     参与熟度判断
          下次调模型前),不打断在跑的工具
FOLLOW_UP 只在本来要停时接上                  参与熟度判断
CONTROL   不插进 run,等闲下来执行            立即执行;不受停止/端点/失败停牌影响,
          (整理记忆、清空上下文)              死着、外接驾驶时拒绝并说明原因
```

- **熟度**:有急件就开;否则按主人设的主动性档位,攒够条数或最老的一条等够时长才开。
- **注入一次取光**,拼成一条 user 消息:现场块在前 → 世界的事按时间排进 `<events>` → 主人的话垫底。
  躺超过 10 分钟的条目标注年龄(跨会话恢复的旧闻尤其要紧)。
- **进行中的请求永不因输入掐断**;主人的停止键是 `halt(OWNER_STOP)`,不是一条输入。
- **事件的种类就是类型表的一行**:`task_finished`、`death`、`hungry`、`owner_hurt`、`timer`、`woke`、
  `dimension_change`、`reflex`(本能做了什么,带上是哪个本能)、`dropped`。服务端只有一个发出口
  `NumenEvents.emit`:主人在线直送,离线进出箱,重连时整批打成一个包补发。
- **插件同一扇门**:`NumenApi` 登记事件类型、发出事件,与内置事件同一条路;客户端上的桥接(弹幕、群消息)
  发主人的话或登记过的世界事件,入口是 `NumenGateway.emit`——游戏里的面板和快捷对话也走它。
- **死亡**:`halt(DEATH)` 进停牌 `DEAD`,队列照收不误(条目盖着真实时间戳,模型分得清哪些发生在死前);
  复活时推一条急件死亡叙事,解开停牌,和死着期间攒的一起走。
- **状态不是事件**:"她这一轮身上是什么样"(饰品、模组装备位)每轮都要在、不能进历史——走服务端的身体状态
  片段,随状态包推给主人的客户端,进 `<runtime_state>` 和 `get_self_status`。
- 判定口诀:"这是发生了一件事,还是她此刻的样子?"事 → 发事件进队列;样子 → 状态片段。

## 五、Reflex(本能)登记处

Reflex 不是运行时概念,是自动机制的入职契约:

```java
interface Reflex {
    String id();        // "mlg"
    String describe();  // 一行自述,汇入系统提示词反射总览
    // 做了什么经 NumenEvents 发成一条 reflex 事件,带上本能 id;通道与紧急度由类型表定,不由本能定
    // 开关由 Registry 统一管理(持久化,主人可关单项)
}
```

- 执行形态各归各位:要身体的 implements TaskChain(照旧),
  纯策略只 implements Reflex。没有第二个调度器。
- 新机制的接入成本 = 机制本身的逻辑;自述进提示词、动作发成 reflex 事件、
  开关,全部由登记处自动获得。

## 六、异步任务与事件登记处

长跑任务(move_to / auto_mine / attack / collect_items / wait)受理即回执:
工具结果只承载 `{task_id, async:true}`,身体在后台跑,大脑当场自由——
干活期间照常聊天、感知、规划。

- **一具身体一件活**:LLM 车道上有任何工作时,新的异步派发与同步动作工具
  一律拒绝并报出当前任务号。排队不可取:串行的工具派发器会被长活整个卡死。
  拒绝话术把选择权丢回模型(task_stop 叫停,或等收尾再派)。
- **收尾走事件,不走工具结果**:task_finished 进收件箱(§四),完成、失败等要她当场知道的
  由发送方标成急件——它顶替的是旧同步模式里最后那次工具结果往返,不是新增开销。
  timeout 事件携带进度,重派同一调用可续做;stopped 是叫停的回执,叫停通常发生在
  回合中,自然在下一个边界注入。
- **事件唯一入口**(numen-api `NumenEvents`):所有 `<event>` 的 kind 在此登记,
  XML 组装、转义、游戏内时间戳在此收口——散装手搓 `<event>` 字符串违宪。
  入口不管时机:何时被消费是队列按自己规则说了算,事件类型没有贵贱之分。
- **模型侧感知**:每个用户回合注入 `<current_task>`,内容由**服务端推**
  (`CurrentTaskPayload`,槽一变就发),客户端只照抄不推断——重启重放、
  死亡复活重放起来的活,客户端自己是看不见的。task_status 拉取现场,
  task_stop 叫停。禁止轮询——完成必然主动送达。
- **目标重算在任务层,进度携带只在寻路层**:重派任务=从当前世界状态重新
  求解(背包里已有的收获天然就是进度),已算路径由寻路层自己缓存。任务层
  永不做挂起/恢复簿记——每次打断后的"恢复"就是一次带新信息的重算,免费
  且无陈旧状态(2026-07-16 裁决)。
- **替换式受理,不做拒绝式**:身体只有一个槽,派新活直接顶掉旧活,不必先
  task_stop——主人改主意是常态,"她在挖矿所以不理你"是最直观的一种出戏。
  唯一拒绝的情形是槽里那件**同一批工具调用里刚受理**的:那说明模型在一个
  回合里连派两件活,该让它拿到第一件的结果再决定。

- **表不是身体任务**(`set_timer` / `TimerRegistry`):不占身体、不进任务槽,当场
  返回。到期时刻记的是主世界游戏刻的**绝对值**(世界不跑表就不走,重启不重新
  计时),跟着存档落盘。到点发一条 `timer` 事件(类型表里恒为急件)——主人离线进出箱、
  她死着停牌不开 run,都由既有的那条路答,这里不重复实现。它是给"世界不会主动
  通知你"的事准备的:炉子、庄稼、天亮;自己派出去的活会发 task_finished,
  用表去盯就是把轮询换了个马甲。

## 七、检验:新功能四问

1. 要不要独占身体?→ 要:进任务槽(有界短走 `runSync`,无界走 `setTask`);
   不要:当场返回,不进任务系统(查询、UI、`set_timer` 这类登记)。
2. 是模型发起的吗?→ 是:一个 `NumenTool`,回执按 §六 的口径写。
3. 是身体自己发生的吗?→ 是:走 `NumenEvents`,离线与开轮时机由它和队列答。
4. 模型需要预先知道这机制吗?→ 是:实现 `Reflex`,自述自动进提示词。
5. 这个动作会不会改世界或伤到实体?→ 会:必须经过权限层(§八)的裁决,没有第二个入口。

五问答完仍无处安放的功能,先修宪再动工。

## 八、权限层:身体的任何动作在动手前怎么过门

设计稿 `docs/permission-layer.md`。放在 api,它是机器;core 的任务与工具是往里送动作的
内容。五个零件:

**动作(Action)。** 身体要对世界做的一件具体的事及其目标:`break(pos)`、`place(pos, block)`、
`attack(entity)`、`use_block(pos)`、`use_entity(entity)`、`take(container, item)`、`drop(item)`。
不带工具名、不带 JSON。

**信号(Signal)。** 给动作贴事实的函数,每个只回答一个通用问题,不按种类枚举:

| 信号 | 问题 | 来源 |
|---|---|---|
| placed | 这格是不是玩家放的 | `BlockItem.place` 返回处的 mixin,放的人不是同伴就按区块记进每维度一份 SavedData;查询时格子已是空气视为无记号;同伴自己垫路的不记,build 完工把成果格登记 |
| block_entity | 这格有没有方块实体 | 方块状态 |
| contents | 容器里有没有东西 | 世界(只在主线程读;搜索线程按"有") |
| owned | 这只实体有没有主人 | `OwnableEntity` |
| named | 有没有自定义名字 | 实体 |
| villager | 是不是村民 | 实体类型 |
| hostile | 是不是敌对 | 实体分类 |
| hazard_item | 放的是不是岩浆、火、TNT、水 | 物品 |
| near_placed | 放置点附近有没有玩家放的方块 | placed 的邻域查询 |
权限层只做原版,领地模组之后以联动插件做。原生通道里服务器退回的挖掘,由挖掘落点如实报成被拒,
那是身体汇报,不是权限裁决。

**代码里不写死能,也不写死不能。** 放行只来自 allow 行与主人选的 bypass;拒绝只来自主人写的
deny 行与主人选的 observe;其余一律问。身体的物理与安全判断(岩浆、摔落上限、
挖不动)不属权限,不经裁决。

**规则(Rule)。** deny、allow、ask 三张表。一条规则一行字符串 `动作(信号 & 信号 & !信号)`,
项也可以是方块或实体种类 id、`#标签`、`entity:<uuid>`。查的顺序 deny → allow → ask → 都不中
也问(allow 在 ask 之前,因为"允许并记住"存的是从 ask 行里抠出来的更细的 allow 行)。出厂:
deny 空;allow 为 `break(!placed & !block_entity & !#minecraft:beds & !#minecraft:doors &
!#minecraft:trapdoors & !#minecraft:fence_gates)`、`place(!hazard_item)`、
`place(hazard_item & !near_placed)`、`attack(!owned & !named & !villager)`、`use_block(*)`、
`use_entity(!owned)`、`take(*)`;ask 为 `break(block_entity & contents)`、`break(placed)`、
`break(block_entity)`、`break(#minecraft:beds)`、`break(#minecraft:doors)`、
`break(#minecraft:trapdoors)`、`break(#minecraft:fence_gates)`、`attack(owned)`、`attack(named)`、
`attack(villager)`、`drop(*)`、`place(hazard_item & near_placed)`。

**不可逆提示。** `attack(owned)`、`break(block_entity & contents)` 是普通 ask 行,允许与记住都
盖得住;征询卡片把命中它们的清单项标出"撤不回"。

**裁决(Verdict)。** 唯一入口 `Permission`:主线程 `judge(companion, action)` 对活世界问一个动作;
`gateFor(companion)` 取一份快照(模式、规则、放置记录、任务期授权)交给搜索线程逐格问。答复
三种:放行;拒绝并附理由;需要主人同意并附理由。

**模式(Mode)。** 每个同伴一个,存在主人的 SavedData 里:`ask`(默认,走规则表)、`bypass`
(全放行)、`observe`(只看不动,拒绝一切改世界的动作)。

**三个时机,各管一事。**

| 时机 | 做什么 |
|---|---|
| 规划 | 成本模型只读裁决:拒绝无穷大;要问的格在 `alter=any` 下按有限代价算进路线、其余规格下无穷大;`TerrainBill.Break.consent` 带着那一条征询 |
| 执行开始 | 整条路线或整个动作过一次裁决,需要同意就发起一次征询;不是走到墙边才问 |
| 每次动作 | `BlockDigger`(唯一挖掘落点)、攻击落点、放置落点强制,不发起征询;到这里还没授权就当动作失败,任务按既有机制重算或收尾 |

**各内容的接入点。** 内容只提出动作(`AbstractCompanionTask.permit`),判与问归权限层。mine 选目标
不看权限,规格 `alter=any`,按"走过去 + 挖它"的同一套定价挑,动手前把挖掘交给权限层;goto、follow
的导航采纳每段路之前,`alter=any` 的路把要问的格打包送一次;build 施工前整批裁决,要问的一张卡,
拒绝的格跳过并交代;attack 开打前送目标,自卫换目标时再送;interact_at 左键动手前送;drop_items
每次送。允许的作用范围:本任务内,同一行规则问出来的同一种方块(或同一只实体)。

**征询**是一个请求响应子协议:登记处 `ConsentDesk` 挂在身体上,同一同伴同时一条、新的顶掉旧的;
`ConsentRequestPayload` 推主人客户端,答复框取代这只同伴的输入行(G 面板与 Y 快捷对话同一张,右上角 toast 提醒按 Y 答复)→
允许 / 以后都允许 / 拒绝 / 不行并告诉她怎么做(附言只随拒绝)→ `ConsentReplyPayload` 回服务端(只认主人);主人离线或两分钟没答复按拒绝。等待期间
同步调用悬着、后台任务站住,期限都不走表。模型看到的只有普通的工具结果和回执;征询的答复走
任务回执,不新增事件种类。
