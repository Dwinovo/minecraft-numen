# 0012 建造只有直接写一条路:站不住的排到队尾重试一次,每刻三十格

- 状态:已接受
- 日期:2026-11-24
- 修订:body 0011 第 4 点里"每一格仍走原版的放置流程,原版规则放不出的样子才直接写"
- 另见:[control 0026](../control/0026-ownership-is-asked-not-recorded.md)(这格是谁的去问)

## 背景

0011 第 4 点的第一版(`3530e5c80`)让建造站在原地放,但一格怎么落进世界留了两条路:先"手放"——把"点哪一面、点面上哪一点、头朝哪"
列成一张 324 下的表,逐个问原版会放成什么,对得上图纸就真的点一下;一下都对不上才直接写。保留手放只为一件事:走原版的放置流程,
别的模组(领地)才看得见这次放置。

这张表的形状里写进了"原版方块大概怎么算"的知识(每面四个象限点、斜向只配顶面、固定按潜行),模组方块的规矩不同就对不上;
两条路并存,后一条是前一条的兜底。排顺序另有一张我们自己列的"哪些方块要依托别人"的清单(梯子、火把、告示牌、铁轨、红石线、
地毯、花……),和一套"等托着它的盖好再开一遍"的状态。用户:"我怎么感觉很特化呢""没必要搞这么大一张特化表在这里"。

读了几家的源码:

- 机械动力的蓝图(`BlockHelper.placeSchematicBlock`):`world.setBlock`,邻居不反应。
- 创世神(`WorldNativeAccess.setBlock`):直接改区块;通知邻居默认开,让这一格自己重算形状(`VALIDATION`)默认关;想拦的插件
  经它自己的 `EditSessionEvent` 登记。
- 投影的粘贴(`SchematicPlacingUtils`):全部写完,一格都不更新,开了开关的话最后逐格通知一遍邻居。
- MineColonies 的建筑工(Structurize 的 `PlacementHandlers`):`setBlock` 加 `setPlacedBy`。
- 建筑小帮手(`ServerTickHandler.build`、`RenderBlockBE.setRealBlock`):和我们最像——生存里隔着距离放、扣材料、按刻一格格放。
  一个队列;取出一格先问方块自己站不站得住(`canSurvive`),站不住的排到队尾、只重试一次;站得住的让它照着周围算好形状
  (`updateFromNeighbourShapes`),写进去并更新邻居,确认能放之后才扣材料。

没有一家模拟人怎么点。

## 决定

照建筑小帮手的结构。**一格怎么落进世界只有一条路:直接写。我们一种方块都不认识,要问的两句都由方块自己答——"你能待在这儿吗"、
"照着周围,你该是什么样"。**

1. **队列。** 这次要放的格排成一队:低层在前,同一层里离她近的在前。没有别的排序知识。
2. **每取出一格:**问它站不站得住。站不住,第一次排到队尾,等别的都放完再问;第二次还站不住就放弃,回执说这一格留不住、
   周围是什么。站得住:让它照着周围算好自己的样子,写进世界并更新邻居,然后扣料。
3. **每刻三十格**,生存与创造同一个速度(用户:"改成每刻30格吧,这样子玩家比较喜欢")。生存每秒四格、创造至少演二十五秒没有了。
4. **不发放置事件。** 领地保护走"这格是谁的,去问"(control 0026);平台的放置事件、Fabric 上的 Common Protection API
   这类"还没人接到的需求"先不考虑(用户原话)。

不变的:她站在原地、不看距离、不走路;不挖(生存下格里立着别的方块,回执说先挖开;创造直接顶掉);逐格过权限层、开工前要问的
一次问完;她身体占着的格不放;每一格只轮到一次(排队尾的那一次除外),没放成的不自动重来;放下就更新,世界说了算。

## 后果

- 324 下的点击表、"谁要依托别人"的清单、"等托着它的盖好再开一遍"都删掉;回执里"有几格是直接写的"没有了。
- 模组里带朝向的方块:图纸写什么样,世界里就是什么样。
- 装了领地模组、却没有回答"这格是谁的"的插件的服务器上,建造拦不住(挖方块仍走真玩家的流程,照拦)。
- 重试只有一次:托着它的那一格自己也是排到队尾的,它第二次仍站不住,就放弃、如实说。
- 靠"被放下"那一下自己反应的方块照原版:悬空的沙子两刻后掉下去,收工对图纸时如实报。
- 一份两百格的图纸七刻放完。

## 没有定的

- 写之前要不要向平台问一句"她能不能在这儿放"(NeoForge、Forge、Paper 发放置事件,Fabric 上只有第三方的约定):等真有人要。
