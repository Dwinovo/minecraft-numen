# 0002 身体只经输入层驱动:键盘、视角、鼠标、快捷栏

- 状态:已接受
- 日期:2026-06-13 起;09-28 收成一副键盘;10-07 归 Numen API
- 提交:`5d23e3984`、`d529eab10`、`6ba1f8540`
- 另见:`docs/input-pipeline.md` §七

## 背景

服务端玩家(body 0001)可以直接改位置、直接放方块、直接往背包里塞东西,写起来最省事;但那样她做的事和真玩家做的不是一回事
(穿墙点方块、瞬移),原版与别的模组看到的也不是一个玩家在操作。

## 决定

- 只设按键与视角,由原版走步、碰撞、迈上 0.6 格(照 Carpet 的 ActionPack,`InputDriver`,06-13)。假玩家没有客户端的包来改它的位置,按键就是真的在动。
- 09-28 寻路切换时收成一副键盘 `Controls`,每刻在她自己的实体刻里经 `Physics.step` 落一次;导航、本能、各件活按的都是这一副。拿东西到手统一走快捷栏 `Hotbar`。
- 10-07 键盘、视角 `Look`、鼠标 `Mouse`(准星、左键挖、右键用,动手之前过权限层)、快捷栏与它留下的记录 `BodyAction`、物理步进,
  以及身体与寻路共用的原版公式(`DigTime`、`Reach`、`Sight`、`Faces`)归 Numen API 的公开部分;谁驱动她都用同一份,第三方也可以自己写一套寻路按它让她动。
- 身体做的每件事都报告给模型:下载具、换工具、凭空取料、身体变化(背包增减、血量、骑乘、工具用坏)都记进结局。不做模型不知道的瞬移与背包改动。

## 后果

- 挖要转头瞄准、放要点中一面、看不见就点不中:规划必须知道"点不点得中、看不看得见"(寻路的 `Sight`)。
- 她和真玩家走同一条代码路径,权限层只需要守在"鼠标按下去"这一处。
- 换驱动者(寻路、本能、程序)时统一松开键盘与鼠标,不会留下按着的键。
