# 0007 界面里的钮、写字、交易:替她发客户端会发的包,读回来再报

- 状态:已接受;补充 0003(0003 只代答服务端在等的握手,这里代发玩家主动做的事)
- 日期:2026-10-21

## 背景

原版玩家能做、她做不到的一批事,都是客户端发一个包、服务端收包时校验并落地:附魔台的钮、切石机与织布机的钮、讲台翻页取书、选交易、信标定效果、铁砧改名、合成器开关、写告示牌、写书、起床、鞘翅起飞、骑着时开坐骑的物品栏、右键盔甲架的某一截(`INTERACT_AT`)。
界面都在服务端(`containerMenu`),她缺的只是"按一下"这个动作。

## 决定

- **只替她发客户端会发的那个包**,交给她连接上原版的 `ServerGamePacketListenerImpl.handleXxx`。入口只有一处:`NumenPlayer#packets()`(`ClientPackets`)。校验一条也不另写,原版不认就静默不做。
- **发完读回来**:原版拒绝时不报错,所以每个函数发完去看界面、物品、方块真的变了没有,如实报成功,失败则把读到的事实(要多少、有多少)说出来。写告示牌与写书原版先过文字过滤再排进服务端任务队列,读回来的活排在它后面(`afterHandled`)。
- **按界面种类读和做**:每种有名堂的界面一个 `MenuKind`(附魔台、切石机、织布机、交易、信标、铁砧、讲台、合成器),能做的事是几个小接口(选、改名、翻页、开关、取出),`MenuKinds` 按开着的界面的菜单类挑,不写总的 switch。
- **权限照旧在动手那一刻**:动到别人东西的(告示牌、讲台、信标、合成器)落在 `use_block`,交易落在 `use_entity`,取成品、取书是 `take`;不新增动作词。
- 信标按层数能选的效果取真客户端按钮的那张表:原版服务端收 `SetBeacon` 时不查层数,她只发真客户端点得了的。

## 后果

- 想让她再会一个界面里的操作:写一个 `MenuKind`,列进 `MenuKinds`;不在函数里各自 `connection.handleXxx`。
- 文字过滤是异步的服务器(Mojang 文字过滤配置)上,排队读回时可能还没写完,会读到没变;没开过滤的服务器上过滤是当场完成的。
