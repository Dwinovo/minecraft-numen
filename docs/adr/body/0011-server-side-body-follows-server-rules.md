# 0011 她是服务端的身体:守服务端的规矩,不替她模拟屏幕前的人

- 状态:已接受,已落地(实现说明见文末);第 4 点里一格怎么落进世界由 [0012](0012-build-writes-directly.md) 修订
- 日期:2026-11-24
- 修订:body 0002(输入层)里"鼠标只对准星落着的东西起作用"对方块的那一半;body 0009 末尾"方块不变"一句
- 另见:body 0009(实体已先行)

## 背景

身体一直照原版客户端做:转头、准星落在哪就点哪、手速照客户端的缓手。其中一部分是服务端真查的,另一部分只是
"坐在屏幕前的人"才受的限制,服务端并不要求,是我们在服务端替她模拟出来的。后一部分带来的全是麻烦:

- 方块要准星看得见才能点、才能挖。于是要算视线、挑看得见的面、被挡住先挖挡路的、寻路挑站位要算看不看得见,
  还多出"走到了却看不见"这种失败。
- 建造要手够得着、点得中才放。够不着就走过去,走路又会挖会垫:她挖穿过自己刚放的格(慢批四条用例)。
- 挖出来的东西落在地上,她站着等它落定、记一本去向的账,再走过去捡。

11-12 已经把点实体改成"够得着就点"(0009)。用户 11-24 定:

> 他是一个服务端实体,遵循服务端的规则就行。

建造"不必须让他像人";10-29 说过的底线是"无脑放,无视任何条件、距离"。

## 决定

**服务端查什么,她守什么;服务端不查的,不再自己加。**

1. 点方块、挖方块:够得着就行(原版服务端只查眼睛到这一格的距离,不查朝向,不查中间隔着什么)。不再要求准星落在它上面。
2. 转头直接转到位,不取整到鼠标像素。转头是给看着她的人看的,不参与判断。
3. 两次右键之间不隔 4 刻,挖碎一格之后不缓 5 刻:这两样是客户端的手感,服务端不计。
4. 建造站在原地放:不看距离、不为够着哪一格走路;低层先,层内就近。每一格仍走原版的放置流程(放置事件、
   模组方块自己的放置逻辑都在),原版规则放不出的样子才直接写。
5. 她自己挖出来的东西当场进背包,放不下的留在原地、回执如实说。本来就在地上的东西仍由 `numen.work.collect` 走过去捡。

留着的,因为是服务端算的或游戏机制本身:按键走路与物理、挖要花时间、够得着的距离、吃与拉弓的时长、攻击冷却、
容器里一格一格点、放置与破坏走原版流程。

第 4、5 两条比"真玩家发包"还多一步:真客户端做不到隔着距离放、挖了直接进包。这是服务端的身体才做得到的,用户明确接受。

## 后果

- 够得着的方块一定点得中、挖得动;"走到了却看不见"没有了;寻路挑站位只看够不够得着,能站的地方多。
- 她能隔着方块点、隔着方块挖,矿前面站着别的实体也照挖。装了反作弊、自己补视线检查的服务器上可能被拦。
- 建造时她不走动,远处的格也放;工地上不再有她挖的洞、垫的方块。建造不再有"够不着"这一类回执。
- 连着挖、连着右键比真玩家快。
- 挖矿的回执直接说得到了什么;等掉落物落定与掉落物去向的账没有了。
- 她站在图纸的格子里时那一格不放,回执说明;挪开是模型的事。

## 没有定的

- 看不见时点方块的哪一面(放东西、按钮这类要看面的右键)。
- 经验球要不要也当场收。
- 本来在地上的东西要不要也改成够得着就捡。

## 实现说明

第 4 点(建造站在原地放):

- 一格怎么落进世界只在 `task.build.BuildPlacer`。手放是一次 `gameMode.useItemOn`,点的是要放的这一格自己(原版对可顶替的格原地放,
  悬空的格也有得点);这一下点哪一面、面上哪一点、她朝哪,是一张固定的候选表(324 下),逐个拿原版自己的放置规则只读地问
  "这样点会放成什么",和图纸一字不差的那一下立刻用。朝向点之前设、点完还原,同一刻完成。一下都对不上、或一格要不止一件料,才直接写。
- 没有"够得着/够不着"了:`BuildSurvey` 的情形里是"放得进去"(`READY`);建造任务没有走路的相位,`Arrival.place`、`Destination.reach`、
  `Faces.inSightAll` 删了。`numen.build.diff` 交回的是 `ready`,没有 `far`、`next`。
- 顺序在 `BuildOrder.from`:贴附件最后,低层先,清障、整块、非整块,同档离她近的先。一遍放下的方块让原来立不住的格立得住了,
  就为它们再开一遍;每一格仍只轮一次。
- 开工前把这一次要放的全部格一次问完主人。转头、挥手、粒子对所有落下的格统一由 `BuildShowmanship` 演。
- 慢批 `GeneratorGameTests` 的四条(沼泽小屋与三棵树)因此变绿。Paper 上只编译过,没有端到端场景覆盖建造。

第 1、2、3、5 点:

- **够得着只有一个出处。** 能不能点、能不能挖是 `Mouse.reaches(BlockPos)`,就是原版服务端收挖掘包与右键包时查的那一条
  (`canInteractWithBlock(pos, 1.0)`:眼睛到这一格,交互距离加一格);走过去的判据是客户端的交互距离(`Reach.reaches`,不含那一格),
  寻路的到达目标 `Goals.reach` 用它。和 0009 对实体的两条一一对应。
- **鼠标指名哪一格:**`Mouse.dig(BlockPos)`、`Mouse.use(BlockPos, Direction, …)`,与 `attack(Entity)`、`use(Entity, …)` 对称;按准星的
  `pick`、`on` 没有了。右键没指名面时点朝着她眼睛的那一面,只在 `Faces.toward` 一处定("没有定的"第一条)。按之前仍朝那一格转一下头,
  给看着她的人看。
- **跟着没有了的:**可见面与视线的判据、挖掘里"看不见先挖挡路的"、寻路挑站位与给挖一格定价时算的视线、"走到了却看不见"的结局、
  为了看见要贴的面而潜行探出边沿搭桥。`Sight` 只剩 `numen.scan.sight` 在用(它照旧如实报看不看得见);`Faces.against` 留给寻路
  贴着邻格的面放方块与倒水;物品自己沿视线打的那一条(桶)照旧。
- **转头与缓手:**`Look` 直接转到位;两次右键之间的四刻、挖碎之后缓的那几刻删了,寻路给挖一格定的价同一处去掉。
- **挖出来的进背包:**`api.entity.Harvest`,每具身体一份。她的手挖碎一格的那一段(`ServerPlayerGameMode.destroyBlock`)里新进世界的
  掉落物,结束时逐件走原版的拾取(`ItemEntity.playerTouch`,先清掉拾取冷却);放不下的把冷却还回去、留在原地。挖掘的活、走路途中挖的、
  左键点碎的是同一处。模组端由两个可共存的 mixin 给出这一段的起止与掉落物,Paper 端由 `BlockDropItemEvent` 给出。干活的一方要说
  "挖到了什么"时开一本账(`Harvest.open`),回执是 `got` 与 `on_ground`。原来记掉落物去向的 `Drops`、等落定、去向的句子都删了。
  经验球照原版,本来就在地上的东西仍由 `numen.work.collect` 走过去捡("没有定的"后两条)。
- **给模型的函数跟着变的:**`numen.use.item` 只用手里的东西,不再顺带点到面前的方块或实体;`numen.work.mine` 不再自己去捡,
  背包满了、有东西留在地上时停下并说明。
- 寻路可靠性矩阵里"头顶悬着会掉下来的方块"那一个场景去掉了(悬着的沙子两刻后自己掉,场景立不住);场景的零件伸出地形的那一列
  不再摆(原先会写进并行的邻格)。
