# 0002 GameTest 必须可复现;只有离不开真世界的才进 GameTest

- 状态:已接受,未落地
- 日期:11-05(与用户定)
- 相关:[0001](0001-gametest-short-deterministic-fixed.md)(本条补充它的第二节"规矩"与第一节"分层")

## 背景

0001 定了"确定、短、固定场地、不重试",落地后单遍整套全绿,但通读全部 41 个用例类(11-05 只读审计)发现结果仍然会变,
而且一次失败没法原样重现:

- **场地原点每次开服随机。** 原版 `GameTestServer.startTests` 用不定种子的 `world.random` 在 ±1500 万格里取原点,三个平台都没改。
  区块对齐、远处落点、下界地形、结构朝向都跟着变;一次红换一次开服就可能不见。
- **随机没定种子。** 我们自己的(`RecordedLevel` 的 `RandomSource.create()`、生成器里的 `ThreadLocalRandom`),原版的(实体 AI、掉落物初速、烟花寿命)。
- **"每刻等后台停下"漏了来源。** 只等寻路与 Lua 程序两样;MCP 的 HTTP 线程、皮肤签名线程不在里面,寻路"空闲"的判法有竞态;
  有的套件没换成按工作量计的搜索时钟。测试服两刻之间不睡,漏掉的墙钟直接变成刻数。
- **状态跨用例、跨运行残留。** 服务器配置目录跨运行保留、失败的用例不收场、有的批次没有批前设置,结果依赖上一条或上一次。

同时,大量用例测的是参数校验、提示文本、判据这类不需要世界的东西,也挤在 GameTest 里,拖慢整套又放大上面这些来源的影响。

## 决定

### 一、可复现(补 0001 第二节)

1. **同一份代码、同一组选择,结果逐次相同;一次失败能原样重放。** 场地原点固定(默认一个常量,可由开关指定),失败日志写明原点与种子。
2. **随机只有两种用法。**
   - 我们自己的随机:随机源可注入,用例给定种子。
   - 原版的随机:照主流,让用例不依赖它。
     - 实体用无 AI、清零速度、由用例推进(NeoForge `EntityFluidInteractionTests`、AE2 的做法)。
     - 实在绕不开的(钓鱼咬钩),断言与时限对全部取值成立,并在注释里写出取值范围的出处。
3. **每刻等齐全部后台来源。** 凡是被测代码在服务端起的线程或异步(寻路、程序、MCP、签名、区块生成与光照的等待),都登记进每刻等待;
   "空闲"按在飞计数判,不按线程池的瞬时状态。所有套件(含插件、手动套件)共用同一套等待与时钟设置。
   原版的区块系统也是一个来源,`BackgroundSettle` 每次都等:票据节流与区块升格经工作线程、存储 I/O 线程再排回各维的区块主线程执行器,
   原版只在一刻还有剩余墙钟时间时才执行那个执行器(`managedBlock` 也不例外),等的时候亲手把它做空;原版的活没有在飞计数可挂,
   就按存储 I/O 线程池、工作线程池(`Util.backgroundExecutor()`)都空闲且区块主线程执行器无任务判,顺着交接的方向先查上游、后查下游。
4. **每条用例从已知状态开始,不论成败都收场。**
   - 批前设置统一。
   - 测试服的配置目录每次开服重置。
   - 用例结束时同伴、程序、开关一律复原。
5. **证明稳定**照 0001:修完之后在一次开服里铺多份确认;铺份只是最后的确认,判断稳不稳靠读代码找来源。

### 二、准入:什么才进 GameTest(补 0001 第一节)

一条用例进 GameTest,当且仅当它的对错取决于真服务器才有的东西:原版物理与方块更新、实体与区块、网络与线程、从 Lua 入口到身体再到世界的整条链路。
其余放单元测试:
- 参数校验、拒绝与提示文本;
- 回执拼装、判据、规划与决策;
- 不碰世界的命令解析。

照主流(Fabric 自动化测试文档、AE2、Mekanism 把逻辑放 JUnit):

- 一个入口在 GameTest 里一般只留一条打通链路的正路,加上只有真世界才能产生的失败。
- 同一判据的多个变体在单测里穷举。
- 从 GameTest 挪到单测时,断言意思不变弱,提交里写明去了哪条单测。

## 后果

- 红了能重放,排查不再碰运气;整套更短,能照 0001 进推送 CI。
- 代价:
  - 我们自己的随机源要开注入口;
  - 实体类用例改成无 AI、由用例推进;
  - 单测要有不起服务器就能调 API 判据的接缝。现有的 `ApiTester` 优先复用。
