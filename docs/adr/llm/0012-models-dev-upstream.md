# 0012 厂家与型号目录改用 models.dev 做上游

- 状态:已接受;已落地(现状见 `docs/llm.md` 第十一节),厂家 `/models` 一级待做
- 日期:2026-10-08 讨论,10-10 定为 0.1.5 必做,10-12 对外承诺
- 另见:CurseForge 上 1.20.1 玩家报 OpenRouter "Invalid key",已答复 0.1.5 修复

## 背景

手工目录(llm 0003)只有 15 家,型号、上下文、思考形态都会过时;同一家不同型号的思考控制方式不同,按"每家一种形态"(llm 0008)表达不了。
[models.dev](https://models.dev)(opencode 团队维护,开源)是一份公开的全量目录:
- 228 家厂家,每家有默认地址、key 的环境变量名、文档链接,以及 `npm` 字段(调这家用 Vercel AI SDK 的哪个适配包,等于说这家讲哪种方言:
  188 家是 OpenAI 兼容、8 家 Anthropic、6 家 OpenAI 官方);
- 每个型号有能力(工具调用、带图、温度)、上下文与输出上限、价格(含缓存价)、思考怎么控制(`reasoning_options`:开关、档位及取值、预算及下限)、
  思考内容在哪个字段(`interleaved`)。

## 决定(方向)

- 型号能力全交给上游,运行时拉取、本地缓存、定期刷新;随包带一份快照(models.dev 托管在 Cloudflare,国内直连不一定稳)。
- 我们只维护一张"协议 × 思考控制类型 → 请求写法"的小表。不按型号名打补丁。
- 来源优先级唯一:玩家手填 > 厂家自己的 `/models` 接口 > models.dev > 随包快照;每一项只取最高的那个,不合并、不猜。
- 查不到能力的型号只给"自动"(什么思考参数都不发),厂家的报错原话交给玩家。新厂家走"添加自定义厂家"(地址 + 协议 + key)。

## 后果

- 取代 llm 0003 的手工目录,以及 0008 里"每家选一种形态"的写法。
- 协议仍是我们自己实现的那几种(llm 0009);models.dev 只给数据。
- OpenRouter 的 "Invalid key" 根因在设计稿里一并查清。
