# 0013 拿不准的协议细节照 pi-mono 做

- 状态:已接受
- 日期:2026-09-20 首轮对齐;10-14、10-15 用户定为惯例("按主流的来,参考 pi agent")
- 另见:`docs/llm.md` 第二节;pi-mono 源码 `packages/ai`

## 背景

各家协议的细节(思考怎么开关、出错长什么样、缓存断点打在哪、流怎么收尾)文档常常不全,只靠读文档和猜,我们漏过好几次:
OpenRouter 上的 Claude 从没缓存过,三种协议都把半截流当成功收下。手头没有每家的真 key,也不可能每处都用真接口验。
pi-mono 的 `packages/ai` 是一份开源、持续维护、被大量用户在真接口上跑着的实现,覆盖了我们接的三种协议。

## 决定

- 协议与厂家的行为细节拿不准时,读 pi 的源码,照它做;不凭印象,不自创写法。
- 和 pi 不一样的地方必须有我们自己的理由(比如每轮末尾附加的运行状态,见 [0016](0016-prompt-cache-all-protocols.md)),
  理由写进代码注释,出入列在 `docs/llm.md` 第十一节。
- 照 pi 对齐但没用真 key 验过的,如实标"未验证",并写出真接口上最该盯的几处。

## 后果

- 新协议、新厂家的适配先对照 pi,能少走一轮"上线才发现"。
- pi 改了做法,我们不自动跟;遇到问题再回去对照。
