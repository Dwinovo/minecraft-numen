# 0004 网络韧性照抄官方 SDK 的共识

- 状态:已接受
- 日期:2026-07-14;09-15 加取消令牌
- 提交:`1237a791d`、`202b2b918`、`7c8fc3929`
- 另见:issue #1

## 背景

国内网络与代理下,请求经常在开流前失败,或者流到一半卡住不动。JDK 的请求超时只管到响应头,半死的连接会把智能体循环永久挂起。

## 决定

读过 openai-python、openai-node、anthropic-sdk-python 的源码,按它们的共识实现:
- **只在第一个流事件之前重试:** 408、409、429、全部 5xx,`x-should-retry` 响应头可覆盖,以及连接错误与超时;默认 2 次。
- **退避:** min(0.5 秒 × 2ⁿ, 8 秒) × (1 − 0.25 × 随机数),照 Stainless 系的常数;`Retry-After`、`retry-after-ms` 在 0 到 60 秒之间时覆盖算出的值。
- **流式空闲看门狗 90 秒:** 任何一行(数据、keepalive、空行)都算活着。
- **流中途断掉:** 照 SDK 惯例往上抛,回合层丢掉半截(从未进入对话,天然幂等)再跑一次。
- SSE 行去掉回车,兼容按 CRLF 分块的后端与代理(#14)。
- **取消令牌(09-15):** 取消即关闭 SSE 订阅,不再回调、不再重试、不再退避。

## 后果

- 偶发的网络错误对玩家透明;真的连不上时报错原话交给玩家。
- 常数来自官方 SDK,不是我们拍的,以后跟着 SDK 调。
