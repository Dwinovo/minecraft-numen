- 状态:已被 [0012](0012-models-dev-upstream.md) 取代:目录改用 models.dev,`numen_providers.json` 与 DeepSeek/Moonshot 两个子类已删
- 日期:2026-06-19 起;08-01 样板类数据化;08-02 改名、协议进数据
- 提交:`f657a262e`、`979612291`、`d42580df6`、`4fa51ed87`、`53b308763`

## 背景

最早每家厂家一个类。其中智谱、硅基流动、阿里云、火山、MiniMax 五个类只改了名字和默认地址,而这两样数据里本来就有——同一份数据写了两遍。
压缩阈值也需要每个型号的上下文长度。

## 决定

- 内置一份厂家目录 `numen_providers.json`(最早叫 `tulpa_models.json`、`numen_models.json`):每家的默认地址、可选报头、
  思考开关的形态(`thinkingFormat`,见 llm 0008)、线协议(`protocol`,见 llm 0009)、几个预设型号与上下文长度。
  型号与上下文从 LiteLLM 的 `model_prices_and_context_window.json` 和各家文档刷新(06-19)。
- 连接地址的优先级:档案里填的 > 目录里这家的地址 > 适配器的缺省。(06-19 修过一个潜伏的错:请求一直用适配器写死的地址,
  自定义站点的请求悄悄打到 api.openai.com。)
- 只有真有行为差异的厂家保留子类:DeepSeek(缓存计费)、Moonshot(`reasoning_content` 兜底);其余都是一行数据。
- 目录只读内置;玩家自己的配置在档案库里(llm 0005),两者不共用文件。

## 后果

- 加一家兼容厂家是改数据,不改代码。
- 目录是手工维护的:型号、上下文、能力会过时,只有 15 家。这正是 0012 要换掉的部分。
