# 0014 每一档思考实际发什么,只由端点一处算出

- 状态:已接受
- 日期:2026-10-14
- 修订:[0008](0008-thinking-dialects.md)
- 提交:`bfc9944ac`、`38d250d79`

## 背景

0012 之后,型号支持哪几档由 models.dev 的档位表给出,但"这一档在线上写成什么"还要看协议和兼容项。界面问的是档位表,
请求体由各协议自己判断,两边不一致:只有开关的厂家照样列出低、中、高(发出去都是"开");OpenRouter 遇到只有预算的型号,
界面写着预算,请求里什么都没发;Anthropic 的老型号界面写"档位",实际发的是预算。

## 决定

- "这一档在这个型号、这个协议、这套兼容项下写成什么"只在 `ThinkingPlan` 算一次;请求体、界面列哪几档、每档的说明都只问它。
- 发不出参数的档位不列;只剩"自动"时界面整栏不出。"自动"什么都不发(0008 不变)。
- 照 pi([0013](0013-pi-as-reference.md)):OpenRouter 对推理型号一律写 `reasoning.effort`,只给预算或开关的型号缺省给低、中、高,
  关写 `none`;Anthropic 的关显式写 `thinking.type=disabled`。
- 预算型去掉不小于型号输出上限的档(预算算在输出里,发出去必被拒)。

## 后果

- 界面上的每一档都真的会发出去,说明写的就是实际发的。
- 0008 的"按形态分族"成了兼容项里的 `thinkingFormat`,只是 `ThinkingPlan` 的一个输入。
