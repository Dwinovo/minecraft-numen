# 0005 每只同伴一份模型档案,空库起步、不兜底

- 状态:已接受
- 日期:2026-07-14
- 提交:`f306ca669`、`eecb8273a`、`d0b6796d3`;`98c384246`(08-24)
- 另见:issue #2

## 背景

玩家想让同一局里的几只同伴接不同的模型(一只 ChatGPT、一只 DeepSeek、一只 GLM)。原来只有一份全局设置。

## 决定

- **档案库** `ProviderLibrary`(`config/numen/providers.json`,版式同人设库):每条档案是一份完整的连接配置
  (厂家、型号、key、地址、思考档位、代理、上下文长度)。召唤时给同伴选一条,之后它的请求都走这条。
- 连接参数解析成不可变的 `LlmEndpoint`,客户端按值缓存,同参数复用连接池;全局单例与"重置"退役。
- 同一天改了三版,最后定在"归零"的心智:
  1. 先是"条目空字段回退全局设置";
  2. 改为"条目自足 + 一条默认条目";
  3. **最终:库从空开始,没有种子、没有默认、没有任何回退。** 新建只要名字,其余可以先空着;同伴严格按选中的条目走,
     缺 key 或条目被删,第一次对话时给一条指向明确的报错(去设置里填)——错误即引导。
- 08-24:压缩阈值与水位按同伴自己的档案算,档案可以填上下文长度。之前"发请求用档案、算窗口用全局"是双源,DeepSeek 的 1M 窗口被当成 64k。

## 后果

- 不同同伴可以并存不同的后端;配置出错时玩家看得见原因。
- 档案里的"厂家"指向目录(llm 0003)里的一行,目录换成 models.dev 后,这一层引用要跟着定(llm 0012)。
