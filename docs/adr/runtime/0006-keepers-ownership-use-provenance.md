# 0006 她有一张主人表:归属、使用、出处三件事分开

- 状态:已接受,在落地
- 日期:2026-11-13
- 另见:runtime 0001(服务端 Agent)、runtime 0004(房主的库)、body 0008(出勤跟着主人在场走)、`docs/group-chat.md`、`docs/input-pipeline.md`、issue #136

## 背景

玩家想把自己的同伴分享给朋友用(issue #136)。0.1.5 起她的循环、记忆、模型档案和 key 都在服务端(runtime 0001),
"朋友的话要绕回主人的客户端"这个难点已经不存在,剩下的是一个字段的问题:名册里的 `owner` 同时回答着三个互不相干的问题。

| 问题 | 今天谁在问 |
|---|---|
| 她是谁的 | 技能、Lua 模块、接进来的 MCP 工具、权限规则本、"这东西算不算主人的"(`Whose`)、主动性偏好、数量上限、FTB 队伍、车万女仆的主人、YSM 同步、外部大脑的令牌 |
| 谁能用她 | 上行包的门(`OwnedBody`)、主人输入的门(`OwnerInputs`)、私信叫醒(`Whispers`)、在场与出勤(`OwnerPresence`、`Companions.reconcile`)、动态推给谁(`CompanionLoops.Link`)、征询问谁(`ConsentDesk`) |
| 她用的东西是谁的 | 模型档案、人设、声线从谁的库里解析,用谁的钥匙串,服主 key 的限额记在谁名下(`LlmMind`、`CompanionBinding`) |

三个问题的答案今天恰好是同一个人,所以一个字段够用。分享之后只有第一个问题的答案还是一个人。

## 心智模型

1. **归属:她属于创建者。** 一个人,不变。她读的技能、模块、规则本是创建者的;只有创建者能删除她、清空她的记忆、把她分享出去或收回。
2. **使用:她有一张主人表。** 表上的人都是她的主人:跟她说话、派活、答征询、看她的对话、改她的绑定。表上任何一位在场,她就该在线。创建者永远在表上。
3. **出处:每项绑定记着是谁绑的。** 用那个人的库解析,用那个人的钥匙串,账记在那个人名下。谁都只能绑自己看得到的条目(自己的"我的"与服务器提供的)。

叫法:界面上表上的人都叫"主人",创建者多一个"创建者"标记。代码里 `owner` 仍然只指创建者;表上的全体叫 `keepers`(创建者加 `sharedWith`)。

## 决定

### 归属

1. **`owner` 的含义收窄为"归属",值不变。** 背景表第一行列的那些全部照旧读创建者,一行不改。
2. **世界上的东西算谁的只认创建者。** 权限层的 `Whose`、放置记录、规则本不看主人表:分享是创建者单方面的动作,它不能让别人的箱子和房子变成"主人的"。
   被分享的人的东西对她仍是"别人的",该问的照问。
3. **外部大脑只驾驶自己名下的。** 令牌、驾驶席、`ServerActuator` 照旧按创建者;被分享的人用外部大脑驾驶她不在本稿。

### 主人表

4. **只存一处:名册条目 `CompanionRegistry.Entry.sharedWith`**(不含创建者),她休眠时也查得到。问"这个人用不用得了她",登出着的问 `Entry.usableBy`,
   在世界里的问身体(`NumenPlayer.usableBy`:创建者本来就记在身体上,分享给了谁现问名册);问"这个人用得了哪几只"只有 `CompanionRegistry.usableBy`。
   身体的 `.dat`、她的家里都不另存。
5. **改表的只有两种人。** 创建者加人、移人;被分享的人只能把自己移出去。创建者移不掉。可以加此刻不在线的玩家(按名字查到他的 UUID)。
   分享不需要对方确认——它只给对方权力,不花对方的东西;对方不想要就自己退出。
6. **改表是一处动作,后果在那一处收齐**:重算出勤、把新名册推给表上的每一位与少了她的那一位(名册的行带着整张主人表)、给她一条事件(多了哪位主人、少了哪位)、被移出的人绑的东西退回未绑定(第 16 条)。

### 使用

7. **门只问主人表。** `OwnedBody.of` 与 `OwnerInputs` 的"是不是你的"改问 `usableBy`。删除、清空记忆、改主人表另问归属。
8. **在场。** `Attendance` 的公式不变:该在线 = 名册里有她 且 主人在场 且 没被留在外面。"主人在场"改为表上任一位在场,仍只在 `OwnerPresence` 一处算。
   创建者的在场照旧三条腿(人在游戏里、外部大脑连着、渠道来访);被分享的人只算前后两条,外部大脑那条不算——他的外部大脑驾驶不了她(第 3 条),
   撑不起"此刻有人能驾驶她"。对账(`Companions.reconcile`)按人对他用得了的每一只;某位离开后表上已无人在场,才收拾她(作废在飞的回应、收掉程序)。
   "让她下线"任何一位主人都能下令,任何一位都能再召唤。
9. **说话。** 表上的人的话都叫醒她(面板、私信、切进会话的聊天)。循环记下每句话是谁说的:
   - 她不止一位主人时,`<query>` 的开标签上带说话的人(身份只有一种写法,`player@短码`,名字只附带);只有一位主人时不带——没人要区分,说了是噪音(与"就他俩时不写谁在场"同一个道理)。
   - 她的回话回给说话的那位(私信回私信、会话聊天回那个会话);面板上的动态表上在场的每一位都看得到。
   - 聊天流里每句主人的话标得出是谁说的,读的就是那个标记;没有标记的是创建者。
10. **会话仍然按人。** 每个人有自己的会话表(成员表加名字),成员只能是他用得了的同伴;"就他俩"是同一个视图,表上每一位看到的是同一份记录(含分享之前的)。
    她此刻在哪个会话里,在说话那位的会话表里解析(谁在场那一行、旁听转述、会话名)。别人的群会话盖的印,不在自己会话表里的不显示。
11. **眼前的主人。** 跟随的默认对象、说话时看向谁、`numen.status` 报的主人位置,都指"最后跟她说话、此刻在游戏里的那位主人";没有就是创建者。只在一处算。
    她的系统提示与感知里,表上的人都标成她的主人。
12. **动态推给谁。** `CompanionLoops.Link` 仍是"一位主人那一头";一只同伴登记的是表上各位的 Link 的组合(`KeeperLinks`,每位还是原来那个单人 Link)。`FeedEncoder` 不改。
    没装客户端的主人的动作栏是按人的(他用得了的各只合成一行),不经每只同伴的那一头,由 `CompanionLoops` 按在线的人算。
13. **征询。** 问在场的每一位主人,先答的算数,其余人的答复框撤回并写明是谁答了。"允许并记住"写进创建者的规则本——规则本只有一本(第 2 条)。
    规则本的行现在只记来源是主人还是她、和写的人说的理由,没有记"是哪一位加的"的地方;这一项等规则本的行有了位置再记。

### 出处

14. **绑定的值从"条目 id"变成"谁绑的 + 条目 id"**(`binding.json` 三项都是)。读到只有 id 的旧值,绑的人补成创建者,下一次落盘写成新形状。
15. **解析、钥匙、记账都跟着绑的人。** 模型档案在他看到的档案库里解析,key 先找他的钥匙串再找服主的,用了服主的 key 限额记在他名下;人设正文从他的人设库取。
    `LlmMind` 不再在建大脑时钉死一位主人。声线在客户端朗读:条目是服务器提供的,人人的客户端都解析得了;是某人"我的"里的,只有他的客户端念,别人看到名字和"是谁的"。
    皮肤不带出处:穿上的是签名缓存里的一份副本。
16. **绑的人不在表上了,他绑的那几项退回未绑定。** 在场的主人被告知少了哪几项、因为谁退出;"没绑档案"的停牌照旧显示。
    库条目改名、房主合并(`HostMerge`)时改指的范围,从"这位主人名下的同伴"改为"绑的人是他的那些绑定"。
17. **界面上每项绑定标来源。** 是自己的不标;别人的标"某某的",自己可以换成自己看得到的条目。状态里带上绑的人,客户端据此画。

### 入口

18. 命令:`/numen player share <同伴> <玩家>`、`/numen player unshare <同伴> <玩家>`(创建者);`/numen player leave <同伴>`(被分享的人退出)。
    面板:分享来的她带"来自某某"的标记;创建者的档案页管理主人表(加人、移人),被分享的人在那里只看得到表、页底是退出;
    非创建者看不到删除、清空记忆、分享。面板的加人、移人、退出是上行的 `OwnerInput.Share`、`OwnerInput.Unshare`,和命令落在同一处(`Sharing`),
    结局回的是同一句话。
    被分享的人面板上她的技能名单(斜杠命令的补全与 `/skills`)显示创建者的那一份(第 1 条):服务端另给他一张只读的表
    (库协议 `companion-skills`,只有名字与描述,正文不下行),他自己的技能库管不着她;设置页的技能、工具、权限三页顶上写明
    "由创建者 某某 管理"。模块在面板上没有名单。

## 后果

- 创建者不在线时,被分享的人上线就能把她带上线;她若绑着创建者的档案,花的是创建者的钱或他名下的限额。分享确认处写明这一点。
- 被分享的人看得到分享之前的对话与札记。分享确认处写明这一点。
- 权限层不防主人表上的人:他让她做的事,征询也是他(或另一位在场的主人)答。
- 名册下行推给客户端的行带着她的主人表(每位的 UUID 与名字,创建者在前);状态里的绑定多一项"谁绑的";主人的上行多"分享"与"不再分享"两种;`PROTOCOL` 加一。
- 数量上限仍按创建者算:分享来的不占被分享的人的名额。
- 不在本稿:被分享的人用外部大脑驾驶她;被分享的人改她的技能、模块、规则本。有人确实需要再议。
