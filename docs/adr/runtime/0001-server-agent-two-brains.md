# 0001 服务端 Agent:只有服务端大脑与外部大脑,配置与 key 归服主

## 背景

control 0011 把循环与记忆定到服务端,但留了三种大脑:主人客户端代调模型、服务端直调、外部大脑,默认是客户端代调,
不变量是"API key 不出主人的机器"。往下设计时三件事把它推翻了:

- 以后要出 Paper 端,那里只有原版客户端,客户端大脑与代调在那里不存在。
- 代调要把每一轮请求反向发给客户端、再把流式回复传回服务端,复杂、费网络;同类模组(VoxelMind、Player2/ChatClef 等)没人这样做,都是服务端或外部进程直接调模型。
- "key 不离开玩家的机器"外部大脑已经做到:key 留在玩家自己的 agent(Claude Code、Codex 一类)里,服务端只收发事件与程序。

## 决定

- **定位是服务端 Agent。** 服务端必装,客户端可选;客户端是装了更好用的前端(面板、语音、动效),玩家的交互不变。
- **只有两种大脑,同一时刻一个坐驾驶席**:服务端大脑(服务端跑 `AgentLoop`,用服主配置的 key)与外部大脑(循环停牌,外部 agent 经远程端点驾驶)。
  不做客户端大脑,也不做客户端代调。
- **配置与 key 归服主,都在服务端**:模型档案、models.dev 目录、语音服务的 key;客户端不存任何 key。
  单人游戏与自己开的服,服主就是主人。想在别人的服务器上用自己的 key,走外部大脑。
- **她的一切数据在服务端**:同伴的东西落世界存档,玩家的库按玩家存在服务器上;客户端只留展示偏好。
- **语音**:客户端只录音与播放,识别与合成在服务端用服主的 key 做。

## 后果

- control 0011 的"主人客户端代调为默认"与"key 不出主人机器"作废;后者改由外部大脑满足。
- 服主看得到她的对话与札记。不是存盘带来的(循环在服务端,每句话本来就经过服务端),做到的是说清楚、可撤回:进服授权卡写明、可导出、可清空。
- 客户端里的循环、档案库、人设库、各家语音实现都要搬到服务端;搬迁分步见设计稿 §十二。
