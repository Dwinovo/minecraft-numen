# 0008 大脑在主人的客户端,身体在服务端:两端之间只有一个座位,说 JSON-RPC

- 状态:已接受,在落地
- 日期:2026-11-25
- 修订:[0001](0001-server-agent-two-brains.md)(服务端 Agent、配置与 key 归服主)、[control 0011](../control/0011-brain-on-server.md)
  (循环、记忆与外接大脑放服务端);回到 [control 0010](../control/0010-programs-run-on-server.md) 的"客户端想,服务端做"
- 另见:[0003](0003-network-off-main-thread.md)(只走 MC 的连接)、body 0008(没人能驾驶就登出)、[0006](0006-keepers-ownership-use-provenance.md)(主人表)

## 背景

10 月把循环、记忆、key 与外接大脑的入口都搬到了服务端(0001、control 0011),最硬的一条理由是要出 Paper 端,那里只有原版客户端。
Paper 已经移除(0007)。剩下的理由在单人游戏里不存在(服务端就跑在主人电脑上),只在专用服上有区别,而专用服正是代价最大的地方:

- 玩家要么把自己的 key 交给服主,要么服主替所有人出钱;
- 玩家本机的 Ollama、MCP 工具服务器、Claude Code 一类的外接大脑,服务器都够不着,外接大脑要服主开端口;
- 换一台服务器她就不认识你了。

用户:

> 我很确定,以后就是定下来了,客户端跑 agentloop,服务端负责假人的执行,配置什么的也最好统一在客户端一下,聊天记录什么的。

主人下线她还接着想、服主给全服提供模型、把她借给别人,用户定为"等服务器来找我定制的时候做"。

同类模组(车万女仆、VoxelMind、CreatureChat 等)都把大脑放服务端:它们是聊天机器人,key 由服主统一配。没有一家做"大脑在主人客户端、身体是服务端的假人"。
跳出 Minecraft,这是主流的分法:MCP 的主机与服务器、Codex 的 harness 与 exec-server(循环在一边,执行环境在远处,中间 JSON-RPC)、
机器人的上位机与本体(目标、进度、结果、取消,失联就安全停下)、网络游戏的权威服务器。

## 决定

心智模型:**她的脑子和记忆在主人电脑上,她的身体在服务器上。脑子想好了,写一段程序发过去;身体做完,回一份回执。**
判据只有一条:**服务端要用的放服务端,只有脑子用的放客户端。**

1. **两端各管什么。**

   | 主人客户端(脑子) | 服务端(身体) |
   |---|---|
   | 循环、收件箱、调模型 | 身体、背包、装备,跑程序 |
   | key、模型档案、人设、她用的 MCP 工具、语音 | 主人表(谁是她的主人) |
   | 主动性、定时 | 权限设置(八个档位与名单)、征询卡 |
   | 上下文:聊天记录、摘要、札记、目标 | 她穿的皮肤(大家都要看到) |
   | 她的 Lua 模块、她自己的技能 | 内置模块、插件登记的函数、技能与提示片段 |
   | 外接大脑的入口(开在主人本机) | 世界上的事:她挨打了、有人跟她说话 |

   权限设置、主人表、皮肤留在服务端,主人仍在客户端的界面上改,改完发给服务端。
2. **两端之间只有一个座位。** 服务端对每只同伴开一个座位,只认她的创建者的客户端来坐。客户端里的循环坐这个位子;外接大脑连主人本机,
   经同一个客户端、同一个座位开她。服务端不知道、也不关心来开的是内置的循环还是外接大脑——谁在驾驶由客户端一处定。
3. **座位说 JSON-RPC,走 MC 的连接。** 请求、答复、通知三种消息,编号配对、超时、撤回、断线时"答复不会来了"都由 `mcp` 模块现成的
   JSON-RPC 一端(`RpcPeer`)管;装进一种 MC 自定义包,超长的分片。不开自己的端口:进服、断开、认人都跟着 MC 的连接。
   单人游戏两端在同一个进程,包只在内存里转一手。界面上的事(召唤、换皮肤、显示征询卡、切游戏模式)不是脑子在说话,照旧用各自的 MC 包。
4. **座位上的方法**(名字定稿以代码为准):

   | 方向 | 方法 | 干什么 |
   |---|---|---|
   | 客户端 → 服务端 | `seat/open` | 坐上她的座位;答复带她此刻的代数、目录版本、服务端记得的最后一个序号 |
   | | `catalog/get` | 她能做什么:函数与说明、插件与内置的技能、提示片段、本能名册、命令索引 |
   | | `program/run` | 跑一段程序;答复就是结构化的结局(回执、结束方式、每次调用的结局、用到的模块) |
   | | `program/interrupt`、`program/cut`、`body/stop` | 叫程序停在调用之间、当场切断、叫停身体上的活 |
   | | `state/get` | 她此刻的样子(`<runtime_state>`) |
   | | `say` | 她要说的话,由服务端在聊天里说出来 |
   | | `events/ack` | 收到第几号了 |
   | 服务端 → 客户端 | `events/new`(通知) | 世界上的事、别人对她说的话;带序号、代数、她此刻的样子 |
   | | `catalog/changed`(通知) | 目录变了(插件、`/reload`),再取一次 |
   | | `modules/get`(请求) | 程序用到的她的模块,服务端按内容哈希缓存,缺哪份要哪份 |
   | | `client/call`(请求) | 程序里只有主人客户端答得了的函数,取代现在的反向调用包 |
5. **她此刻的样子跟着消息走。** 服务端发的每条事件和每份结局都带上她此刻的样子与游戏刻;脑子由主人开口这类本机的事开一轮时,先 `state/get`。
   样子只在服务端读身体时写成,不按刻推。
6. **序号与续传。** 服务端发给座位的事件每条一个递增序号,留到客户端确认收到。断线重连 `seat/open` 带上最后收到的序号,从下一号补。
7. **代数。** 她的身体每进一次世界(召唤、重生、回来),代数加一。事件带着代数;`program/run` 带上脑子以为的代数,对不上直接退回
   "她已经不是那个身体了",不去猜包谁先谁后。
8. **急件。** 世界上的事急不急,两端用同一份规则(`EventQueue` 的急件规则,在 `agent` 模块):程序在服务端等身体收尾时来了急件,
   服务端自己让它停在调用之间;主人开口、按停止是客户端的事,发 `program/interrupt`、`program/cut`、`body/stop`。
9. **断线。** 主人的客户端断开,身体照 body 0008 登出;在跑的程序当场切断,它的结局留着,重连时随续传补上。服务端不替主人想事。
10. **别人的话。** 群聊、私聊、共享主人说的话都先到服务端,作为事件送到她的座位,也就是创建者的客户端。共享主人能和她说话、能看她,
    但她的脑子只跑在创建者那台电脑上,只有一份记忆。
11. **删掉的**:服务端的循环与它的接线、服务器上的钥匙串与每日额度、库协议里属于大脑的那些种类、"服务器提供"的库、服务器上的外接大脑
    HTTP 入口与令牌(搬到主人客户端)、只为"大脑在服务端"存在的兼容与迁移代码。

## 后果

- 专用服上玩家用自己的 key、本机的模型与工具;服主看不到她的对话与札记,也不再替谁出模型的钱。
- 模型边想边出的字不再经服务器转发,线上只剩程序、回执和事件。
- 外接大脑连主人本机(`127.0.0.1`),服务器不用开端口;QQ、弹幕这类渠道桥要连到主人电脑上的入口。
- 主人下线她就停;共享主人不能在创建者不在时单独用她。
- 配置与记忆不跟着人换电脑;存档拷给别人,身体过去了,她不记得以前的事。
- 内置大脑与外接大脑经同一个座位开她,服务端只写一份、测一份。

## 没有定的

- 单人存档里现有的记忆(世界存档 `numen/companions/<UUID>/`)要不要搬到客户端,等用户定;默认不搬。
- 记忆放进物品、交给别人接着用:用户说先不考虑,想好产品形态再说。

## 修订(2026-11-25,里程碑 2 的计划读过代码之后)

- **她此刻的样子只跟着结局走,每一轮开头取一次。** 事件只带时间(真实时间、游戏刻、游戏里的时刻),不再带样子:一轮开头 `state/get`
  一次,这一轮里每份程序结局带着那一刻的样子。开头现取比沿用攒着的事件里的那份新,服务端也不用为每条事件渲染一遍。样子由服务端
  一处写成,含她手上那件活(`<current_task>` 要的那份),客户端不拼身体上的东西。
- **身体的变化也是事件。** 死了、重生、被请出服务器、登出与回来,服务端经 `NumenEvents` 发成事件送到座位;客户端的循环按事件种类
  在一处决定停牌与解开,不另开一条"身体变了"的通道。
- **她的模块与技能的原文**:`program/run` 带上这段程序用到的她的模块清单(名字与内容哈希),服务端缺哪份经 `modules/get` 要;
  内置模块与插件技能的原文由客户端按需取(`modules/builtin`、`skill/read`),不塞进目录。
- **她在世界里待不待着,看创建者的座位有没有人坐。** 共享主人在线、创建者不在,她照 body 0008 登出。

## 分步

一条分支 `brain-to-client` 做完再合回 `1.21.1`,中间不合,免得出现两份大脑。分里程碑提交,每个里程碑审一次:

1. **座位**:JSON-RPC 装进 MC 包(分片)、服务端的座位与它的方法、客户端的座位一端、序号续传、代数;回环传输上的单测。
2. **大脑搬家**:循环、收件箱、上下文、配置、key、她的模块与技能到客户端;系统提示由客户端用目录与人设拼。
3. **外接大脑入口到客户端**:端点、令牌、渠道桥搬到主人客户端,经座位开她;谁在驾驶在客户端一处定。
4. **别人的话与杂项**:群聊、私聊、共享主人、定时、插件听大脑(run 的开收由客户端报回服务端再派给插件)。
5. **删掉与修宪**:服务端的大脑与只为它存在的协议、钥匙串、额度、兼容代码;`docs/architecture-mind-model.md`、`docs/agent-loop.md`、
   `docs/input-pipeline.md` 改成现状;全套测试。
