# 0004 房主的“我的”就是服务器目录

- 状态:已接受,已落地
- 日期:2026-10-21
- 另见:`docs/input-pipeline.md` §六"库:服务器提供与我的"

## 背景

内容库(人设、模型档案、技能、声线、接进来的 MCP 服务器)原来都分两组:**内置**是服务器目录里的,管理员能改,还混着 jar 自带的默认内容;
**我的**是每位玩家自己一份目录。单人游戏里房主既是管理员又是唯一的玩家,界面上却摆着两节、磁盘上放着两份,想放一条东西要先想放哪边;
钥匙串同样有"服主的 / 玩家自己的"两本。

## 决定

规则只有一句:**房主自己这台机器上的库,对房主是"我的",对别人是"服务器提供"。**

- 单人游戏:只有"我的"一节。房主就是这台服务器,他的"我的"就是服务器目录那一份,不另有玩家目录——两份合成一份,不是两份拼着显示。
- 专用服务器:玩家看到"我的"(他自己的目录)与"服务器提供"(服务器目录,管理员能改)。
- 局域网开房:房主同单人游戏;来串门的玩家把服务器目录看作"服务器提供"。
- jar 自带的条目照旧落在服务器目录,界面上带一个"自带"小标记,"有新版 / 恢复默认"照旧。所以它们在单人游戏里出现在"我的"里,在专用服务器上出现在"服务器提供"里。
- 界面文案"内置"统一改叫"服务器提供"。钥匙串照同一规则:房主的个人钥匙就是服务器那一本。
- "是不是房主"只在一处判:`Homes.isHost`(集成服务器的房主本人)。各库、钥匙串、皮肤都问它,不各判一次。
- 例外只有一个:Lua 模块是她自己写的东西,房主的也不进服务器目录,否则串门的玩家会把它当成随模组发布的出厂模块(`LibraryKind.apart()`)。
- 已有数据迁移(`HostMerge`):房主个人目录里的库条目并进服务器目录,同名而内容不同的按"我的优先"改名并告诉他,他名下同伴的绑定跟着改指;钥匙同服务两边都有而不同,他的留下。
  可重来:一条一条整个移过去,移完就没有可搬的。

## 后果

- `Library` 多一种状态 `merged()`(`mine()` 与 `server()` 是同一个货架);条目的 `group` 说它住在哪一处,界面上叫什么由读它的一方按 `merged()` 定。
- 线上"组"从 `builtin` 改叫 `server`,行里多一个 `shipped`;`HelloAck` 多一位 `host`;`PROTOCOL` 加到 4。
- 串门的玩家看得到房主放进服务器目录的所有东西(含他"我的"里的人设)——这是规则本身的意思,不是漏。
