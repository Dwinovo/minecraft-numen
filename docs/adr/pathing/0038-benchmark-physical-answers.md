# 0038 评测:起终点不碰排除格,标准答案改物理口径,数据集 v3 加 GRAV3D 层

- 状态:已接受;改 [0031](0031-planning-benchmark.md) 里"出题挑起终点"与"标准答案"两处(次优比的算法、答案的口径)
- 日期:2026-11-01

## 背景

查 v2 的 nether 题时发现 v2 里 120 道里有 64 道起点、21 道终点的脚格是岩浆。原因在出题:`Generate` 挑起终点只问 `Stance.at != null`(身体待得住),
`Stance` 只看碰撞几何——岩浆没有碰撞箱,岩浆湖底的实心托得住脚,所以那一格"站得住"。岩浆、火、粉雪这些危险是在代价与准入层处理的
(`RouteSpec.excluded`、`Contact.admit`),不在节点层,所以搜索认为从岩浆里出发有路,v2 的答案对这些题也是"最优"。这样的题不合法:题的起终点
不该落在路线规格自己排除的格子里。

另一个问题是标准答案的口径:v2 的最优价按出厂规格的成本模型算(含放、挖、起跳、涉水的罚分,挨着伤身格走的加价,挖掘遮挡的加价),
次优比 = 路线价 ÷ 最优价。调罚分、权重就要重算整个数据集(慢,约 9.5 小时),答案也不是任何公共意义上的最优。

## 决定

1. **起终点不碰排除格**(`Generate.clean`):起点、终点(含洞穴、空腔的地面)要求身体待得住,而且脚到头占的格与脚踩的那一格都不是
   `RouteSpec.defaults().excludes` 认的种类(岩浆、危险方块、流水、机关、易碎);封闭在实心里的一格同样不能是这些种类。判据是搜索准入同一个
   (`Spec.excludes` 就是 `RouteSpec.excludes`),没有另写名单。粉雪属于危险方块:不穿皮靴的身体会陷进去。
2. **中立地形的"禁入"类别取同一个判据**(`Neutral`):方块状态里只看状态就定得了的排除种类(岩浆、危险、机关、易碎)加流动的水、气泡柱,
   所以出题与 GRAV3D 对"禁入"是什么看法一致。
3. **标准答案改物理口径**(`Spec.physicalRoute`、`Spec.physicalModel`、`Physical`):出题与重算答案用同一份规格,放、挖、起跳、涉水四项罚分与
   挨着伤身格走的加价(`RouteSpec.exposurePenalty`,从 `ActionCosts` 挪进规格,否则清不了零)全为 0,挖一格时隔着硬遮挡的加价
   (`Goals.dig` 的 `arrival`,目标侧的偏好)在 `Physical` 目标里清零,代价只剩物理刻数;答案另记路线挖、放了几块。答案文件标"Numen 物理模型
   `numen-physical-1` 的参考值",不称真最优(0036 的状态抽象有混叠,最优只相对 Numen 的状态)。"有定论才收"的判据与两档上限、内存预算排程照旧,用的是这一层。
4. **评测的次优比**改为路线的物理刻数(`Course.minimumAt` 之和)÷ 物理最优价,与罚分、权重无关:以后调罚分、权重都不必动数据集。
   出厂规格下的搜索与路线本身不变(与改动前逐行相同,只有次优比一列因口径而变)。
5. **数据集 v3 加 GRAV3D 层**(`benchmark/Export`、`benchmark/Neutral`,规则与验证器在数据集仓库):每块地导成每格一个字节的中立类别网格,
   规则 `grav3d-1.0` 写成文档,独立写的参考求解器给 A、E 两个赛道的最优价与参考路径,独立写的验证器逐条验证。GRAV3D 只求解,不参与收题。
   v2 的题集因 (1) 不再合法,v3 重出全部 840 题(同种子、同流程),题号与 v2 不能混用。

## 后果

- v3 的 Numen 层答案与 GRAV3D 层答案是两套:前者是 Numen 的搜索按纯物理耗时算的参考值,后者是公共规则下可独立验证的最优。
- 数据集不再随罚分变。只有走法、物理模型或口径变了才重出(换 `Spec.PHYSICAL_MODEL` 的序号)。
- 评测的基线要用 v3 重跑,v2 的基线与 v3 不可比。
