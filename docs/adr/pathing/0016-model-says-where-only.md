# 0016 给模型的寻路只说去哪,许不许归权限层

- 状态:已接受;取代 0008 与 0009 里给模型的旋钮
- 日期:2026-10-11(0.1.5 第 7 步,与用户定)
- 提交:`ff3c619fe`

## 背景

真机里主人开观察模式钻进地下叫她,她试了五次都失败。拦住她的不是权限层(出厂行放行挖自然方块),而是 `costs` 默认不许改地形,
许了以后 `move.go` 又守"只改计划里列出的格",而计划只看清一截,剩下要挖的格必然不在计划里。"能不能动这一格"在工具、计划、权限层三处判,
前两处是工具里的"我可以吗",违反"改世界的动作只由权限层决定"。

## 决定

参照 mineflayer-pathfinder(每次只给 Goal,走法是整只机器人的配置,默认可挖)与 Mindcraft(`goToPosition(x,y,z,min_distance)`):
- 给模型的只剩 `numen.move.to(目标, 距离?)`、`move.away`、`move.follow`、`use.dismount`;删 `numen.route` 整组、`move.go`、计划对象与全部旋钮。
- 可挖可搭,只看价钱:能走就不挖,绕太远才挖。禁止的格是墙,要问的格加价、走到跟前才问,拒了那一格在这一趟里当墙重新规划。
- 动手的工具够不着先自己走过去;回执照实交代这一路(停在哪、差多远、挖放几格、问过什么、被拒了什么)。物理安全(不挖脚下、沙砾、放出流体、摔落按血量)留在寻路。

## 后果

- 观察模式下权限层拒一切改动,她自然只走。
- 默认可挖后,往下的估价只能按"可能有洞"取下界,地面每个节点都长出往下挖的分支:`basin_descent` 没走到、`hill_detour` 1586 刻(基线 677)。
  试过的半程挑法(纯 f 最小、focal ε 0.01~2.0)都不行,根因归估价(0017)。
