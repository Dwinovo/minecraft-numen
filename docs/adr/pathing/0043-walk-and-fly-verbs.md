# 0043 走与飞分成两个动词:move.walk 只走,move.fly 只飞,飞的条件照参考项目

- 状态:已接受(取代 [0042](0042-flight-and-gliding.md) 的"一、接口"与"五、鞘翅"里"用不用、起飞点、巡航高度、交账"几条;0042 的身体层、步进器、颈部、`Pilot`、`Airway`、迫降与盘旋照旧)
- 日期:11-03(与用户定)
- 相关:[0042](0042-flight-and-gliding.md)、[0016](0016-model-says-where-only.md)、`D:\01_Projects\flight-research\REPORT.md` 与 `REPORT-feel.md`

## 背景

0042 把飞并进 `move.to`,用不用按价钱。11-03 真机两局:

- 模型不知道 `move.to` 会飞,主人得告诉它"寻路会帮你飞";
- 十趟远途里飞成两趟。没飞的都是我们自己的几何门槛:起飞点按远近只试 6 个(就是脚边一圈),每个都要朝目标 45° 爬升、两侧各 2 格的通道;
  航线是"爬升 → 巡航 → 按滑翔比 9 直线下滑到降落点",巡航一高下滑就放不进水平距离,中距离遇山就"任何高度都过不去";
  计划查通道的起点比交给飞行的线高 1.3 格,起飞即"前方有东西挡着"迫降;一趟只在出发时问一次要不要飞,失败一次剩下全走;降落点会选在水底。
- 这些都比参考项目死:MovementSync 在附近找一根宽口径通天的空柱走过去起飞,沿线每 16 格扫最高碰撞面 +16 定巡航高度,落地另成一段(进近、触地速度);
  Baritone 升到障碍上方直飞,烟花少于 5 支或耐久低于 5 点就降;Lambda 撞障碍改步行绕过再接着飞;Baritone 寻路时关创造飞行。

用户定:走与飞分开,名字 `move.walk` 与 `move.fly`;创造飞行只归 `fly`;`away`、`follow` 只走。

## 决定

### 一、接口

- `numen.move.to` 改名 `numen.move.walk`(破坏性,一次改完:内置模块、技能、例子、提醒文字、回执、评测场景、测试、文档、插件里的调用全改,不留别名)。
  它只走、游、挖、搭,**从不飞**:创造许飞时也不排飞行走法、不排滑翔段(Baritone 的做法)。开始时身体在飞:先降到地面(原版落地停飞),回执里说。
- 新 `numen.move.fly(where, distance)`:同样的 `Where` 与到达语义。只飞:
  - 许飞(创造):创造飞行进 A*(0042 第四节的飞行走法;走法集仍由身体给),到点悬停或落地;
  - 否则穿着可用鞘翅:滑翔(下面第二节);
  - 两样都没有,或鞘翅模式下没烟花也没有能滑下去的边沿:受理时当场拒绝,说缺什么、怎么补(`gear.wear`、带烟花、或 `move.walk`)。
- 飞不再和走路比价钱:模型叫飞就飞。`move.walk` 也不比:叫走就走。
- `move.away`、`move.follow` 只走,同 `walk`。`use.glide` 留作手动。
- 回执类型仍是一份(`Walked`,说明里叫 trip),两个动词共用;`status.self` 的 `flying`、`gliding` 照旧。

### 二、`move.fly` 的鞘翅:照参考项目

一趟 `fly` 是:走到起飞点 → 起飞 → 巡航 → 进近降落 → 走完最后一截;飞不下去就落地收工,不悄悄改成长途步行。

1. **起飞点**(MovementSync):在身体附近找"头顶开阔"的起飞点——检查用整条模拟爬升轨迹的扫掠(REPORT-feel 的建议),不是固定 45° 朝目标的通道;
   候选在附近铺开(不是按远近只取脚边几格),按走过去的路程从近到远试,走路的段走过去。也可以从边沿走出去展开(Baritone)。
   起飞点的搜索范围和试的个数是算力预算,写明是预算。附近一处都没有:当场失败,说"附近 N 格内没有头顶开阔的地方",给出下一步(`move.walk` 到开阔处再飞)。
2. **起飞**(REPORT-feel 第四节):起跳上升段里用颈部把头抬到爬升俯仰,下落段按跳展开,滑翔确认后的下一刻放第一支烟花;俯仰陡抬但不到垂直,由推演按净空选,
   到了安全高度再转向目标。**计划检查的爬升线就是交给飞行的那条线**,只算一次、两处共用。
3. **巡航高度**(MovementSync):沿起飞点到目标的直线,每 16 格取一处、看那一列最高的碰撞面,巡航高度取其中最高的再加 16;没加载的那段照 0042 边飞边看,
   新加载的那段更高就抬高(`Glide.raise`)。不再要求"爬升 + 直线下滑放得进水平距离"。
4. **进近与降落**:飞到目标上空附近再下降,高就盘旋下沉(0042 已有的 `approachCorners`),触地速度照 0042。降落点要站得住、**不在液体里**
   (目标在水里时落最近的岸);找不到才盘旋再找,时限照 0042。
5. **烟花与耐久**(Baritone):不要求起飞前备够全程。飞着时烟花少于 5 支、或鞘翅耐久低于 5 点,就近降落(先朝目标方向找);起飞时就不够这个数,当场拒绝并说要几支、有几支。
6. **中途落地之后**:离目标还远、烟花耐久仍够,就从此刻的位置再起飞(Lambda、MovementSync 的做法);同一个起飞点失败过的,这一趟不再用。不够了就收工,回执说飞到了哪、为什么停、离目标多远。
7. 迫降、盘旋、撞墙否决、颈部与 `Pilot` 照 0042;迫降的日志写明挡路的那一格。

### 三、交账

- `fly` 的回执:每段滑翔一条(0042 的 `Gliding`)、走了几格、为什么停(到了、烟花或耐久到了下限、附近没有起飞处、被挡且降不下去)、离目标还有多远。
- `walk` 的回执不再有"为什么没飞"(`EditLedger.Grounded` 与 `NavText.grounded` 删掉:走就是走)。
- 工具说明照 Anthropic 的工具说明指导写:做什么、什么时候用哪个、参数、局限;术语全篇一致(walk、fly、glide、trip)。

## 验证

- 步行评测(`pathingBenchDiff`)对 `walk` 逐字节不变;两平台 GameTest、单测全过。
- GameTest(按入口从 `numen.move.fly` / `numen.move.walk` 调):树林边起飞、中距离翻山、第一次滑翔中途落地后再起飞、目标在水边不落水、
  烟花不够下限当场拒绝、没鞘翅当场拒绝、创造下 `walk` 不飞而 `fly` 飞、在飞时 `walk` 先落地。
