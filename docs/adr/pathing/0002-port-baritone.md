# 0002 照 Baritone 一比一移植到服务端

- 状态:被 [0004](0004-engine-v2-learning-table.md) 取代
- 日期:2026-06-13
- 提交:`4892fea3f` … `4e7bc1df8`(六步)、`7ecf74294`

## 背景

身体换成假玩家之后([身体 0001](../body/0001-server-side-player.md)),要预测的就是玩家的物理。自己写的第一版(0001)常数是估的,执行常对不上。
Baritone 是 Minecraft 里最成熟的寻路,走法、代价、执行经过多年真实世界的检验;但它是客户端模组,读的是客户端的世界。

## 决定

把 Baritone 一比一搬到服务端,接在假玩家身上:代价常数照它的物理(平走 4.633、疾跑 3.564、水里 9.091 刻一格,逐刻积分的坠落表)、
估价 3.563 加七档系数挑半程(`COEFFICIENTS`)、执行阈值、每种走法的 `updateState`、分段预搜下一段、执行时逐刻重算代价。
之后照着补开门、`MineProcess`、`ToolSet`、水里浮起。

## 后果

- 当天的提交写着"Pathing is now a complete 1:1 Baritone port"。
- 远路暴露问题:挖隧道每步 46~300 刻,七档系数里没有一档认得出这种"贵但真实"的进展,真机从 y=−42 往上逃,搜了一万个节点记下 0 格进展,报"没有路"(`92808741f`)。
  这促成了 0004。
- Baritone 的走法只在规划时粗判、执行时重算做什么,规划与执行可以不一致;这个分歧到 0011 才正面处理。
