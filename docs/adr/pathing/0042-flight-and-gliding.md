# 0042 飞行:创造飞行与鞘翅进同一趟行程,用不用由身上已有的能力加价钱定

- 状态:已接受(分批落地:第 1、2 批 11-02 已合入;飞行控制器按真机修订与第 3 批鞘翅 11-02 在 worktree 里落地,待合)
- 日期:11-02(与用户定)
- 相关:[0016](0016-model-says-where-only.md)(模型只说去哪)、[0014](0014-kinematics-and-gait.md)(运动学与步态)、[0012](0012-plan-subset-of-execution.md)(规划是执行的子集)、
  [0028](0028-execution-lookahead.md)(执行往前核)、issue #154

## 背景

- 创造模式下她从不飞:原版"双击跳起飞、按跳升、按潜行降、落地停飞"在客户端 `LocalPlayer.aiStep`,我们的 `Controls` 没补这几段。
  鞘翅只有原子动作 `numen.use.glide`(空中展开)与 `numen.use.item`(放烟花),寻路不会用。
- 寻路只有步行一种身体:走法集是全局常量 `Moves.ALL`。船走另一套平面规划 `BoatNav`,骑其它载具时 `move.to` 当场拒绝。
- 两份调研(本机 `D:\01_Projects\flight-research\REPORT.md` 与 11-02 接口调研):
  - 鞘翅做得像样的都是两层:上层定走廊或巡航高度,下层用一份原版物理把几组候选输入往前推演若干刻、挑最好的;没人在方块格上给鞘翅跑 A*
    (转弯半径大、停不下来,状态里必须有速度)。执行合法(只用视角、跳、右键烟花)的只有 Baritone 与 MovementSync,其余改速度、坐标、计时器。
  - 创造飞行可以进格子搜索(原版飞行生物、Wurst:身体在飞时多出空中邻接),但水平惯性大(松键滑约 5 格,疾飞约翻倍,按原版公式推算),要算刹车。
  - 给 LLM 的移动接口(Mindcraft、Voyager)按目标分动词,没有按移动方式分的;按方式分命令的(Baritone `#goto`/`#elytra`)是给看得见地形的人用的。
    Anthropic 与 OpenAI 的工具设计指导都要求合并意图相同的工具,重叠的工具最容易选错。机器人(Nav2)、游戏(Unreal `MoveTo`)、地图 API 都是一个
    "去目标"的接口,方式由规划器按代价或由智能体自身属性定。

## 决定

### 一、接口:不加动词,能力由身体给,用不用由价钱定

- `numen.move.to`、`away`、`follow` 签名不变,不加 `move.fly`,也不加"限制方式"的参数(0016:模型只说去哪,怎么走归寻路)。
- 这一趟能用哪些移动方式,只看她**此刻身上已有的**能力,判据只写在一处(宿主抄身体快照时):
  - 走、游、挖、搭:一直有,照旧;
  - 创造飞行:她此刻许飞(`abilities.mayfly`);
  - 鞘翅:胸甲位是没坏的滑翔物(1.21.1 是鞘翅;1.21.2 起看滑翔组件,移植时只改这一个判据);有动力要背包里有烟花,没有就只算从高处往下滑;
  - 载具:不在本 ADR,照旧(船走 `BoatNav`,其余拒绝并指向 `use.dismount()`),见"以后"。
- 寻路**从不**替她穿脱装备、上下坐骑、从箱子里取烟花——那是模型的决定,经现有原子动作 `gear.wear`、`use.entity`、`use.dismount` 做。
  模型不想这一趟飞,把鞘翅换下来就是。`use.glide`、`use.item` 留作手动控制。
- 走还是飞全按价钱,不写死距离阈值。烟花与鞘翅耐久的余量是物理安全,留在寻路:不够余量不起飞,飞着不够了就降落,都照实报告。
- 跟随、远离走同一趟行程,主人飞着走时她有能力就跟着飞。

### 二、身体层(Numen API):补齐原版客户端的那几段输入

`Controls.apply` 补 `LocalPlayer.aiStep` 里还没补的,全部是玩家按得出的键,判定仍归原版服务端:

- 双击跳(原版 7 刻窗口)切换创造飞行:经她的假客户端发能力包,服务端照原版判 `mayfly`;起飞时照原版起跳一次;
- 飞行中按跳上升、按潜行下降(原版每刻 ±3 × `flyingSpeed`);落地即停飞(原版客户端的规则);
- 空中按一下跳(按下沿)展开鞘翅,条件照原版 1.21.1 `tryToStartFallFlying`,不另加"须在下落段";滑翔状态只由服务端落地时清。
  `numen.use.glide` 改走这同一条路,不留第二份展开逻辑;
- 放烟花是右键,走现有 `Mouse`/`Hotbar`,换手照常交回 `BodyAction`。

### 三、物理只有一份:飞行与滑翔的步进器

- `world/Kinematics` 加一个纯函数的逐刻步进:输入(前后左右、跳、潜行、疾跑、视角、这一刻放不放烟花)与状态(位置、速度、在飞/在滑翔)进,下一刻状态出。
  公式只照原版 1.21.1 源码(`LivingEntity.travel` 的滑翔分支、`Player.travel` 的飞行分支、`FireworkRocketEntity` 的推力),不照任何参考项目的代码。
- 规划的代价、局部控制器的推演、执行看护的期限,读的都是它(0014 的同一份运动学),不另写常数。
- 测试:单测对着原版公式逐项;GameTest 让真身体按同一串输入飞,逐刻对照步进器的预测,误差上限写在测试里。

### 四、创造飞行进同一个 A*

- 身体快照(`BodySnapshot`)带上移动方式的事实(许不许飞、此刻在不在飞);一趟的走法集由身体给,取代全局 `Moves.ALL`,步行时与现在逐字节相同。
- 新走法:起飞(地面到空中)、空中移动(六向加水平斜向,前提是身体放得下、扫过的路线通)、降落(空中到落脚)。节点键不加"在飞"位:
  一格要么站得住(站、攀、浮),要么只有飞着才待得住(站姿 `FLYING`),同一格只有一种待法;代价是不贴地一格飞。
- 加权 A*(权重 4)下,走得通的近处常交出步行路线,飞行多在走不通处(峡谷、半空、高墙)选上;交出的路线不超过最优的权重倍,按 0023 的取舍先收,
  真机看远距离再定。
  空中一步的代价来自步进器的稳速;起落与转弯处的刹车按步进器算进段的耗时(同 `Gait` 处理疾跑的方式),往前核与看护照常。
- 估价:有飞行时水平底价取飞行与疾跑里更快的那个,竖直项按飞行升降的下界,仍须是下界;`EstimateAdmissibilityTest`、`EstimateConsistencyTest` 按每种身体各跑一遍。
- 执行:`drive/` 加飞行的控制器,只按键、只看方向;到点悬停算到(创造下目标是半空的一格时,停在那里)。
- 执行修订(11-02 真机):第 2 批的控制器竖直目标逐格取(下一格的高度),水平与竖直各管各的。真机上直升 44 格用了 325 刻
  (0.135 格/刻,原版按住跳的稳速约 0.375),每格都刹一次;水平先冲过、竖直没跟上,一趟里两次 `LOST` 重搜。落地的做法:
  - 一段连着的飞行(起飞、飞、降落)当一整条折线跟(`Airway`):拉直之后跟,拉直同时过扫掠净空和路线规格(`Flight.refused`,复用规划的 `Contact.admit`);
    身体在折线上的弧长就是进度,每一步的落点投到折线上,一刻跨过几格照常算走过,不要求逐格进格;
  - 局部控制器 `Pilot` 与介质无关:候选宏动作(每组按 3 刻)× 往前推演(步进器 `Kinematics.fly`,颈部 `Neck` 一起算)× 打分。硬约束先过——撞方块整组不要,
    滑出去会撞的试刹车一程;再看软代价——沿折线前进、离折线、收处停不停得住、换键。换键有代价,至少按满 3 刻,推刹承诺锁存;
  - 视角是身体层的颈部模型(闭环二阶跟踪,限角速度与角加速度,两轴同时到位,推演里复制同一个值),取代"瞬间转到"。步行的转头不动(步行评测逐字节不变);
  - 与报告的差别:候选里没有"左右小偏移的偏航"和"上一刻方案平移一刻"(按满 3 刻的锁存已经是热启动);惩罚不是严格字典序,硬约束用负无穷、软代价相加;
    纯追踪的前瞻距离随速度变(3 格加 6 倍水平速度),没有单独的横向速度纠偏项——推演打分里滑停的终点已经包含了横向速度的后果。
  - 验收(`FlightGameTests`):直升 40 格 113 刻(理想 114)、平飞 64 格过沟落地 99 刻(理想 98)、斜着爬升 24 格 88 刻(理想 73);上限写在测试里:理想耗时的 1.3 倍加 25 刻。
    计划代价(每步按稳态速度)与实际对得上,没有改代价。

### 五、鞘翅:行程里的一段,两层

鞘翅不进格子搜索。一趟行程(`Trip`)由若干段组成,每段一种移动方式,共用一本账、同一套重规划原因与日志。滑翔段:

1. **用不用**:身体有可用鞘翅、烟花按估计够用(含余量)、且"走到起飞点 + 飞 + 降落后走到目标"的估计耗时低于步行的下界时才排滑翔段;否则全程走。
2. **起飞**:就近找头顶开阔、助跑跳得起来的起飞点,用步行段走过去;跳起、下落段展开、放烟花爬升。
3. **巡航高度**:沿起点到目标的直线,按快照与已加载区块的高度图取沿途最高碰撞面再加余量;没加载的区块是"未知",不是空气,按保守高度处理
   (远距离未加载区块的完整处理不在这一批,见"以后")。
4. **局部控制器**:每隔几刻,对一组候选输入(偏航 × 俯仰 × 放不放烟花)用步进器往前推演一段,打分挑一组执行;推演撞上方块、扫过危险格、进未加载区块的一律否决;
   分数看前进、离巡航高度与目标的偏差、烟花消耗。候选的组数、推演长度、权重由我们自己的 GameTest 定,不照搬参考项目的常数。
5. **降落**:接近目标时就近找平整、不伤身的降落点,下滑进场,落地速度不超过不伤身的上限;落地后步行段走完最后一截。
   飞着时烟花或耐久低于余量、前方推演全被否决,就就近迫降,迫降点按伤害最小挑;都照实报告。
6. 执行合法:只用视角、跳、右键烟花;不改速度、坐标、计时器,不发原版客户端不会发的包。

#### 落地的实际(第 3 批,11-02)

行程由几段组成(`Voyage`):走路的段(`Driver`)与滑翔的段(`Sortie`)共用一套家伙(`Rig`:同一本账、同一份行程日志、同一套重规划原因),
段与段只通过"这一段到了没有"相连。第一刻问一次要不要飞(`Glide.plan`):不飞就是一个走路的段;飞,是 走到起飞点 → 滑翔 → 照原目标走。
走不到起飞点或滑翔中止都不是整趟的失败,从身体此刻的位置照原目标走。偏离与补充:

- **用不用**:不是另写一份耗时公式。拿同一个局部控制器(`Pilot`,物理 `Dynamics.gliding`)在没有障碍的空场里把计划的线飞一遍(`Glide.rehearse`),数它用了几刻、放了几支、
  落得轻不轻;"走到起飞点 + 飞 + 降落后走到目标"低于全程步行的下界(水平距离乘疾跑一格的耗时)才排;烟花用量乘 1.5 加 1、鞘翅耐久同样留余量,不够就不飞。
  目标要是有限的几个格(最多 64 个),水平不到 48 格不排。
- **线与巡航高度**:起飞点→爬(一格水平一格高)→平飞→按滑翔比 9 下滑→降落点。巡航高度**不读高度图**(洞顶、屋檐也在高度图里,测试场地的壳也在):从起飞点之上 10 格起每次多 6 格往上试,
  取第一个"线和线两侧各 2 格的平行线都能扫过去"的(碰撞扫掠);走廊上有一个区块没加载就不排滑翔(未知不是空气)。降落点在目标这一侧 6 格处,起飞点高度上 16 格、下 40 格里找第一个站得住的地面。
- **起飞点**:身体附近 2 格内站得住的格,近的在前,取第一个线通得过去的;没有"整根空柱通天"的检查(整条爬升线的扫掠已经包含了它)。
- **起飞**:先把烟花拿到手上(`Hotbar.grip`,换手记进身体动作),朝巡航方向抬头 45 度,起跳、松开,离地后新按一下跳(按下沿,`Controls` 发展开的指令),展开了就是滑翔。
  展开的条件照 `Controls.unfurl`(原版 `tryToStartFallFlying`:离地、不在水里、没有漂浮效果、胸甲位是没坏的鞘翅),**没有**"竖直速度小于零"这一条:我没能打开 1.21.1 的反编译源码核对客户端那一段,
  依据是 `AirGameTests` 的实测(静止在空中按一下跳就展开)和服务端 `tryToStartFallFlying` 里没有这一条。
- **局部控制器**:与创造飞行是同一个 `Pilot`,只换 `Dynamics`(物理 `Kinematics.glide/boost`,键集是"目标俯仰 × 偏航偏移 × 放不放烟花")和代价项(放烟花扣分、落地速度过快扣分)。
  颈部模型 `Neck` 逐刻逼近目标俯仰,不在离散俯仰值之间直接跳。烟花的保证推力刻数按 `10 × 飞行时长`(下界)规划,不读实体的真实寿命;右键间隔 4 刻,冷却在尝试**之前**就锁存。
  推演撞方块的候选被否决;一组都过不去且停不下来(滑翔)时,挑撞上之前能多飞几刻的(`Pilot.survive`)。
- **降落**:落点附近下滑进场,滑翔里落地竖直速度高于每刻 -0.5 不掉血;落得重的候选扣分(别无选择时伤害最小的胜出),落地后原版停滑翔,走路的段走完最后一截。
- **迫降**:烟花用完又够不着降落点(按滑翔比留 0.8 的余量),或前方推演一组都过不去,就在身边挑够得着、直线通得过去、不用俯冲(水平距离至少是下降高度的 3 倍)的站得住的地面,
  离原降落点近的优先,改沿它下滑,账上记为迫降。没有水面优先、没有"可恢复尾巴"的拉起轨迹检查。已经在迫降又被围住就不再有办法,键松着等落地,落地的伤害如实记账。
- **没做**:没有烟花时"只从高处往下滑"的排法(目前要有烟花才排);"跳下高处"的起飞;盘旋找落点。

### 六、照实交账

- 受理时能估的先报:这一趟打算怎么走(走多少、飞多少、在哪起飞)、估计用几支烟花、现有几支、鞘翅耐久;写明是估计。
  (实际:`numen.move.to` 等是阻塞调用,没有单独的"受理"消息;估计写进日志(`Sortie` 开始时 INFO 一行:起降位置、水平格数、估计刻数、烟花与耐久估计),回执里的细账带"计划的烟花数"。)
- 回执(`Journey`/`Walked`,三个动词共用)在现有之外加:每段的方式与格数、每次起降的位置、用掉的烟花、鞘翅耐久前后、落地伤害、收场时是在飞还是落地。
  给模型的话只在 `NavText`。(实际:每段滑翔一条 `EditLedger.Glided`,回执 `Walked.glided`:起降的格、飞了几格、用了几支烟花(计划几支)、鞘翅耐久前后、落地掉了几点血、是不是迫降、收场时在不在空中;
  话是 `NavText.glide`。)

## 分批

1. **地基**:二(身体层)+ 三(步进器与逐刻对照)+ 身体快照带移动方式、走法集由身体给。步行评测逐字节不变(AutoDL 上 `pathingBenchDiff` 为零)。
2. **创造飞行**:四 + 六里与创造飞行有关的部分;GameTest:飞越峡谷到点降落、飞到半空一格悬停、平地近处不飞。
3. **鞘翅**:五 + 六;GameTest:平地起飞到远处降落、烟花不够走路、飞着用完迫降、撞墙推演否决。
4. 每批全套验证(单测、两平台构建、GameTest)全过才合。
