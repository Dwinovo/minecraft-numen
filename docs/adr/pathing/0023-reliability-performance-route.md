# 0023 取舍与边界:可靠 > 性能 > 路线;规划粗判、执行核实

- 状态:已接受;取代 0012、0018,与 0024–0028 一起取代 0020
- 日期:2026-10-28(用户定)

## 背景

10-28 与 Baritone 同机对比(靶场 27 条,`baritone-vs2` 外挂):可挖可放时每节点我们 41µs、Baritone 6.8µs;路线在我们自己的成本模型下贵 1–5 倍,
挖 503 放 289 对 Baritone 挖 119 放 5;不改地形时 `broken` 我们 48000 个节点找不到,Baritone 6149 个找到。

病根是 0012"规划是执行的子集":搜索里每个候选步都做执行级的精确判断(视线射线、找面、潜行探出、问权限、叠改动)。世界会被别人、实体、
流体改,规划永远保证不了执行一定成功;这条原则做不到,却让每个节点贵了 6 倍,预算只好压小,压小了路线就差、洼地出不来。

## 决定

1. 优先级:**不卡死 > 性能 > 路线好坏**。路线只报告,不设门槛。
   按距离再分一层(10-29 用户定):**短距离(水平 32 格以内)与中距离(32–128 格)的可靠与性能优先于长距离(128 格以上)**。
   日常指挥多在眼前与一两百格内,更远的在服务器上常用传送;长距离允许路线差一点、多走几段。具体是:中距离以内一次搜索
   就该搜到终点(快照与首段时限按此定),路线不能离谱;长距离允许交半程、靠接续走完。靶场与对比报告按这三档分开列。
2. 规划可以粗、但不许把能走的判成不能走;**用到哪一步才精确判哪一步**(0024)。交给执行的每一步都是精确判过的。
3. 执行闭环兜底:走之前往前核、世界变了就重规划、同一步不通不试第二次、收场只看节点总数(0027、0028)。
4. 一次重构到位,不留双轨:旧机制在被取代的同一阶段删掉,不加开关,不保留旧路径做对照。对照只用 Baritone 外挂与 10-28 的数据。
5. 模块边界不变:`numen/pathing` 只依赖原版 Minecraft,宿主经端口(`Ports`)接入;Numen 侧只在 `nav/` 适配层。新增的可替换部件(时钟)也走端口,
   不用全局可变静态、不在公共代码里判断加载器或运行环境。

## 依据

主流做法一致:Baritone(粗判代价函数 + 执行前往前核 5 步 + 失败拉黑)、mineflayer-pathfinder(时限内交半程 + 方块变了重算 + 卡住重算)、
Azalea(超时交半程、无解加时重试)、ROS 2 Nav2(规划 / 控制 / 恢复分层,有限次重试后交回上层)。
理论:Lazy Weighted A*(Cohen, Phillips, Likhachev 2014)、LazySP(Dellin & Srinivasa 2016)——边的评估贵时惰性评估,完备且有界。

## 后果

- 可靠性矩阵(0022)改为检验"精确判过的步在执行里走得通"。
- 靶场指标加两项:执行中重规划次数、取出时精确判断不成立的比例。
