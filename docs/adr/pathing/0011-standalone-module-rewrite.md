# 0011 寻路独立成模块重写:几何只从碰撞箱推一份

- 状态:已接受
- 日期:2026-09-27(三批)、09-28 切换
- 提交:`505deb86b` … `e4a9e8c2b`、`d916bbce5`;设计与落地记录见 `pathing.md`

## 背景

09-27 真机一局:爬梯上阁楼卡死(分类表说屋顶楼梯可穿,执行被碰撞箱顶住头,重规划算出同一条路;那条表项的理由"原版视为可通行"是错的,
原版 `StairBlock.isPathfindable` 返回 false)、上楼梯一级级跳、手里有圆石却说没带料、goto 没到高度报完成。结构原因四条:
地形几何两个来源;每个走法把规划与执行写在一个类里(照搬 Baritone 的 `Movement`);边界两头漏(寻路 import 十来个 Numen 类,外面引用寻路内部类四十多种);
不能单独测。当时 `core/pathing` 81 个文件约 1.5 万行。

## 决定

- 地形几何只从方块碰撞箱推一份(第 0 层),规划、执行、感知读同一份。
- 独立的 Gradle 模块、只依赖原版,Numen 经端口接入,边界由编译器保证;以后可单独发布(LGPL)。
- 分五层:地形、规划(每种走法只有前提与代价)、搜索、执行(每种走法一个控制器)、门面。规划与执行分开,执行用同一份几何校验。
- 派发搜索时拷所需区块段的只读快照,工作线程不碰活世界(取代 0003 的活引用)。
- 用普通假玩家跑 GameTest;14 件设计选择(`pathing.md` 第十二节)。不做分层粗图。

## 后果

- 楼梯、半砖、门这类"两边对不上"的问题从结构上收掉;217 条旧单测逐条对照迁移。
- 每个节点贵了:同口径对照,起伏地形 100 格旧 5.7 毫秒、新 38 毫秒,挖 30 格隧道旧 197、新 843 毫秒,每节点 15~76 微秒;
  新实现每个节点按碰撞箱推迈步、判站姿、查接触与禁令,读方块 500~900 次(旧的 67~309 次)。当时判断追平旧实现就得把分类表搬回来,
  正是重写要去掉的多来源;节点的价钱到 0019 才压下去。
- 0.1.4(10-06)与 0.1.4.1(10-09)带着这一版发布。
