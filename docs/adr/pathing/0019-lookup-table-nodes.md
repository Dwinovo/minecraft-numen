# 0019 节点查表:标志字、平行数组、快判断

- 状态:已接受;快判断被 [0024](0024-lazy-evaluation.md) 修订
- 日期:2026-10-13(0.1.5 第 10 步第 1 步)

## 背景

0011 之后每个节点 15~76 微秒;第 8 步第三批(快照整层解开、改动表写时复制、按状态查表 `StateTable`)压到 10.6~22.1。
同机对照 Baritone 搬运版:不挖不放约 1.0 微秒,许挖许放 2.1~2.8。差一个数量级来自每个节点做的事:它的走法是固定偏移的静态函数、零分配,
方块按状态编号预算成字节表(`PrecomputedData`),执行时才重算做什么。我们不放弃"规划与执行同一份前提"(0011),能借的只有"按状态预计算"。

## 决定

- 每种方块状态一个标志字(`CellFlags`:能穿、整格、会塌、湿、可能可攀、液体、伤身),由 `Boxes`、`Semantics` 推出,不另立判据;单测对原版全部状态逐个核对。
- 快照读到某一层时同时得到那一层的标志字;节点是平行数组里的一个下标(`Nodes`、`OpenSet`),不建对象。
- 走法先过快判断(`Move.quick`):读标志字、按位判断、查表得价;四周有半砖、楼梯、门、水、梯子、伤身格或要挖要放的,答"断定不了",走精确前提。
  只有交出的路线才逐步补全 `Maneuver`,补出来不是"成立"就抛出(那是缺陷,不是兜底)。
- 先例:原版 `WalkNodeEvaluator`/`PathType`、Baritone `PrecomputedData`。
