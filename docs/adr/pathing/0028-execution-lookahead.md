# 0028 执行往前核与重规划触发

- 状态:已接受;修订 0020 第 4 条
- 日期:2026-10-28

## 背景

搜索读的是快照,走的是活世界;别人放了方块、水流过来、沙子落下,已核的步也会失效。现在执行只复核正在走的一步,走到跟前才发现,还常常已经迈进去了。

## 决定

1. 每一步开始前,在活世界上精确核对**接下来 5 步**;正在走的一步每刻照常复核。不成立就不走,这一步记进这一趟的"走不通",从身体此刻的位置重规划。
2. 世界变化用**轮询**发现,不订阅事件:往前核本身就会读到变了的格,不需要另挂 Mixin 或按加载器接事件,`pathing` 模块保持自足。
3. 重规划的触发只在段状态机一处汇总:往前核不成立、一步执行失败、一步超时(`Watchdog` 不变)、半程快走完(接续)。
4. 收敛不变:同一步不通不试第二次;收场只看节点总数(0026);缺什么交回模型。

## 依据

Baritone `PathExecutor`:每个动作开始时按 `costVerificationLookahead = 5` 重算后面几步的代价,当前动作每刻重算,变成不可能就取消重算;
一步耗时超过预估就取消。Nav2:控制器失败触发重规划与恢复。mineflayer-pathfinder 用方块更新事件,我们在服务端用轮询得到同样效果而不加接缝。

## 后果

- 靶场与 GameTest 统计"执行中重规划次数",按原因分开。
- 往前核与搜索取出时的精确判断是同一个函数、读不同的世界(活世界 / 快照叠改动),判据只有一份。
