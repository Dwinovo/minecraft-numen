# 0015 半程只交到最后一个回得了头的节点

- 状态:被 [0020](0020-segments-learning-closed-loop.md) 取代
- 日期:2026-10-11(0.1.5 第 4 步)
- 提交:`447a68249`、`a4275b831`

## 背景

搜索预算用尽时交出"离目标最近"的那一截,不管里面有没有回不了头的动作。`ravine_floor`:半程路线里连续 9 次计划内坠落,落到峡谷壁的平台上,四面无路。

## 决定

- `Maneuver` 记一项事实:不改地形能不能原路回到起点(由运动学与第 0 层几何在每种走法的前提里判一次)。
- 交出策略拆成 `search/HandOver`:半程只交到最后一个回得了头的节点;第一步就回不了头的不交,接着搜到目标或搜完。

## 后果

- `ravine_floor` 不再困在半腰,但结局变成预算用完(崖沿一大片,一万个节点搜不完)。
- 第 9 步查出 `rock_far` 在两个竖井口之间来回:最优路线第一步就是不可逆的坠落、截不出半程,`pick` 落到最松一档的另一个井口,两个井口互相被对方挑中;
  估价随快照窗口变,停滞判定被骗。"截不出就换一档"这套半程挑法由 0020 整个取代。
