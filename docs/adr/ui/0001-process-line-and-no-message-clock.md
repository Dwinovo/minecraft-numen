# 0001 她干活的过程是一行安静的字,点开是一根线串起的步骤;对话里不再标时刻

- 状态:已接受,已落地(待真机看);第 6 点的"日期分隔照留"被 [0005](0005-no-dates-no-toasts.md) 修订
- 日期:2026-11-26
- 另见:[control 0028](../control/0028-ask-user-question-tool.md)(提问工具)、lua 工具的 `description` 与 `NumenTool.summary`(一次调用读作什么由工具自己说)

## 背景

她连着的思考与工具调用(中间没开口)在对话流里合成一块"过程"。现在收起时是"思考过程 · N 步 · 执行",点开后思考被压成一整段、
工具行只有图标与截断的参数,看不出每一步做了什么、用了多久。每条气泡右下角还挂着时刻,对话里一屏全是 14:01、14:02。

用户先后否了大改界面("UI 还是不要太大重构了,现在的其实也能用"),只改思维链;看过演示(在现在的配色与方角里只改过程块)后:
"OK,顺便把聊天下面的时间去掉"。参照的是 shadcn 体系的 chatcn `reasoning`(一行安静的字加计时,不自己开合)与 AI Elements 的
Chain of Thought(一根线串起带状态的步骤)。

## 决定

心智模型:**她干活时,对话里只多一行字,告诉你她此刻在干什么、已经多久;干完这一行变成"已处理 N 秒"。想看细节就点开,
里面是一根线按先后串起的每一步。** 其余界面、配色、方角都不动。

1. **一段过程照旧**:她两次开口之间连着的思考与工具调用;换了一只、开口说话、日期换了都收口(现有规则)。
2. **收起时的一行。**
   - 在想:`思考中`(闪动)+ 已用秒数(走动)+ 这段思考的第一句(截断)。
   - 在跑一次调用:这次调用读作的那一句(`ToolLine`:工具名加 `summary`,lua 就是它的 `description`)+ 已用秒数。
   - 做完:有调用是 `已处理 N 秒`,只有思考是 `已思考 N 秒`;N 是这段过程从第一步开始到最后一步结束的秒数。
   - 失败照最后一步算:最后一步失败,这一行是失败色;中途失败、后来成了,不标。
   - 不自动展开也不自动收起;展开状态只随主人的点击变。
3. **点开后的步骤线。** 左边一根竖线,按发生先后列出每一步,每步右边是它用的秒数:
   - 思考:淡色正文,保留原有换行,不压成一段;
   - 调用:状态(在跑转圈 / ✓ / ✕)+ `ToolLine` 那一句;再点这一步,下面展开它的代码(调用参数里的程序)与回执(工具结果原文)。
4. **只有一次调用、没有思考时**,照旧不包一层,直接就是那一步(同样可点开看代码与回执)。
5. **秒数从记录里的时刻算**,不另记:每条记录(主人的话、她的一轮、工具结果)本来带时刻;一步思考的秒数是它前一条记录到这一轮的间隔,
   一次调用的秒数是发出到结果回来的间隔;还在跑的一步用此刻减去它开始的时刻。成败照旧只认 `ToolOutcome.failed`,不猜字符串。
6. **对话里不再标时刻**:话的气泡、清单消息、征询卡收起后的到达时刻都不再画;征询挂着时的倒计时(还剩多少秒能答)照留,日期分隔照留。
7. **删掉的**:"思考过程 · N 步 · 用了哪些"那种摘要、把思考压成一行的扁平化、气泡里时刻的排版(放得进最后一行就挤在右下角的那套)。

## 后果

- 她在干什么、干了多久,不点开就看得到;点开能逐步核对代码与回执。
- 对话流更干净;要知道某句话是什么时候说的,看日期分隔与左栏。
- 演示:`numen-chain-demo`(只改过程块、去掉气泡时刻,其余是现在的样子)。
