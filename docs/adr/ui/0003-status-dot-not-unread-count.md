# 0003 头像右下角一个状态点,代替未读数与在线标记

- 状态:已接受,已落地(待真机看)
- 日期:2026-11-26
- 另见:[0001](0001-process-line-and-no-message-clock.md)、[control 0028](../control/0028-ask-user-question-tool.md)(她的提问)

## 背景

左栏头像、转盘、消息通知上都显示未读条数,对话里还有一条"以下为未读消息";头像右下角另有一个绿色在线标记。用户先提出只去掉对话里那条线,
再提出"不要记有多少条了,有没有读用一个点就行",并要求先看主流。主流的 agent 产品(Cursor、ChatGPT、Codex、Claude Code 桌面版)
都不数条数,而是给每个会话标状态:在跑转圈、等你是橙黄点、做完有没看的是蓝点、出错是红点,看过的不标。看过演示后,用户嫌状态点和在线标记
混在一起乱,改成只留右下角一个标记、不在线的头像变灰,确认"这个方案没问题"。

## 决定

心智模型:**头像右下角只有一个标记,说她此刻最需要你知道的那件事;什么都不标就是在线、闲着、你都看过了。**

1. **四种状态,同一时刻只显示一种,按这个先后取:**
   1. 等你(黄点):她有一条征询在等你答,或她用 `AskUserQuestion` 问了你还没答;
   2. 出错(红点):她的循环因为需要你处理的原因停下(连不上模型、没绑模型档案这类),直到原因解除;
   3. 有新话(蓝点):这个会话里有你还没看过的她的话;打开这个会话就灭;
   4. 在干活(转圈):她正在想或正在跑程序。
2. **不在线**:整个头像变灰变淡,不另加标记,也不显示上面四种。
3. **哪里都一样**:左栏、转盘、消息通知用同一个判断、同一种画法。消息通知照弹,不带数字。
4. **"看过没有"只记一个开关**:每个会话记你最后看到的时刻,和她最后一句话比;不再数条数。
5. **群聊会话**只显示"有新话"。
6. **删掉的**:左栏、转盘、通知上的未读数字;对话里"以下为未读消息"那条线;绿色在线标记;为数条数存在的计数与它的同步。

## 后果

- 扫一眼左栏就知道谁在等你、谁出了错、谁有新话,不用点开。
- 少一份要保持一致的计数状态。
- 演示:`numen-status-demo`。
