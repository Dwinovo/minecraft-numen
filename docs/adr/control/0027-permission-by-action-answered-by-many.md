# 0027 权限按动作问一圈:八个动作,谁都可以回答,主人只有档位与点出来的名单

- 状态:已接受
- 日期:2026-11-24
- 修订:[0025](0025-permission-judges-does-not-recognise.md)(规则里的词、出厂与硬规则)、
  [0026](0026-ownership-is-asked-not-recorded.md) 第 6、7 点(规矩与 `structure` 这个词);更早的规则语言、三层规则、命中计数、模式
- 另见:[0020](0020-questions-answered-by-whoever-knows.md)(问题与登记的门);现状与细节在 `docs/permission-layer.md`

## 背景

0025、0026 之后权限层不再自己认东西,但"许不许"仍是一门规则语言:七个动词、八个词(`contents villager hostile hazard_item
block_entity named near structure`)、`&`、`|`、`!`、带参数的词,三十来行出厂规矩。纯原版里其中十一行永远碰不上(方块没有人回答
是谁的),`hazard_item` 与 `near` 完全空转,`structure` 只为"村庄"一件事活着;出厂规矩写在 `numen-api` 里却说着原版的事。因为同层
"允许"排在"问"之前,想让一样东西要问就得回头在允许行里写排除,于是才需要这门语言。

用户:

> 这太特化了,完完全全就是为玩家考虑了很多没有必要的东西,我现在只需要 numen 和世界的"交互"需要被我们控制,并且是否可以
> 由多个人来回答。交互其实就是那七个动作我是认的,要不就以动作来划分吗?是不是我们现在做的太细了?

读了两路一手材料:

- Minecraft 的保护系统(FTB Chunks、Open Parties and Claims、Flan、GriefPrevention、WorldGuard、MineColonies):规则都按动作分
  (FTB Chunks 六个、GriefPrevention 三级、MineColonies 二十七个),看的是"你和这块地主人的关系";只有允许与拒绝,没有一家有"问";
  没有一家能写"并且/不是",例外靠 id 或标签的名单。FTB Chunks 每个动作是一个函数,答 `ALLOW`、`DENY` 或 `CHECK`(不拍板)。
  加载器的破坏、放置、交互事件本来就是谁都能来听、任何一个取消就算取消。
- 智能体产品(Claude Code、Codex、OpenCode、Gemini CLI、Cline、Goose):三种判决;Claude Code 每类工具一个基本档,模式调基本档,
  规则叠在上面,先后是拒绝、问、允许;"以后别再问"由程序记一条,记什么按工具类型定(命令记命令、联网记域名),按钮上写明记的是什么,
  说不清范围时只给"这一次";钩子与插件可以对一次调用说拒绝、必须问或放行;对话里说的边界不存成规则。

## 决定

心智模型:**她要动手之前,按"做的是哪种事"问一圈;有人说不许就不做,主人说过不用问就做,有人说要问就问;都没人说话,看主人
给这种事定的档。权限层不认方块、不认实体,也不知道"这是谁的"——那是回答者自己的事。**

1. **八个动作。** 挖方块、放方块、交互方块、打实体、交互实体、扔东西、用手里的东西、执行命令。"用手里的东西"是新加的:对着空气
   右键(掷出去、射出去的)原先不过任何一道卡。动作是她的身体动手的方式,不是模组的名词;模组的操作说成这八种里的一种。
2. **回答者。** 谁都可以登记来回答"这个动作、这个对象,许不许":不许、要问、许、不表态。只说自己懂的,互相不知道对方。
   原版的由 `numen` 登记,模组的由插件登记,同一个写法。
3. **合起来的顺序,先碰到哪条算哪条:**
   1. 有回答者说不许 → 不做;
   2. 在主人"不用问"的名单里 → 做;
   3. 有回答者说要问 → 问主人;
   4. 有回答者说许 → 做;
   5. 都不表态 → 看主人给这个动作定的档。

   不许是解不开的;主人说过不用问的就不再问(被问的就是他自己,这一条与 Claude Code 相反)。
4. **主人只有两样。** 每只同伴八个档位(许、问、不许),和每个动作一张"不用问"的名单。名单在征询卡上点"以后都允许"进去,
   记什么由动作定:挖、交互方块记哪种方块,放记放的是什么,打、交互实体记哪一只(有主的、玩家)或哪一种,扔与用记哪种物品,
   命令记命令名。原来的 `observe`、`bypass` 是八个档位的两种预设,不再是另一样东西。
5. **服主**是一个回答者:服务器设置里同样八个档位,给全服定上限。
6. **"归属"是一个回答者:**别人的东西不许,主人的东西要问,其余不表态。它用 0026 的"这是谁的"查事实。
7. **征询卡:**允许(这一次的活)、以后都允许(按钮上写明记的是什么)、拒绝;允许与拒绝都可以附一句话交给模型。
8. **她自己只能往严了调:**把一个档位调严、从名单里删一项直接生效并告诉主人;调松、往名单里加,要发卡经主人。
9. **干活的一方不问权限。**卡长在她身体改世界的入口里:她的手、直接写一格、扔东西、执行命令;内容只调入口,入口去问。
   要主动问的只有两种:开工前打听一批动作里哪些要问(合成一张卡、给寻路定价),和插件做了一件不经过她身体的事。

没有了的:规则语言与它的解析器、八个词与登记词的口、出厂规矩与硬规矩的原文、三层规则、命中计数、存档里的规则行。

## 后果

- 主人面对的是一张八行的表与点出来的名单,不用学任何写法。
- 主人说不出"挖石头随便、挖箱子要问"这种区别:挖是一个档位;这种区别只能来自回答者,或卡上点出来的名单。
- 村庄、村民、起了名字的生物、装着东西的容器、危险物品都不再特殊;那七条写死放行的原版命令没有了,命令一律看档位与名单。
- 她给自己加不了"别动箱子"这种细规矩,只能把整个动作调严;细的约束在对话里,或等标记。
- 存档里旧的规则行与模式读不通:记一条日志、不生效、不迁移。
- 装了回答"这是谁的"或直接回答"许不许"的插件,保护自己生效;纯原版里方块没有人回答,只看档位。

## 没有定的

- **标记**(给实体、区域起名字):主人圈的一片是又一个回答者,见 0026。
- 动作的清单要不要对插件开放:结构上一个动作只是名字、出厂的档与"记什么",等真有说不成这八种的用例。
- "这一下右键会做什么"原版还有没人回答的物品(锄、铲、斧、骨粉、刷怪蛋)。
