# 0002 能力做成工作流工具,一律向 API 注册

- 状态:被 [0004](0004-command-line.md) 与 [0005](0005-atomic-commands-composed-by-scripts.md) 取代
- 日期:2026-06-03、06-29
- 提交:`045eb4c55`、`bb51cc4ed`、`be7f1cb64`
- 另见:网站《怎么让 AI 操控一个服务端玩家?》(`numen.dwinovo.cn/zh/deep-dive/controlling`)

## 背景

直接给模型一副键盘(W、A、S、D、按住左键……)行不通:每一下都是一次工具调用,token 爆炸,模型反应也慢。Voyager、Mindcraft 都不这么做。
同时 Minecraft 的模组生态很大,她不能是一座孤岛。

## 决定

- **工作流做成工具**:几个原子操作组合成的一串动作是一个工具,模型只说要什么。例如 06-03 的 `mine_block(block_ids, count)`:
  她自己找最近的、走过去、挖、凑够数,模型不给坐标、不自己组合"走 + 扫 + 挖"。
- **一律注册**:06-29 引擎拆成 `numen-api`,Numen 自己的内容也和第三方一样向登记口注册(工具、任务执行器、本能);人人平等。
  当天试过注解反射的写法(`@NumenAction`),第二天删掉,工具的契约只剩名字、说明、参数结构与调用。

## 后果

- 早期版本很快做出了挖矿、建造、战斗、合成一套工作流;适配模组就是注册新工具。
- **工具越堆越多**:组合出来的工作流也得再注册一遍、再写一遍参数与说明;08 月 45 个工具的完整定义每轮全发,09-24 达到 48 个(插件占 9 个),
  工具定义约 1.45 万 token,占固定前缀的 84%。
- **工作流是黑盒**:模型下达 `goto` 的那一刻就交出了一切,寻路照程序走,知道主人的房子在哪也照样挖过去。
