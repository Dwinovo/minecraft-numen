# 0008 模型只剩一个 lua 工具,API 原子化,管大脑自己的事另成工具

## 背景

Lua 接上之后(control 0006),模型面上同时有 `command`、快捷工具与 `lua`,同一件事几种写法;胖命令还在替她做决定。

## 决定

- **在世界里做事的工具只有 `lua`**:一段程序,一次调用跑完,回一张回执。`command`、快捷工具删掉;10-04 命令行前端(Brigadier 承载 API 调用的命令树)整个删掉,只剩 Lua 一个入口。
- **管大脑自己、不碰世界的是独立工具**:`skill`(照 Claude Code 的 Skill 工具)、`todo`(照 TodoWrite)、`memory`(照 Anthropic 的 memory 工具)。工具表是 `[lua, skill, todo, memory]`。
- **五层**:⓪ 身体控制(Java,模型看不见)、① 原子 API(Java 登记生成 Lua 函数,权限只守这层)、② 出厂模块、③ 她的模块、④ 这一轮的程序(后三层是 Lua)。
  判据:秒级的决策进 Lua;每刻的控制、重计算(寻路搜索、大范围扫描)、权限、反射留 Java。① 层定死,模块换不掉也遮不住。
- **API 原子化**:走、挖、捡、打一片、盖整栋交给出厂的 Lua 库;Lua 不留状态,世界就是状态,不做名词的增删改查,要记住的只走 `memory`。
- **值、错误与帮助各一种写法**(照 mineflayer、Cloudflare Code Mode、smolagents、CodeAct、LuaLS):位置是一种值、查询结果原样交给下一个函数、
  失败是带 `kind`/`hint` 的错误值、帮助是登记处生成的 LuaLS 类型签名,系统提示只放索引、`api.help` 按组展开。
- **模块一律是库**,按名字直接用,不提供 `require`(实验:提示里写明"不用 require"后 60 份程序 0 份写它;标准 `require` 7% 漏写)。

## 后果

- 第二轮真模型评测与基线持平(各 5 次 41/50 对 41/50),参数写错占程序的比例 8.3% → 3.7%,屋后挖矿的轮数 17~20 → 3,token 大降。
- 胖命令拆完之后,组合逻辑都在 Lua 里看得见、改得了;Java 里残留的几处流程(合成挑配方、驾船等)逐个拆。
- API 怎么登记见 0009;程序在哪一端跑见 0010。
