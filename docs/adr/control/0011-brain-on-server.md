# 0011 服务端必装、客户端可选,循环、记忆与外接大脑放服务端

- 状态:已接受;"三种大脑、客户端代调为默认"与"key 不出主人机器"被 [runtime 0001](../runtime/0001-server-agent-two-brains.md) 修订

- 提交:`a8754af50`、`a9e99d7ab`(设计稿)
- 另见:`docs/input-pipeline.md`

## 背景

程序已经在服务端跑(control 0010),但收件箱、循环、她的记忆、外接大脑(MCP)还在主人客户端:主人一下线,外接大脑就操控不了她,她听不见也想不了。
用户的方向:言出法随要往服务端插件走;"这才是你在 Minecraft 里的个人 agent"。

## 决定

- 三层两管:渠道(聊天、面板、QQ、弹幕、定时、世界的事)把话送进收件箱;大脑(主人客户端代调模型 / 服务端直调模型 / 外接大脑)从收件箱取件、交出 Lua 程序;
  身体在服务端跑程序。加渠道不碰大脑,换大脑不碰渠道,谁驱动她都用同一副身体。
- 服务端必装、客户端可选;循环在服务端,客户端只代调模型与呈现;她的记忆(对话、札记、待办、目标、人设)只存服务端、落世界存档。
- 外接大脑放服务端:一个远程 MCP 入口给所有人,按令牌认人,动作照过权限层。
- 不变量:API key 不出主人的机器;第三方服务器上走代调、按服务器额度上限,提醒在服务商一侧设上限。

## 后果

- 修订 0010 的"服务端不存任何大脑数据"。
- 不装客户端的玩家怎么和她交互(聊天 @、命令、行动栏、箱子菜单、服务端对话框)、端口方案,做时单独出设计稿。
- 做任何设计时不把"大脑在哪个进程、怎么跟她说话、配置存哪"写死在客户端。
