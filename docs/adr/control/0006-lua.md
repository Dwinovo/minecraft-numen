# 0006 组合语言用 Lua

- 状态:已接受
- 日期:2026-10-01
- 提交:`0b37ff8f0`、`8bd6300f2`
- 另见:`docs/shell.md` §四;网站《怎么让 AI 操控一个服务端玩家?》

## 背景

原子命令(control 0005)要一门语言把它们组合起来,并让模型自己掌控工作流的细节,而不是我们再给她注册一个组合好的工具。
Claude Code 的工具表里最特殊的是 bash:一门图灵完备的语言能组合任何操作,删掉别的工具它照样能干活。Voyager、Mindcraft 一开始就让模型写脚本;
游戏里用脚本驱动的模组(CC: Tweaked、超级工厂)大多选图灵完备的语言。

## 决定

组合语言是 Lua 5.2,只有这一套。语言只经 `ScriptEngine` 一处认,派发、等待、上限、打断、回执与语言无关。

考虑过的:
- **bash 子集**(当天上午的方案):没有函数、没有数据结构,和 Lua 并存就是两套组合语言。
- **JavaScript**:实验(DeepSeek 真写 30 份 JS、30 份 Lua,用桩函数测"直接能跑"的比例):Rhino 语法 8/30(不认 `for const of`),出局;
  GraalJS 与 LuaJ 语法都 30/30,但 GraalJS 发行包多 61.8 MB、冷启动 2~3 秒、元空间多 25 MB、社区版没有堆上限,LuaJ 只多 0.34 MB。
- 实验里决定成败的是 API 的形状,不是语言:返回 `{ok, text, data}` 信封时一半以上被用错,改成"成功直接返回、失败抛错"后两种语言都是 28/30。

09-15 看第三方框架 mc_agent 时否过"Lua 即动作",否的是它的实现(Cobalt 没有指令预算、死循环卡服,脚本绕过权限,超能力身体,62 KB 脚本全文进提示),不是 Lua;
现在有原子命令、权限层与实际账,Lua 只做组合。

## 后果

- 原子操作注册成 Lua API,模型用脚本自由组合;适配模组的负担大减。例如驯服女仆是一段脚本里连着调"拿出蛋糕"与"右键",不用再注册一个"驯服女仆"工具,也不用赌两次工具调用之间女仆没走开。
- 用户真机:"引入 LUA 之后体感丝滑特别多……利用上模型的 coding 能力才是对的。"
- 虚拟机怎么选见 0007;模型面只剩 Lua 一个工具见 0008。
