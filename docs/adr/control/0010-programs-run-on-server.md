# 0010 程序整段在服务端跑:客户端想,服务端做

- 状态:已接受;"服务端不存大脑数据"一项被 [0011](0011-brain-on-server.md) 修订
- 日期:2026-10-05
- 提交:`27c777cda`、`f7ae5ee1e`、`43ea07c42`、`054a976b7`、`418e60358`、`d251c67dc`
- 另见:`docs/shell.md` §十四

## 背景

模型写的 Lua 原先在主人客户端跑,程序里每调一次服务端函数就经网络往返一次:一轮评测 36 次运行共 4469 次调用,98% 是服务端函数;
真机 81 轮约 1700 次往返,一团扫描结果几百格原样传回、超过上行包 32767 字节的上限。为此做到一半的"句柄"框架(大结果留在服务端、只给一个引用)越补越费劲。

## 决定

- 切口在"一段 Lua 程序":客户端把程序文本、她的模块清单、这个连接还没送过的模块正文发上去,程序**整段在服务端、身体与数据旁边**执行,只回一份回执
  (remote evaluation / query shipping;CC: Tweaked、OpenComputers、Voyager 都是把代码送到数据旁)。
- 函数两端都有,按第一个参数定端;程序在服务端遇到客户端函数,就向主人客户端发**反向请求**(MCP 的 sampling、LSP 的 workspace/configuration 的先例),有时限,程序结束即撤销。
- 主线程只执行、从不等程序:程序的服务端调用排进主线程车道,每刻全部 10 ms、每段 5 ms(取 CC: Tweaked 的 `max_main_global_time`/`max_main_computer_time`)。
- 她的模块真源在客户端,服务端按内容哈希缓存(Redis EVALSHA、Bazel FindMissingBlobs 的做法)。不开自己的端口,走 MC 网络;载荷层分片(照 CC: Tweaked)。
- 回执照标准三管道:stdout 是 `print`,stderr 是 API 主动报告的(身体经过、征询、失败),结局是退出状态与返回值;去掉逐次调用的流水,值按 NumPy 式缩略打印。
- 句柄框架暂停:切口对了就不需要它。

## 后果

- 往返从每次调用一次变成每段程序一次;循环查询的回执 3787 → 42 字。
- 服务端要跑玩家提交的代码:沙箱的指令、字符串、时间上限之外,加每只同伴一段、每位主人 8 段、全服 64 段的并发上限。
- 主人一下线,她能把手上的程序跑完,但听不见、想不了(0011)。
