# 0028 问人只有一处:权限征询与她自己的提问,同一块面板、同一条回答路

- 状态:已接受,在落地
- 日期:2026-11-26
- 另见:[0027](0027-permission-by-action-answered-by-many.md)(权限按动作问一圈、"要问"由谁答)、[runtime 0008](../runtime/0008-brain-on-owners-client.md)
  (大脑在主人客户端)、[0008](0008-lua-only-tool.md)(她的工具)

## 背景

她停下来等人,现在只有一种:权限层判出"要问",服务端的征询登记处(`ConsentDesk`)把征询推给在场的主人,答复框是对话流里一条带按钮的消息,
外接大脑的客户端(MCP elicitation)与渠道是另外的去处(`ConsentVenues`)。她自己想问主人一句("用哪台炉子烧?")没有工具,只能开口说话、
等主人下一句,这一轮就结束了,主人的回答进来时她已经不记得在等什么。

用户:"一般来说有 HITL 的时候不应该是占领输入框吗……我想干脆做 HITL 工具了,比如说你的 AskUserQuestion";"统一的 HITL 工具"。
主流做法:Claude Code 的权限确认与 `AskUserQuestion` 都接管输入框,同一种面板;选项之外永远可以自己写一句。

## 决定

心智模型:**她停下来问人,只有一处可答:接管输入框的那块面板。问题有两个来处,答案各回各处。**

1. **两个来处。**

   | 来处 | 谁发起 | 答案回到哪 |
   |---|---|---|
   | 权限征询 | 服务端权限层判出"要问"(0027),`ConsentDesk` 推给在场的主人 | 服务端,先答的算数(照旧) |
   | 她的提问 | 她调用新工具 `ask` | 她这一次工具调用的结果,只在主人客户端,不经服务端 |

2. **`ask` 是她的第五个工具,照 `AskUserQuestion`。** 一次 1–4 个问题;每个问题一句问话、一个短标题、2–4 个选项(名字加一句说明),
   可以多选;"其他回答"永远在,不用她写。答案原样回给她:选了哪几个、自己写了什么。它只问创建者(脑子在他电脑上,0008);
   群里也只有创建者看得到、答得了。
3. **一块面板。** 两个来处在客户端变成同一种"问题",画在同一块接管输入框的面板上:标签、问话、一行说明、编号选项、"其他回答"的输入行。
   挂着时她的过程那一行写"等待确认"或"等待回答",头顶气泡同样;答完对话流里留一行"你选了「…」"。面板外的去处(外接大脑客户端的
   elicitation、渠道)也收这同一种问题,哪里先答算哪里。
4. **问题挂着时你说的话,就是你对它的回答。** 不另设"先放着、聊别的":
   - 她的提问:你打的那句作为"其他回答"回给她;
   - 权限征询:你打的那句是拒绝的附言(就是现在的"说一句再拒绝"),允许只能点选项;
   - Esc 只把面板收成一行好看上面的对话,问题照旧挂着。
5. **问题怎么结束。** 照各自的来处:征询照 `ConsentDesk` 的超时、顶替、撤回(0027 不变);她的提问没有超时,主人按停止、她被急事打断、
   她离开世界,都撤回问题并把"为什么撤回"作为结果回给她。撤回的问题面板当场收起。
6. **删掉的**:对话流里那条带内联按钮的征询消息与输入框上方的"说一句再拒绝"提示栏,由这块面板取代;客户端只有一处挂着的问题,
   `ConsentCards` 与 `ConsentVenues` 合成这一处。

## 后果

- 她可以先问再做:"用哪台炉子""先挖哪边",主人的回答直接回到她手上的那次调用里,不靠下一轮猜。
- 主人面对的永远是一块面板、一套按法(数字键选、回车写),不分是权限还是她在问。
- 外接大脑仍用它自己的提问(它问坐在电脑前的人);`ask` 是内置大脑的工具。
- 问题挂着时输入框被占住,想跟她说别的话就是在回答这个问题;这是有意的,和主流一致。
