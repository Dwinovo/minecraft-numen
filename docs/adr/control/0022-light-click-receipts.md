# 0022 点一下的回执只说游戏接没接,之后变了什么她自己看

- 状态:已接受,已落地(实现说明见文末)
- 日期:2026-11-23
- 另见:[0020](0020-questions-answered-by-whoever-knows.md)(本条取代它的决定 4:一次动作前后变了什么)、
  [0021](0021-look-and-do-no-windows-for-the-model.md)(看与做)

## 背景

0020 把"点一下之后变了什么"做成了一个问题:动作之前开账、动作之后结账,登记的回答者各说一样,原版登记了十一个(背包、物品里的数据、
血量、饥饿、状态效果、骑乘、瞄的那一格、实体的装备、身边新实体、界面开合、界面里的格子),还开了口子让插件往回执里加话。
当天讨论下来,这个方向反了。用户的原话:

> 我们应该把回执做轻,而不是把回执做重,这个问题很大,因为当你这么做的时候,你大概率已经知道接下来应该发生什么才对,
> 这种东西回执是捕捉不了的呀,现在的回执返回的信息大部分其实是冗余的。

> 应该是模型自己通过skill去了解这种机制……哪怕对真人来说也不知道要这样子做吧,一旦你这样子做了,意味着你已经了解这个机制了。

当时代码里的毛病:

1. **回执里多数是她已经料到的**:用打火石必掉耐久,吃东西必变饥饿。
2. **料不到的恰恰接不全**。回执靠的是"按之前猜哪里会变、按之后回来看":只盯瞄的那一格,打火石的火生在隔壁就报不到;方块只写名字,
   营火点着了写成 `campfire -> campfire`;实体消失不报。盯得再多也是一张表,表外的照样漏。
3. **游戏自己的答复被扔了**。被点的方块、实体、手里的物品都向游戏交回"接了 / 做不成 / 不归我管",这是每个模组都要交的同一个约定;
   鼠标只拿它决定要不要试另一只手,回执里没有,转头去比对世界。
4. **什么都没看到时回执会说"什么都没变,换个位置再试"**。这句话只有盯全了才成立。

## 主流怎么做

- **CC:Tweaked**(程序控制一个身体的主流模组):`turtle.place()` 交回的只有 `true`,或 `false` 加一句原因;成没成取的就是游戏对那次
  右键的答复。不比对世界,不报背包变化,也没有让模组往右键结果里加话的口子。程序要知道发生了什么,自己 `turtle.inspect()`、
  `turtle.getItemDetail()`;模组要让程序多知道些什么,是往这两个"看"里加内容。
- **Create 的机械手**:假玩家替人右键,同样只看游戏的答复。

## 决定

1. **点一下的回执只说两件事:做了什么(按了哪个键、点了什么),游戏接没接。** 右键取游戏交回的话:有一样接了、做不成、没人理;
   左键一格是它碎没碎,左键实体是那一下落没落。交回的值里是一个 `accepted`。
2. **之后身上与世界变了什么,不进回执,她自己看**(`numen.scan`、`numen.inv`,以及每轮的状态)。接了不等于留下了看得见的变化
   (船可以吃掉点击却因站位碰撞放不下去),这也由她看了才知道。
3. **不比对世界,不开"往回执里加话"的口子。** 0020 的 `Witness`、`Ledger`、`Questions.WITNESS` 与原版那十一个回答者删掉。
   模组要让她多知道些什么,登记在"看"里(`Questions.DESCRIBE`,0021)。
4. **界面里做一件事同理**:说一句做了什么,交回做完之后的界面,变成了什么样就在那个界面里。
5. **"身体做的一切要报告"的边界**:Numen 让身体做的事(走了哪、挖了放了什么、用坏了什么装备、被拦下了什么)照旧如实报告;她点一下
   之后游戏怎么回应,是她自己看的事。她没要求而自己发生的(进度奖励进了背包)照旧用事件。

## 后果

- 回执短了:`right-clicked 10,64,5 — accepted`。
- 要确认结果得多一次调用。她是大模型,每多看一次是一个来回;换来的是回执不再有冗余、也不再有"盯漏了却说没变"的误导。
- 一种做法该发生什么,是知识,写进技能。
- 实体身上穿的拿的现在没有地方看(原来由回执里"实体的装备"那一条说):等实体接上"这是什么"(0021 没有定的一项)。

## 实现说明

- 鼠标:`Mouse.Use.Pressed` 多了 `answer`(`Mouse.Use.Answer`:`TAKEN`、`FAILED`、`IGNORED`),由两只手、几条路各自的
  `InteractionResult` 归成一个。它原有的 `changes`(点中那格周围变了的格)是寻路开门、垫路在用的结果,不动。
- `Interaction` 记下这次交互的 `answer`,`accepted()` 一处说接没接;回执的那半句只在 `Clicks.said` 一处写。
  `Clicks.Clicked` 的 `changes` 换成 `accepted`。
- 两个点击任务(`InteractAtCompanionTask`、`InteractEntityCompanionTask`)与 `MenuKinds` 不再开账;失败、超时、被叫停的那句话
  后面也不再接"已经变了的事"。
- 删掉的:`numen-api` 的 `witness` 包(`Witness`、`Ledger`)与 `Questions.WITNESS`,`numen` 的 `witness.VanillaWitnesses`,以及它们的
  测试。`Question`、`numen.answer`、`Focus` 留着,`Questions.DESCRIBE` 在用。`BodyDelta`(一件活里用坏的装备)、`Belongings`
  (进度奖励、FTB Quests 的背包变化)不动。
- 测试:GameTest `a_right_click_says_whether_the_game_accepted_it`(打火石点营火写 accepted、空手点石头写 not accepted);挤奶、
  骑猪、点开箱子三条改成断言"接了";插件往回执加话、物品数据变化两条随功能删掉。
