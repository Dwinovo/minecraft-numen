## 背景

工具数量随联动线性膨胀(control 0002),渐进披露失败(control 0003)。模型熟悉命令行;Claude Code 那样一个 bash 就能做完大部分事。
用户的原话:"理论上 claude 只需要一个 bash 就能做完所有功能,其他功能都可以看作是 bash 的封装"。

## 决定

- 一个命令工具,参数是一行命令;一级命令是领域(`move`、`work`、`scan`……)或模组 id(`ysm`、`ftbquests`……);`--help` 按命名空间展开,写错时报错带用法与最接近的候选。
- 常用命令提升为快捷工具,与命令同源(参数结构从命令节点生成,调用走同一个处理函数)。
- 09-26 分层:第 1 层是 Numen 命令层,只给她;第 0 层是 MC 指令树,给玩家;行首 `/` 直通原版指令,以她自己的权限执行、过权限层。

## 后果

- 工具表从 49 个降到 12 个;真机上她会主动查 `--help`,YSM 的命令一次写对。
- **命令行是无状态的**:分步建造要一个"对象"(先铺一层、看看、再加),只能把设计存成磁盘上的文件(`schematics/designs/<名>.numen`),一行命令往里追加一行;
  磁盘上要存各种名词,治标不治本。0.1.4 改了一半自己推翻。
- **命令行不是图灵完备的**:模型还是掌控不了工作流的细节,仍要我们替她注册组合好的胖命令(`work dig`、`build at` 在执行里替她做决定)。促成 0005。
